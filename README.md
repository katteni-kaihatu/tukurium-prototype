# Tukurium プロトタイプ

ブラウザの 3D 空間で交流しながら、複数人でアイテムやワールドを制作する環境のプロトタイプ。

- 文書の案内：[docs/README.md](docs/README.md)
- 現在のロードマップ：[docs/ROADMAP.md](docs/ROADMAP.md)
- 決定記録：[docs/adr/](docs/adr/)
- 開発メモ（詰まりやすい点）：[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)。開発の約束は [CLAUDE.md](CLAUDE.md)

## 必要なもの

- Node.js 22 以上
- pnpm 10（`corepack enable` で有効になる）

## 開発

```bash
pnpm install
```

```bash
pnpm dev
```

クライアント（http://localhost:5173 ）とサーバー（http://localhost:8787 ）が起動する。クライアントの `/api` と `/ws` はサーバーへ中継される。複数のブラウザ（またはシークレットウィンドウ）で開くと、互いの位置が見える。

| コマンド | 内容 |
| --- | --- |
| `pnpm test` | 単体テスト（Vitest） |
| `pnpm typecheck` | 型チェック |
| `pnpm lint` / `pnpm format` | Biome による検査・整形 |
| `pnpm build` | クライアントとサーバーのビルド |
| `pnpm e2e` | ブラウザでの通しテスト（Playwright。背骨の 4 本：一人で作って撃つ・2 人で編集・セッションに出して適用・3 人で一周） |
| `pnpm smoke <URL>` | 設置した環境の動作確認（セッション作成・ワークスペース作成・再生） |

### 周辺サービス（PostgreSQL・S3 互換ストレージ）

サーバーの保存先（PostgreSQL）や、M3 以降の素材の置き場（S3 互換）を手元で使うときは、開発用の compose で起動する（Docker が必要）。

```bash
pnpm services:up
```

PostgreSQL（`localhost:5432`）と S3 互換ストレージの SeaweedFS（`localhost:8333`）が起動する。接続先は `.env.development.example` を参照し、`apps/server/.env` にコピーするとサーバーが使う（`DATABASE_URL` がなければメモリに保存し、再起動で消える）。止めるときは `pnpm services:down`。

## 上のバーとウィンドウ

セッションは人が集まって過ごす場所、ワークスペースはプロジェクトの編集画面。参加しただけでは編集画面を開かず、チルしたり、所持アイテムを取り出して遊んだりできる。「ワークスペース」で編集対象を選ぶとワークスペースが開き、閉じても同じセッションに残る。

左上の「ツクリウム」でホームを開く。上のバーは今いるセッションの名前・参加者と、ワークスペース・セッション・バッグ・退出の操作を表示する。ワークスペースは現在の名前と数が見える旧表示を使う。

フレンド・セッション・アイテム・マーケット・プロジェクト・ライブラリは、上のバーから少し離した、左の補助メニューから開く。3Dの操作中はアイコンだけを出し、通常のマウス操作に戻ると名前を表示する。セッションに参加する前から使え、ライブラリも未参加で閲覧できる。各機能は独立したウィンドウとして並べ、移動・サイズ変更・2D/3D配置ができる。閉じても検索や入力内容、参加先、編集中のプロジェクトは保つ。

| 画面 | できること |
| --- | --- |
| ホーム | フレンドがいる場所、所持アイテム、マーケットの新着を見る。セッションや制作を始める |
| フレンド | 名前・IDで探して申請し、承認する。4種類の状態とひとことをプレビューして設定し、相手の状態・参加先を見る。現在のセッションへ招待する |
| セッション | 名前や参加者から探し、参加・移動・作成・退出する。参加中も一覧が更新される |
| アイテム | 名前・作者・公開タグで所持品を探す。お気に入り・並べ替え・カード／リスト表示を使い、現在のセッションへ取り出す |
| マーケット | 公開アイテムを名前・作者・公開タグから検索して入手する |

「入手」は所持一覧への登録、「取り出す」はセッションへの配置。入手時の版を固定し、自動では更新しない。ゲーム内で物を拾うバッグと、制作へ組み込むライブラリは別にある。所持・フレンド・招待はPostgreSQLに保存し、メニューの検索や選択は本人の画面だけで保持する。

公開タグは作者が公開時に付け、あとから編集できる。タグは作品の情報として保存し、所持している版の内容は変えない。お気に入りと表示方法はアカウント別にブラウザへ保存する。

招待を受け取ると参加先を確認でき、本人が参加ボタンを押すまで移動しない。招待の期限は10分。課金、DM、参加確認メッセージ、作者が設定するサムネイルとカテゴリは初期版に含めない。現在の画面は[UI/UX資料](docs/plans/social-workshop-experience.md)、実装判断は[ADR一覧](docs/adr/README.md)を参照。

## いまできること

- ホームでセッションを作る・開いているセッションに参加する（URL を共有すれば同じセッションに入れる）。持ち主は画面上部の「セッションを閉じる」で終わらせる（中にいる人の画面も終わり、セッションはなくなる。プロジェクトは残る）。ほかの人は「セッションを出る」で自分だけ抜ける
- 3D 空間を FPS 視点で歩く。他の参加者の位置と、その人が開いているパネル（権限に応じた要約）が見える
- セッションの中でワークスペースを作り、複数人で同時に編集する（コードのカーソル共有を含む）。作業内容はサーバーに自動保存
- 権限：閲覧・共同編集・管理。参加者の初期値は管理者が設定（既定は共同編集、非公開も可）
- ワークスペースの再生はホスト（管理者）が実行して全員に共有。ホストが抜けたら別の管理者が引き継ぐ
- アウトプットを「セッションに出す」と、セッションの世界に置かれ、みんなで遊べる。編集を続けて「適用」すると、リンク先がすべて更新される。「維持」マークを付けたフィールド（残弾など）は実行値を保つ。リセットも可
- 別々のワークスペース（リポジトリ）で作った銃と射撃場を、セッションで組み合わせられる
- 独自の KokoState、JavaScript の System（`onUpdate` / `onInput` / `onEvent` / `onCollision`、`audio.play`）、プロシージャル形状・マテリアル、GLB・画像・音声の素材
- プロジェクト（リポジトリ）：作成（テンプレートから）、メッセージ付きの保存と履歴（左が記録のグラフ、右が選んだ記録の詳細。いちばん上は未保存。一緒に編集した人の名前も残る）、名前で開く差分（エンティティは階層と KokoState、コードは行、モデルとテクスチャは変更前と変更後）。1 プロジェクトにつきワークスペースは同時に 1 つ
- 作品として公開・リリース（v1, v2, …）と権限（利用・元データ閲覧・フォーク／抽出）。公開されたワールドとアイテムは、セッション同期の「公開された作品」か、画面上部の「ライブラリ」からセッションに置ける。ワールドは原点、アイテムは視線の先。置いたものは、作っているワークスペースとは別（適用の対象外）
- 画面上部の「セッション」で、公開されているワールドから、このセッションで開くものを選ぶ。開くと、いまのワールドは入れ替わる（原点に置かれる）。アイテムは残る。利用の権限がある人が選べる。ワークスペースを開いていなくても使える
- 公式ライブラリ：サーバーに同梱した公式の「combat」（Health と、Damage を受けて hp を減らす Damageable）が、起動のときに公式の発行者の作品として用意される（ライブラリの欄に「公式」の印。公式かどうかは名前ではなく発行者で決まる）。サンプル「銃と的（公式ライブラリ）」は、的の hp と Damage の受け取りをこれに任せた reference UGC。公式の「interaction」（Toggle と、Interact を受けて切り替える Toggleable）を使うサンプル「扉とスイッチ」もある
- バッグ（持ち物）：E で拾った物は、プレイヤーごとのバッグに入る（画面上部の「バッグ」で自分の中身を見る）。どの作品で拾っても同じバッグで、セッションが続く間だけ残る（ホストが替わっても引き継ぐ）。作品の System は、プレイヤーが E で押した Interact を受けている間だけ、その人のバッグに `bag.add / take / count / list` で触れられる（種類は import したライブラリの KokoState だけ）。公式の「items」（Key と KeyPickup）を使うサンプル「鍵と扉」がある。入力のプレイヤー ID は、サーバーが接続の本人で上書きする
- Host API（`world.*`・`bag.*` など）と Built-in の Contract（Damage・Interact）は、今はすべて experimental（互換性なく変わることがある）。エディタの型の説明と入力補完に出る
- E で見ている物を押す：Host が視線の先（3 m まで）を調べ、その物が `contracts.Interact` を受け付けていれば Built-in の Interact（`{ player }`）を送る。スクリプトからは送れない。セッションでは相手の「外からの見え方」がインタラクション可能なときだけ届く
- フォーク、抽出（アウトプットやリソースを選んで、新しい／既存のプロジェクトへ。由来が残る。入っていたフォルダと、使っているライブラリ（依存）も一緒に持ってきて、import を取り込み先に合わせて書き直す）
- 非公開の作業：独立した空間で編集・再生する。権限のない人には境界と「作業中」だけが見え、中身は届かない。セッションには出せない
- 開いていないワークスペースの編集中の物も、閲覧できる人には見える（ホストが送り、サーバーが権限で見せ分ける）
- ワールドの編集：「＋ ワールドを追加」で独立した空間に移り、セッションの区画のポータルから出入りする。セッションに出すと原点に置かれる
- 素材の取得にも権限（上げた人、使っている制作データを閲覧できる人だけ）
- スクリプトのエラー：構文の誤りなどは Play しなくても出る。実行して止まった System は Stop しても次の Play まで残る。行番号つきで、クリックするとコードのその行へ移る
- ワークスペースのメインパネルは、選んでいるアウトプットと再生の操作。「ワークスペースを閉じる」で、この画面での編集を終える（プロジェクトは残り、セッションの一覧から開き直せる）。セッションに出す・適用とリンク先一覧は、再生のボタンの横の「セッション同期」から開く。Inspector・Resources・エラー・ログ・保存は、下のボタンから開いたり閉じたりする。ワークスペースを開いたときは Inspector と Resources が出ている。Inspector の Hierarchy では、ドラッグで並べ替えと親子付けができ、行に合わせると複製と削除が出る。最後の保存から新しいもの・変わったものは、左の緑と黄色の丸で分かる。変化がないところにも透けた丸があり、文字の開始が揃う。新しいエラーが出ると、エラーパネルが自動で開いて前に出る（閉じても、同じエラーが残っている間は開き直さない）
- パネルを 3D にすると、画面で見えていた位置にそのまま置かれる。空間に入っている間も、照準の先のパネルをクリック・ホイールで操作できる。右クリックを押している間、持った位置と向きのままパネルを動かせる。その間のホイールで前後に動かす。右下をドラッグすると大きさを変えられる（小さくできる限界あり）。画面左下の「空間のパネル」から画面に戻せる。インスペクタは、選んだものに合わせて大きくならない
- 右クリックを押している間、Built-in の Grabbable を付けた物を持つ（Collider も必要。持った場所と角度のまま持ち、離せばその場所に残る。持っている間のホイールで前後に動かし、左クリックで傾きを直し、E を押している間はマウスで回す。持っている物はほかの人にも見える）
- Resources はフォルダで整理できる（フォルダの木・場所の表示・さがす・アイコン／一覧／詳細の表示・ドラッグで移す）。KokoState・マテリアル・スクリプト・テクスチャ・モデルの詳細は、Inspector とは別のパネルで開く。マテリアルは球、テクスチャは画像、モデルは立体で見た目を出す。スクリプトのコードと、その詳細は、Resources が 3D なら 3D のパネルで、2D なら 2D のパネルで開く
- System は KokoState を import で読み込める：`import Gun from "../States/Gun.koko";`（System のフォルダからの相対パス）、`/Combat/States/Gun.koko`（いちばん上から）、`@builtin/Transform.koko`。`query: { with: [Gun] }` と書き、`e.get(Gun)` で値を読み書きする。見つからない・曖昧な import は、その行の問題として出る。KokoState やフォルダの名前を変えたり移したりすると、import のパスも新しい場所に合わせて書き直される。これまでの名前での書き方（`with: ["Gun"]`・`e.Gun`）も、名前が一つに決まる間は動く。別のフォルダなら同じ名前の KokoState を作れ、import の別名で区別して使える（Built-in と同じ名前は使えない）
- ライブラリ：アウトプットの種類を「ライブラリ」にし、Resources で「公開」の印を付けて作品として出すと、リリースごとにサーバーが content hash を残す。使う側は「ライブラリ」の欄の「プロジェクトで使う」で別名を付けて足し（その版と hash に固定）、`import Health from "@別名/States/Health.koko";` で公開された KokoState を読み込める。依存の KokoState は Inspector の「Add KokoState」で Entity に付けられ（`@別名` の印が付く）、import した System が再生でもセッションでも動く。同じライブラリの同じ版の KokoState は、セッションに置いた別の物どうしで同じ型になる。公開した System は、アウトプットの「System を追加」に `@別名/名前` で出て、そのまま動かせる（ライブラリの System が import できるのは、同じライブラリで公開した KokoState と Built-in だけ。セッションでは使う側の KokoState は見えない）。ライブラリも依存を持てて、その System は自分の依存を `@別名` で import できる（依存の依存は、間のライブラリの作者の許可で届く。自分自身に依存するライブラリは出せない）。依存にない別名・見つからない（公開されていないものも同じ扱い）・中身を取り出せないものは、その行の問題として出る
- 同じフォルダの中では、種類が違っても名前を一つにする（大文字・小文字の違いは同じとみなす）。別のフォルダなら同じ名前を使える。名前の衝突・フォルダの輪・素材やマテリアルの参照切れ・Entity の親子のくい違いなどは、Play しなくても「エラー」パネルに出る（KokoState・マテリアル・スクリプトは詳細パネル、Entity は Inspector）。Resources では、自分の問題は塗りつぶしの点、フォルダの中や関係するものの問題は輪郭の点で示す。スクリプトの問題は、編集した後で確かめ直すまでの間、「編集前の確認／実行」として薄く出す。確かめ直すのは、変更の影響を受ける System だけ（依存グラフでたどる）
- セッションでは、スクリプトの `world.find` / `get` / `set` / `destroy` / `emit` は、その System の配置（置いた Item / World）の中の Entity にだけ届く（ADR 0012）。別の作者の Item / World とは、公開 Contract でだけやり取りする：受ける側は System に `contracts: { Damage(e, damage) { ... } }` と書き、送る側は `const hit = world.raycast(...); if (hit) hit.send("Damage", { amount: 1 })` と書く（`hit` は 1 秒の間だけ使え、Contract と effect をそれぞれ一度ずつ送れる。別の配置に当たったときは `hit.entity` が null）。`hit.effect("spark", { color: "#ffd166" })` で、当たった点に一時的な火花を出せる（保存しない。ほかの人にも見える）。Output の「外からの見え方」で、インタラクション可能（初期値）／衝突のみ／非公開を選べる。World の Output では、セッションの土台（最初に置いた World）になったときに「外から来た Item」（別の作者の Item）に許すことを、インタラクション可能（初期値）／衝突のみ／許さない から選べる。コードエディタでは `world.` `audio.` `hit.` などのあとに、使える関数と説明・要る権限が候補に出る。System が使う権限（Capability）はコードから読み取られ、Output の詳細の「使う権限」に出る。セッションでは、読み取った権限にない使い方（`world[name]()` など）は拒まれ、注意が残る。公開されている相手に Contract を拒まれたときは、送った System に「注意」が残り、セッションのパネルに回数と一緒に出る
- プロジェクト名の変更（プロジェクトページの Settings。持ち主だけ）。ワークスペースでは、プロジェクト名がプロジェクトのページへのリンクになる
- Web ページ：ホーム・プロジェクト・新規作成・プロフィール・探す
- 文字：Built-in の Label で、空でない文字列をその場に出す（色と高さ。向いている面は +Z）
- 同梱サンプル「銃と的」「銃」「射撃場」「森」「マルバツ」。森は静かなワールド（同梱の木のモデル）。マルバツはクリックで ○× がつき、最初に押した人が先行、次の人が後攻になる（表示名は入力の `playerName`。本人の確定は ID）。リセットはクリックでも、近く（3 m）で E でも最初からに戻る

## 構成

```
apps/client      Vite + React + Three.js（3D 空間、パネル、Web ページ）
apps/server      Node.js（Fastify + WebSocket）
packages/shared      型と通信プロトコル（zod）
packages/eks         EKS コア（Entity / KokoState / Query / System の実行順）
packages/script      利用者スクリプトのサンドボックス（QuickJS）
packages/repo-model  制作データ（Y.Doc 上の KokoState 定義・System・Entity・アウトプット）と同梱サンプル
packages/runtime     実行（EKS + 物理 Rapier + スクリプト）。入力・衝突・イベント・レイキャスト
e2e/                 Playwright の通しテスト
docker/          Dockerfile
```

## デプロイ（Coolify / docker compose）

手順・環境変数・バックアップ・確認方法は [docs/DEPLOY.md](docs/DEPLOY.md) を参照。

```bash
docker compose up -d --build
```

`app`（クライアント＋サーバー）と `postgres` が起動する。S3 互換ストレージは外部のものを環境変数で指定する（設定値は `.env.example` を参照）。

Docker Hub の取得制限に当たる場合は、ベースイメージを差し替えられる：

```bash
docker compose build --build-arg NODE_IMAGE=<ミラーの node:22-bookworm-slim>
```
