# 作業を出荷する

## 1. 自己レビュー（差分を読む）

`git diff origin/main...` を読み、次を確かめる。

- 権限：新しい通信や API は、閲覧・共同編集・管理の権限を確かめているか。非公開の中身が、権限のない人に届かないか
- 通信：`protocol.ts` を変えたら、`PROTOCOL_VERSION` を上げる必要がないか。古い相手からのメッセージで落ちないか
- 状態：ワークスペースを開き直す・閉じる・接続し直すときに、古い状態が残らないか（ストアの open / leave で初期化しているか）
- 片付け：イベントの購読・タイマー・Three.js のリソース・QuickJS のハンドルを解除・破棄しているか
- 文言：UI とコメントが日本語で、平易な言い方になっているか
- 古いコメント・使われなくなったコードが残っていないか

## 2. 確かめる

`verify-change` スキルの 1 を流す。画面を変えたら 3 で確かめる。背骨の流れに触れたら 2 も流す。CI で合否を決めるのは `check`（lint・型・単体テスト・ビルド）で、`e2e` は落ちてもマージを止めない（落ちたら原因だけは報告する）。

## 3. ドキュメント

- 設計の判断をしたら `docs/adr/` に ADR を足す
- `docs/PLAN.md` の進み具合、`README.md` の「いまできること」を更新する
- 詰まった点があれば `docs/DEVELOPMENT.md` に書き足す

## 4. コミットと PR

- 作業ブランチで作業する（`main` に直接コミットしない）
- コミットメッセージは日本語で、何を・なぜを書く。末尾に、会話で指定された署名の行を付ける
- モデルの名前や ID は、コミットにも PR にも書かない
- PR の本文：概要 / 変更点 / 確認（流したものと件数）/ 残課題。末尾に、指定された署名の行を付ける

## 5. マージしたら

```bash
git fetch origin && git checkout -B <作業ブランチ> origin/main && git push -u origin <作業ブランチ>
```

マージ済みの PR に、続きの作業を積まない。続きは新しい PR にする。
