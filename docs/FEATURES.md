# できること

いまの Tukurium で使える機能を、利用者の行動ごとにまとめる。操作の細かい手順や API の書き方は、画面・エディタの補完・ADR を見る。

## 集まる・作業を見る

- セッションを作る・参加する・退出する。持ち主はセッションを閉じられる。
- 3D 空間を歩き、他の参加者の位置や作業の様子を見る。作業内容は閲覧権限の範囲で見える。
- 編集パネルを画面内の 2D 表示と空間内の 3D 表示で切り替える。
- 公開されたワールドをセッションで開く。ワークスペースを開いていなくても利用できる。
- 上のバーとは別の島にした左の補助メニューから、フレンド・セッション・アイテム・マーケット・プロジェクト・ライブラリを独立したウィンドウとして開く。複数を同時に使い、開閉しても制作や参加先を維持する。
- セッションと参加者を検索し、参加中にも入退室を確認する。移動先が見つからないときは元のセッションを保つ。
- フレンド申請・承認・取消・辞退・解除、状態とひとこと、参加先の表示、10分間のセッション招待。
- フレンドに見せる4種類の状態とひとことを、プレビューしながら設定する。

## アイテムやワールドを作る

- アイテムとワールドを作る。基本形状・マテリアル・GLB・画像・音声・3D の文字表示を使う。
- 独自のデータを KokoState、処理を JavaScript の System として定義する。状態の受け渡し・Query・world.get/set/spawn は安定 ID で扱う。入力・衝突・イベント・音声再生を扱う。
- リソースをフォルダで整理し、相対パス・絶対パス・Built-in の import で参照する。別のフォルダの同名 KokoState も使える。
- 名前の変更や移動に合わせて import を書き換える。同じフォルダ内の名前の衝突を防ぐ。
- 構造・参照・スクリプト・実行の問題を独立した「エラー」パネルに表示する。コードの行、定義、Entity などへ移動できる範囲もある。
- Resources にリソース自身やフォルダ内の問題を表示する。編集前の診断結果は区別し、非同期の古い結果を捨てる。
- 依存関係から影響を受ける System を選び、スクリプトを確認し直す。import は安定 ID、従来の名前で書いた Query は名前を介してたどる。
- Host API の引数検証・権限の分類・拒否時の値・型の宣言・入力補完を `HOST_API_SPEC` から生成する。
- Hierarchy で Entity をドラッグして並べ替えと親子付けをし、開いたり閉じたりする。行に合わせると複製と削除が出る。複製は中を含めるか選べ、削除は確認する。最後の保存と比べて、新しいものに緑、変わったものに黄色、変化がないところには透けた丸を左に出す。丸にマウスを載せると、どう変わったかが出て、左の印から確認して戻せる。詳細では KokoState を消す前に確認する。

## 一緒に編集する

- 同じワークスペースを複数人で編集する。コードのカーソルを共有し、作業内容を自動保存する。
- 閲覧・共同編集・管理の権限と、参加者の初期権限を設定する。
- 非公開の作業を独立した空間で編集・再生する。権限のない人には内容を配信せず、作業中であることだけを見せる。
- アイテムやワールドの編集空間を、セッション内の実行状態と分けて扱う。

## 試す・更新する

- ワークスペースで再生し、結果を共有する。ホストが退出した場合は別の管理者が引き継ぐ。
- 編集した作品をセッションに出す。遊んでいる人がいる状態で、リンク先すべてに変更を適用する。
- 「維持」を指定したフィールドの実行値を引き継ぐ。実行状態をリセットする。
- リポジトリとバージョンごとに実行領域を分け、適用時は対象の配置だけを新しいバージョンへまとめて移す。
- 実行して停止した System の問題を停止後も残し、次の再生で更新する。

## 作品を組み合わせる

- 別々のプロジェクトで作った銃と射撃場などを、同じセッションで組み合わせる。
- 他の配置の内部データを直接操作せず、公開された Contract を通じてやり取りする。Raycast の結果から `hit.send("Damage")` や `hit.effect("spark")` を使う。
- 作品の「外からの見え方」と、World が外から来た Item に許す範囲をプリセットで設定する。
- System が要求する権限をコードから読み取り、セッションでは配置への付与と照合して全 Host API に適用する。付与はサーバーの配置情報に保存し、`setGrants` で変更できる。ワークスペースの再生ではこの制限を強制しない。
- ライブラリをプロジェクトに追加し、公開された KokoState と System を使う。Package の安定 ID・バージョン・公開項目・依存・要求権限を持ち、content hash と依存先のバージョンを固定する。
- ライブラリの依存先も読み込み、依存の循環を検出する。同じライブラリの同じバージョンの型を配置間で共有し、System は使うプロジェクトの実行領域で動かす。
- 公式の発行者と「combat」「interaction」「items」を用意する。「銃と的」「扉とスイッチ」「鍵と扉」で一連の操作を試せる。
- E キーでの操作と、プレイヤーごとのバッグを使う。バッグはセッション中だけ保持し、ホスト交代後も引き継ぐ。
- 拒否された操作を System の注意として知らせる。入力のプレイヤー ID はサーバーが接続の本人で上書きする。

現在は参加者のブラウザが実行役になる協調セッションで、ホストを信頼している。通常のクライアント上の UGC に対する権限制限はあるが、改変したホストからの保護は未実装。

## 残す・渡す・作り直す

- 制作データをメッセージ付きで保存し、履歴と差分を見る。
- 作品をバージョンごとに公開する。利用・元データの閲覧・フォーク／抽出の権限を分ける。
- 公開された作品を見つけてセッションに置く。ライブラリをプロジェクトに追加して使う。
- マーケットで名前・作者・公開タグからアイテムを検索し、入手時の版を所持一覧に保存する。作者は公開タグを編集できる。所持品をタグやお気に入りで絞り込み、現在のセッションに取り出す。検索結果のページ送り、並べ替え、カード／リスト表示に対応する。
- プロジェクトをフォークする。選んだアウトプットやリソースを、新しいプロジェクトや既存のプロジェクトへ抽出する。
- 抽出時に必要なフォルダとライブラリの依存を引き継ぎ、import を取り込み先に合わせて書き換える。元のリポジトリ・コミット・リソース・依存の出所を保持する。
- 抽出する System が使う KokoState を依存グラフから集める。
