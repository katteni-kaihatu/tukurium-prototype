# できること

いまの Tukurium で使える機能を、利用者の行動ごとにまとめる。利用者から見た機能を一行ずつ書き、キーの操作・API の書き方・細かい手順は書かない。それらは画面・エディタの補完・ADR を見る。

## 集まる・過ごす

- れぞらぶの Misskey（misskey.resonite.love）のアカウントでログインする。どの端末でも同じ人として入れる。表示名は最初は Misskey の名前で、アカウントのウィンドウで変えられる。Misskey のアイコンが顔に出る。ログアウトもアカウントのウィンドウからする。

- セッションを作る・参加する・出る。URL を共有すれば同じセッションに入れる。持ち主はセッションを閉じられ、閉じてもプロジェクトは残る。
- 3D 空間を歩き、ほかの参加者の姿と、その人が開いているパネルを見る。パネルの中身は、閲覧の権限に応じて見える。
- 参加しただけでは編集を始めない。ワークスペースを開かずに過ごしたり、所持アイテムを取り出して遊んだりできる。ワークスペースを出ても、セッションには残る。
- ホームで、フレンドの今（フレンドがいるセッション。フレンドが多い順）・オンラインのフレンド・所持アイテム・マーケットの新着を見て、セッションに参加したり、制作を始めたりする。
- 左のグローバルメニューから、ホーム・フレンド・セッション・ワールド・アイテム・マーケット・プロジェクト・ワークスペース・ライブラリを、独立したウィンドウとして同時に開く。メニューは名前つきの形とアイコンの列を切り替えられ、自分のステータスの変更とセッションの退出もここからできる。
- セッション内では、左上の札でセッションの名前・ワールド・人数・接続の状態を見る。その下の左の欄で、参加者・ワークスペースの切り替え・セッションに出ているアイテム・バッグを開く。出ているアイテムは名前と出した人が並び、セッションの持ち主と出した人はそこから外せる。左の欄はたためて、制作中はたたまれる。
- 右の欄で、フレンドがいるセッション（参加前）と、届いた招待・フレンド申請を見る。招待はそのまま受け取れる。チャットと通話はボタンだけで、まだ使えない。参加する前から使え、閉じても検索や入力の内容、参加先、編集中のプロジェクトを保つ。
- ウィンドウは、動かす・大きさを変える・画面と空間を切り替えることができる。
- セッションを名前や参加者から探し、参加・移動・作成・退出する。移動先が見つからないときは、元のセッションに残る。
- フレンドを名前や ID で探して申請・承認し、ステータスとひとこと、参加先を共有する。ステータスは、見え方をプレビューしながら設定する。
- 今いるセッションへフレンドを招待する。招待を受けても、本人が参加を選ぶまで移動しない。
- グローバルメニューのワールドから、マーケットにあるワールド（公開中の版）を選ぶ。一覧はマーケットと同じカードで並ぶ。見出しの「マーケットで探す」で、ワールドだけのマーケットへ移れる。「自分のワールド」では、マーケットに出していない非公開のものも含めて、自分がリリースしたワールドの最新の版を開ける。セッションにいるときは、選んだワールドに変える。変える前に、全員へ 3 秒のカウントダウンが出る。セッションにいないときは、選んだワールドで新しいセッションを開く。ワールドが入れ替わっても、アイテムは残る。ルートワールドが開いているあいだは、何もないときの床（グリッド）を出さない。
- 作品の中で拾った物は、プレイヤーごとのバッグに入る。バッグはセッションが続く間だけ残る。

## アイテムやワールドを作る

- プロジェクトをテンプレートから作り、名前を変える。
- アイテムとワールドを作る。基本の形・マテリアル・モデル（GLB）・画像・音声・空間に置く文字を使う。
- ワールドは、遊ぶ場所から離した編集の空間で作る。ポータルから入り、出口からセッションへ戻れる。
- 独自の KokoState と、TypeScript で書く System で、作品のデータと処理を作る。
- KokoState のフィールドの型は、TypeScript の型の書き方で持つ。よく使う型（数・文字・真偽・`Vec3`・色・Entity やリソースの参照）は、一覧から選ぶ。ほかの型は、「TypeScript で書く」を選んで型の文を書く。
- Entity・マテリアル・素材を指すフィールドの「なし」は `undefined`。Inspector で「（なし）」を選ぶか、スクリプトで `undefined` を入れる（`null` は使わない）。
- フィールドの型エラー（読めない型・知らない名前・関数などの保存できない型）と、型に合わない値・初期値が、「エラー」パネルに出る。型エラーのあるフィールドだけが使えなくなり、ほかのフィールドは使える。
- エージェントは、レコード・リスト・マップなどの型のフィールドを作り、値を入れられる（System からも、その型のとおりに読み書きできる）。型の定義を作って KokoState から使い、参照は入れ子の中でも名前で渡せる。
- 名前を付けた型（`Card` など）を、「型の定義」のリソースに TypeScript で書く。KokoState の「使う型の定義」に入れると、フィールドの型から使える。名前を変えても動かしても切れない。ライブラリに入れて配れる。
- Entity についた KokoState の参照（`KokoStateRef<Health>`）と、そのフィールドの参照（`FieldRef<number>`）をフィールドに持てる。System から `world.getState()`・`world.getField()` などで、指す先を読み書きする。指す先の Entity・KokoState・フィールドが消えたら、問題として出る。
- レコード・リスト・マップの値を、Inspector で直す（足す・消す・並べ替える・キーの名前を変える）。KokoState の参照とフィールドの参照は、Entity とフィールドを選んで入れる（数のフィールドだけを指せる参照では、文字のフィールドは選べない）。`Map`・`Set` は、値の形式の文字で直す。
- 「維持」を付けたフィールドは、入れ子の値もまるごと引き継ぐ。型の定義が変わっていたら、新しい型に合わせて引き継ぐ。
- 型の定義を変えたとき、すでにある値は、足したフィールドを空の値で埋め、消したフィールドを捨てて使う。型が変わったフィールドは、問題として出る。
- リソースをフォルダで整理し、パスで参照する。別のフォルダなら、同じ名前の KokoState も使える。名前の変更や移動に合わせて、import が書き直される。
- Resources でリソースの詳細を開き、マテリアル・テクスチャ・モデルの見た目と、素材の形式や大きさを見る。どのリソースが、どの Entity・System・アウトプット・マテリアルで使われているかが分かる。
- KokoState を、検索とタグで絞りながら Entity に付ける。
- Hierarchy で並べ替え・親子付け・複製・削除をする。
- 「プレハブ」をリソースとして作り（Resources の New）、アウトプットや別のプレハブにインスタンスとして何個でも置く。アウトプットには詳細の「アウトプットに置く」か Hierarchy へのドラッグで、別のプレハブにはその Hierarchy へのドラッグで置く。インスタンスごとに、名前と、場所・向き・大きさを決める。インスタンスを複製すると、同じプレハブのインスタンスが増える。
- プレハブの System は、インスタンスを置いたアウトプットで動く。アウトプットの System のあとに動き、アウトプットの画面から切れる。セッションに出した配置と、公開したリリースでも同じように動く。
- プレハブの名前を変えても、フォルダへ動かしても、インスタンスとのつながりは切れない。プレハブを消すと、インスタンスは残り、問題として出る。プレハブの変更は、保存の差分に出て、まとめて戻せる。
- プレハブを開いて、アウトプットと同じように Hierarchy と Inspector で直す（Resources でダブルクリック、詳細の「開く」、インスタンスの「プレハブを開く」）。Entity を足す・名前を変える・KokoState を付ける/外す・値を変える・並べ替え・親の付け替え・複製・削除ができ、直すと、すべてのインスタンスに反映される。プレハブの System の並びと「入・切」、「維持」の印も直せる。「アウトプットに戻る」で閉じる。
- プレハブを開いている間、空間にはプレハブの中身が出る。編集する場所は、プレハブごとに「その場」（初め。インスタンスから開くと、そのインスタンスと重ならない横に出る）と「離れた空間」（ポータルで入る独立した空間）から選ぶ。Play を始めると、アウトプットに戻ってから再生する。
- プレハブの中の Entity が指すマテリアル・素材・Entity や、KokoState の定義・System がないときは、プレハブの問題として「エラー」パネルに出る。そこから、プレハブを開いて、その Entity と欄へ移れる。
- アウトプットやプレハブの Entity（中の Entity を含む）から、プレハブを作る（Inspector の Entity の操作の「プレハブにする」）。選んだ Entity は、ID・名前・親・場所をそのままに、そのプレハブのインスタンスになる。中身は、新しい ID でプレハブに移る。ほかの Entity からの参照と「維持」の印は、切れないように書き換える。
- 「プレハブにする」を押すと、先に確認が出る：プレハブに移る Entity（元の ID と新しい ID）、書き換える参照、プレハブに移す「維持」の印、プレハブの外を指す参照、スクリプトが ID で探している Entity（スクリプトは書き換えないので、注意として出す）。アウトプットの System から、プレハブにも入れるものを選べる。
- インスタンスの中の Entity は、フィールド・名前・親・並び順を変え、Entity・KokoState・System を足せる。プレハブから来たものは消せず、足したものは消せる。親がプレハブから消えたら、残っている祖先へ付け替わる。
- インスタンスで変えた所は `△`、最後の保存からの変化は丸で示し、それぞれ一つずつ戻せる。プレハブから来たものは `元`、インスタンスで足したものは `追加` で見分ける。中の Entity の複製は追加 Entity になり、いちばん上の複製は上書きを写したインスタンスになる。
- インスタンスの「プレハブに適用」で、変更・追加 Entity の ID・参照・「維持」の印を確認して書き戻せる。ほかのインスタンスにも反映され、適用元の上書きは消える。インスタンスの名前・親・並び・場所・向き・大きさは残る。ライブラリや、親をインスタンスの外に付け替えた変更には適用できない。
- 「ふつうの Entity に戻す」で、いまの中身と System を残して、選んだプレハブとのつながりを切れる。入れ子のインスタンスは残り、そのプレハブの変更を引き続き受け取る。
- プレハブの中に別のプレハブを入れ子にできる。入れ子でも変更・復帰・適用ができ、自分自身を含む循環は作れない。「プレハブにする」で移す範囲の外を親にした子がある場合は、理由を表示して変換を断る。
- Inspector の詳細の幅は、階層との境をドラッグして変える。欄の名前は同じ幅にそろえ、入りきらないときは文字を小さくして全部出す。
- 最後の保存から新しくなったもの・変わったものに印が付き、確認してその部分だけ戻せる。
- スクリプトのエディタで、Host API と import が補完される。最後の保存からの変化の印も出る。
- スクリプトの型エラー（KokoState のフィールドの名前や型の間違い、Query に書いていない KokoState の読み書きなど）が、エディタと「エラー」パネルに日本語で出る。型エラーがあっても再生はできる。
- 構造・参照・スクリプト・実行の問題が、再生しなくても「エラー」パネルに出る。コードの行・定義・Entity のフィールドなど、問題の場所へ移れる。Resources と Hierarchy でも、問題のあるリソース・フォルダ・Entity・アウトプットに印が付き、中にある問題も分かる。
- 「エラー」パネルの問題を、文字で探し、種類・時点・アウトプットで絞り込み、リソース・フォルダ・アウトプットなどでまとめて見る。問題ごとに詳しい中身（対象・場所・関係するもの）を開け、すべてのスクリプトをもう一度確かめ直せる。
- 編集したあとまだ確かめ直していない問題は、古い結果として区別される。確かめ直すのは、変更の影響を受ける System だけ。
- アウトプットにサムネイルを付ける。空間に置くカメラで撮れる。
- ほかのプロジェクトのアウトプットやリソースを、使っているものごと、開いているワークスペースへ取り込む。由来が残る。
- 同梱のサンプル（銃と的、銃、射撃場、森、マルバツ、扉とスイッチ、鍵と扉）から始められる。マルバツは、型の定義と、リスト・マップ・レコードのフィールドを使う見本になっている。

## 一緒に編集する

- 同じワークスペースを複数人で同時に編集する。同じ Entity の別のフィールドを同時に変えても、それぞれの変更が残る。KokoState の定義も、別のフィールドを同時に変えたり足したりすれば、両方が残る。コードのカーソルも見える。作業内容は自動で保存される。
- ワークスペースを出ると、自分だけ編集を終える。ワークスペースは残る。管理の人は、確認してワークスペースを閉じられる。閉じると一覧からなくなり、開いていた人も出る。プロジェクトは残る。
- 閲覧・共同編集・管理の権限を分け、参加者の初期の権限を決める。
- 一つのプロジェクトを同時に開けるワークスペースは一つ。
- 自分が開いていないワークスペースで作っている物も、閲覧できる人には見える。
- 非公開の作業は、独立した空間で編集・再生する。ポータルから入り、出口から戻れる。権限のない人には「作業中」とだけ見える。
- パネルを空間に置き、照準で操作したり、持って動かしたり、大きさを変えたりする。画面に出しているパネルも、ほかの人からは同じ位置と大きさで見える。
- AI エージェントも MCP から参加し、人と同じ仕組みで制作できる。Entity をまとめて読み書きし、素材を取り込んで材質に貼り、開いている画面の指定した視点を確かめられる。
- エージェントはプレハブの作成・変換・配置、インスタンスの編集・復帰・複製・適用・リンク解除もできる。エージェントからの適用には確認画面を出さない。ライブラリの定義は変更できない。

## 試す・遊ぶ・更新する

- ワークスペースで再生し、結果を参加者で共有する。再生を動かしているホストが抜けたら、別の管理者が引き継ぐ。
- アウトプットを「セッションに出す」と、みんなで遊べる。置いた位置と向きは作品全体が持ち、中の位置は作ったときのまま残る。ワークスペースで再生したときも同じ。編集を続けて「適用」すると、つながった配置がまとめて更新される。
- 「維持」を付けたフィールドは、適用したあとも実行中の値を保つ。リセットで初期値からやり直せる。
- 適用で切り替わるのは、そのアウトプットの配置だけ。ほかのアウトプットの配置は、それまでの中身のまま動き続ける。
- 物を持って動かす。道具を装備して使う。装備した道具には、装備した人の入力だけが届き、ほかの人からは構えた姿が見える。
- Collider を付けた物に、プレイヤーがぶつかる。壁はすり抜けず、床やおよそ 35cm までの段の上を歩き、およそ 50 度までの坂を上る。sensor にすると押し返さない。Mesh だけではすり抜ける。
- RigidBody を付けた物は重力で落ち、Collider と、高さ 0 の地面で止まる。重力の倍率を 0 にすると落ちない。形・大きさ・摩擦・跳ね返りは Collider で、見た目と別にできる。軸ごとに移動と回転を固定でき、1 つの平面の中だけで動く物（2D 風の遊び）や、倒れない物を作れる。
- 実行して止まった System の問題は、次の再生まで残る。再生のあとに編集しても、その変更が届かない System の問題は今の結果として残る。

## 作品を組み合わせる

- 別々のプロジェクトで作った作品（たとえば銃と射撃場）を、同じセッションで組み合わせて遊ぶ。
- 別の作者の作品とは、中身に触れず、公開された操作（Contract）でやり取りする。
- 作品の「外からの見え方」と、ワールドが外から来たアイテムに許すことを選ぶ。
- System が使う権限はコードから読み取られ、セッションでは許された範囲だけが動く。拒まれた操作は、注意として知らせる。
- ライブラリをプロジェクトに追加し、その KokoState・System・プレハブを使う。バージョンと中身を固定して使い、ライブラリの依存も読み込む。
- ライブラリのプレハブは中身を開いて見たり、インスタンスを配置して変えたりできる。定義への適用はできないが、インスタンスのリンクは解除できる。
- ライブラリのアウトプットごとに、含めるリソースを選ぶ。
- 公式ライブラリ（combat・interaction・items）と、それを使うサンプルがある。公式かどうかは、名前ではなく発行者で決まる。
- Host API と組み込みの Contract は、今はすべて experimental（互換性なく変わることがある）。

今は、参加者のブラウザが実行役になる協調セッションで、ホストを信頼している。正規のクライアント上の作品に対する権限の制限はあるが、改変したホストからの保護はまだない。

## 残す・渡す・作り直す

- 制作データをメッセージ付きで保存し、履歴と差分を見る。差分は名前と中身で出し、フィールドや行ごとに最後の保存の形へ戻せる。一緒に編集した人の名前も残る。
- アウトプットをリリースとして公開し、バージョンを重ねる。利用・元データの閲覧・フォークと抽出の権限を分ける。
- 公開されたワールドとアイテムをセッションに置く。置いたものは作っているワークスペースとは別で、適用の対象にならない。
- マーケットで、作者が登録したアイテムとワールドを、名前・作者・公開タグ・種類から探し、新着・人気・安い順に並べ、ポイントで入手する（はじめは 1,000 P）。詳細で価格・バージョンと保存のコメント・登録や価格の履歴を見て、公開されたプロジェクトへたどれる。
- マーケットのマイページで、リリースを選んで価格・タグ・自動公開を決めて登録し、あとから編集・取り消しできる。売れると価格の 9 割が自分のポイントになり、入手の記録（誰かは出さない）を見られる。
- マーケットとワールドの画面に出る作品の名前は、マーケットで公開中の版のアウトプットの名前（マーケットに出していなければ最新の版の名前）。
- 無料のワールドと購入した有料のワールドは、ワールドの画面から開ける。購入していない有料のワールドは鍵がかかり、ワールドの画面からマーケットへ移って購入する。
- 入手したアイテムは、そのバージョンのまま所持アイテムに残り、自動では更新されない。タグやお気に入りで絞り込み、今のセッションへ取り出す。
- アイテムの画面の「自分のアイテム」では、マーケットに出していない非公開のものも含めて、自分がリリースしたアイテムの最新の版を、所持アイテムに加えずに取り出せる。
- アイテムの画面の「すべて」にも、自分がリリースしたアイテムが並ぶ（入手していなければ最新の版）。マーケットに出していないものには「非公開」の印が付く。
- 所持アイテムに新しいバージョンが出ると印が付き、詳細から最新のバージョンへアップデートできる。いらないアイテムは確認して所持アイテムから消せる。セッションに出しているものは消えない。
- 作者は公開タグを付け、あとから直せる。
