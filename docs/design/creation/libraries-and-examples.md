# 公式ライブラリと作例

制作で繰り返し使う部品と、動かして改造できる小さな作品を提供する。作品を作りながら、基盤に必要なものと作品ごとに決めたいものを確かめる。

## 公式ライブラリの役割

公式ライブラリも、利用者と同じAPIと公開・依存の仕組みを使う。特別な権限は持たない。「公式」は発行者を表し、他のライブラリと同じように版を固定して使う。

共通にできる処理を部品にし、遊びの個性になる部分は作品側へ残す。例えば、体力を減らす処理は共通にできるが、銃の連射間隔や的が倒れて戻る動きは、作りたい遊びに合わせて決める。

| 部品の例 | 共通にするもの | 作例側が決めるもの |
| --- | --- | --- |
| combat | 体力とダメージを受ける処理 | 銃の動作、的の復活、得点。 |
| interaction | 押す操作によるオン・オフ | 扉の開き方、スイッチの見た目。 |

物理・入力の受け渡し・作品間の境界など、共通部品だけでは受け持てない機能は基盤が扱う。何を公式に用意するかは、複数の作品を作って再利用の効果を確かめながら決める。

## 作例の役割

「銃と的」「扉とスイッチ」など、始めから終わりまで動く小さな作品で、作れることと足りないことを確かめる。遊び方、仕組み、変えて試せる場所が分かる、制作の入口にもなる。

同じ作者の中で動くだけでなく、別々に作った作品を組み合わせて動くことも確かめる。共有する部品と、各作品が管理する状態や処理の境界を見つけるため。

少人数で対戦やミニゲームを一緒に作る体験を、次の検証の中心にする。ライブラリでどこまで共通にすると作りやすく、どこから自由さを狭めるかは、引き続き試す部分。
