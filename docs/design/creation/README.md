# 制作の基盤

作品のデータと動きを作り、ほかの人と編集し、試してから遊びへ反映する。言葉の意味と関係は[用語](../glossary.md)へ。

## プロジェクトと共同編集

プロジェクトは制作データと履歴を持ち、ワークスペースはそれを開いて一緒に編集する場所になる。一つのセッションで、別々のプロジェクトを並べて作れる。今の試作では、一つのプロジェクトを同時に開くワークスペースは一つ。

制作データの変更は参加者の間で共有する。同じ要素の別の欄を同時に変えても、それぞれの変更を残す。コードも共同編集でき、選択やカーソルで互いの作業が分かる。画面上のパネル配置やスクロール位置は各自の作業環境として扱う。

閲覧・共同編集・管理の役割を分ける。初期設定では共同編集でき、非公開の作業では参加を許した人だけが内容を見られる。セッションに参加することと、個々の制作データを編集できることは別の扱いになる。

AIエージェントも、別の参加者として同じ権限と共同編集の仕組みを通して制作する。入口はMCPで、編集は人の画面にも届く。現在、履歴へのコミットと共有する試し再生のホストは人が担う。

関連する判断：[共同編集](../../adr/0004-workspace-sync-yjs.md)、[欄ごとの同時編集](../../adr/0037-field-level-collaboration.md)、[参加と役割](../../adr/0005-sessions-identity-host.md)、[エージェントによる制作](../../adr/0054-agent-remote-mcp.md)。

## 作業途中の保存と履歴

作業途中の内容は自動保存し、閉じても続きから編集できる。区切りとして残す履歴はコミットで記録する。履歴は差分や由来を調べ、公開する版の元になる。差分は作品内の名前と変更前後の内容で示し、何を変えたかを確かめられる。

現在、コミットできるのはプロジェクトの持ち主で、一緒に編集している人も記録に添える。履歴はGitで保持し、共同編集中のデータとは役割を分けている。

関連する判断：[プロジェクトと履歴](../../adr/0007-repos-commits-works.md)、[変更の見せ方](../../adr/0041-history-diff-detail.md)。公開する版は[公開・再利用の基盤](../publishing/README.md)へ。

## 作品のデータと動き

作品は、EKS（Entity / KokoState / System）でデータと処理を組み合わせて作る。作者は独自の状態と処理を定義できる。例えば、的に体力を付け、ダメージを受けると体力を減らす処理を書く。

プロジェクト内の定義や素材を使い、出力ごとにEntityと動かすSystemをまとめる。出力にはアイテム・ワールド・ライブラリがあり、一つのプロジェクトから複数の出力を作れる。

続く値はKokoState、押した・当たったといった一度の出来事はイベントとして扱う。出来事を保存用の値で代用すると、いつ消すかまで作品側で管理する必要が出るため。

見た目、当たり判定、動きは、それぞれの状態と処理を組み合わせる。モデル・画像・音声は素材として参照し、素材の本体と制作データを分けて持つ。

関連する判断：[状態と出来事の役割](../../adr/0011-kokostate-event-capability-package.md)、[素材](../../adr/0006-session-world-apply-assets.md#素材glb画像音声)。

## 名前と参照

名前やフォルダは人が整理するためのもの、IDは同じリソースを指し続けるためのもの。スクリプトではパスで参照を書き、実行には解決したIDを使う。

編集機能で名前や置き場所を変えたときは、参照先を保って書き方を更新する。同じパスが別のリソースを指すようになった場合は、黙って付け替えず、問題として知らせる。

関連する判断：[同一性・パス・参照](../../adr/0010-resource-identity-paths-diagnostics.md)。

## スクリプトと制作支援

作者のコードは、ブラウザの画面を動かすコードと分けて実行する。物理や音などの機能はHost APIを通して使う。今はQuickJS上のJavaScriptで、処理時間やメモリ使用に制限を設けている。

コードや定義は出所と版に応じた実行領域へ分ける。ライブラリのコードも使う側のコードと分け、別の作品や版の変数が混ざらないようにする。再読み込みや引き継ぎで残す値は、スクリプトの変数だけに持たせず、状態として扱う必要がある。

問題の表示は、今の制作データや実行について直す場所を示す。時系列のログとは分け、古い検査結果も区別する。問題があっても試し再生はでき、壊れたSystemを止めて原因を知らせる。

次の制作体験として、TypeScriptの型注釈やinterfaceを書き、型チェックと入力補完で間違いを減らせることを目指す。現在のJavaScriptと入力補完から、これから拡張する部分。

関連する判断：[スクリプト実行](../../adr/0001-script-runtime-quickjs.md)、[参照と診断](../../adr/0010-resource-identity-paths-diagnostics.md)、[ライブラリの実行](../../adr/0015-library-package-minimal.md)。

## 空間の中で作る

制作パネルは画面に固定することも、3D空間へ置くこともできる。置き方を変えても編集内容や操作の途中の状態を保ち、自分の作業のしやすさと、周囲に作業が見えることを両立する。

ほかの人にはパネルの要約や編集中の見た目を伝える。内容は閲覧の権限に応じて見せ分ける。全員に同じ画面や入力途中の内容を見せる方式ではない。

アイテムはセッションの中で編集できる。ワールドの編集や非公開の作業には、遊ぶ場所から離した編集空間を使う。非公開の作業をセッションへ出すには、先に作業の公開範囲を変える。

関連する判断：[制作パネル](../../adr/0003-panels-2d-3d.md)、[空間での操作](../../adr/0009-spatial-input-grab-folders.md)、[編集空間と見せ分け](../../adr/0008-private-work-world-editing.md)。

## 試し再生と適用

制作データは、形、コード、初期値など、作者が編集して残すもの。実行状態は、今の位置や残弾など、動かしている間に変わるもの。試し撃ちで残弾が減っても、制作データの初期値は残る。

ワークスペースの試し再生と、セッションでの遊びも独立する。試し再生を止めると現在の制作データへ戻り、セッションの遊びは続く。再生の共有と実行役は[実行を共有する](../play/README.md#実行を共有する)で説明する。

編集しただけでは、遊んでいる作品は変えない。「適用」で、このワークスペースの同じ出力につながった配置をまとめて更新する。公開されたリリースから置いた配置は、この適用の対象にならない。

更新後も残したい値には、出力ごとに「維持」を付ける。IDで対応するフィールドの型が同じなら、実行中の値を引き継ぐ。装備や手に持った状態と位置は、更新後も対応する要素と機能がある場合に引き継ぐ。それ以外は新しい制作データの値になる。リセットでは、配置に最後に取り込んだ制作データの初期値からやり直す。

途中で生まれた物は、ADR 0006では適用後も残すとしているが、現在の実装では配置を作り直す際に消える。適用後にどこまで遊びを継続するかは、整理が必要。

関連する判断：[適用と状態維持](../../adr/0006-session-world-apply-assets.md)、[版ごとの実行領域](../../adr/0010-resource-identity-paths-diagnostics.md)、[装備の引き継ぎ](../../adr/0053-equipment-tool.md)。
