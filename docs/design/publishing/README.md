# 公開・再利用の基盤

作ったものをほかの人が使い、仕組みを学び、改造して次の作品につなげる。制作途中の変更と、使う人に渡す版を分けることで、作者も利用者も試しやすくする。

## 公開する単位と版

プロジェクトは制作データと履歴を持つ。そこにある出力を公開作品（Work）として扱い、特定のコミットからリリースを作る。制作物全般を指す「作品」と、公開の単位としてのWorkは文脈を分ける。

リリースは公開した時点の版を指す。作者が編集を続けても、利用中の版は勝手に変わらない。アイテムやワールドは、そのリリースをセッションに配置して使う。配置後の遊びの状態は、それぞれのセッションが持つ。

作業中のワークスペースから出す配置と、公開したリリースから置く配置は別のつながりを持つ。前者は「適用」で更新でき、後者は公開された版を使う。

関連する判断：[プロジェクト・公開作品・リリース](../../adr/0007-repos-commits-works.md)。

## 利用と元データの公開

作品を使うこと、元の制作データを見ること、フォーク・抽出することは、別の許可として扱う。共同編集中のワークスペースの権限とも分かれている。

[現在の実装](../../../apps/server/src/repos/service.ts)では、非公開プロジェクトでも、その公開作品に元データ閲覧やフォークを許すと、プロジェクト単位のアクセスにつながる。公開した出力だけに絞るかは整理が必要で、出力ごとに元データが隔離されているとは扱わない。

関連する判断：[公開範囲と許可](../../adr/0007-repos-commits-works.md)。

## ライブラリを依存として使う

ライブラリは、セッションに置く物ではなく、制作で使う定義や処理を配る出力。公開作品のIDをPackageのID、リリース番号を版として使う。

利用するプロジェクトは、ライブラリに別名を付け、Package・版・中身を識別する値（content hash）を固定する。最新版へ自動で切り替えず、同じ版を使い続けられるようにする。ライブラリの出力ごとに含めるリソースを選び、それが外から使える範囲になる。同じプロジェクトでも、中身の違うライブラリを作れる。

今は、公開されたKokoStateをimportし、Systemを出力に組み込んで使える。同じPackageの同じ版の定義は、別の作品でも同じ種類として扱う。ただし、種類が同じでも各配置の状態は別であり、ほかの配置を自由に読み書きできるわけではない。

ライブラリが使う別のライブラリも、固定された依存としてたどる。使う側が直接選べるものと、依存先の内部で必要なものを分ける。複数の版は共存できるが、別の版の型は別物として扱う。

現在、依存の依存は、それを利用するライブラリの作者の許可で取得する。利用者が直接参照できない部品でも、依存先を動かすために公開分が届く場合がある。

関連する判断：[Packageの同一性と版](../../adr/0013-package-identity-version.md)、[公開範囲・依存・実行](../../adr/0015-library-package-minimal.md)、[出力ごとに含めるリソース](../../adr/0055-library-included-resources.md)。

## 改造と再利用

| 方法 | 引き継ぐもの | 使い道 |
| --- | --- | --- |
| 依存に追加 | 固定した版への参照 | 共通部品として使う。 |
| フォーク | プロジェクトと履歴、依存、元の由来 | 全体を自分の制作物として改造する。 |
| 抽出 | 選んだ出力やリソースと、それに必要なもの | 一部を別のプロジェクトへ取り込む。 |

抽出では、必要なリソースやライブラリ依存も持っていき、取り込み先の名前や参照へ合わせる。由来は残るが、コピーした部分が元の更新に自動追従するわけではない。

編集中のワークスペースへ取り込む場合は、今ある内容を保って必要なものを追加し、共同編集にも反映する。Gitへ直接抽出する経路では、編集用データがすでにある取り込み先を拒否し、編集中の内容との食い違いを防ぐ。

関連する判断：[フォークと抽出](../../adr/0007-repos-commits-works.md)、[依存を含む取り込み](../../adr/0015-library-package-minimal.md)、[既存先への抽出](../../adr/0038-extract-into-editable-repo.md)、[編集中の取り込み](../../adr/0052-import-from-project.md)。

## 探して使う体験

公開された作品を探し、アイテムやワールドを遊びに取り込み、ライブラリを制作の依存へ追加できることを目指す。ワークショップの初期範囲には、ライブラリの検索から依存への追加までを含める。

現在のマーケットはアイテムを名前・作者・公開タグで探し、版を選んで入手する場所。所持一覧には入手した版を残し、自動更新しない。所持は整理のための記録で、利用権限を増やすものではない。

ライブラリは公開作品の一覧から依存に追加できる。ライブラリの検索と更新の案内は、これから整える部分。

関連する判断：[所持と版の固定](../../adr/0024-owned-items-and-placement.md)、[公開タグ](../../adr/0034-owned-item-tags-and-browsing.md)、[作品の詳細と検索範囲](../../adr/0047-market-work-detail.md)。

## プロトタイプとしての変更

Host APIと組み込みContractは、現在すべてexperimentalとして扱う。公式ライブラリも利用者の作品と同じ公開・依存の仕組みを使い、公式であることだけで互換性を約束しない。

プロトタイプの間は、変更内容を事前に知らせたうえで、制作データの作り直しやスクリプトの手動修正を許容する。版の固定は利用する部品を選ぶための仕組みであり、プラットフォームの変更をすべて吸収する保証ではない。

関連する判断：[APIの安定度と公式ライブラリ](../../adr/0019-api-stability-all-experimental.md)。
