# 遊びの基盤

人が同じ空間に集まり、操作し、別々に作られた作品を組み合わせて遊ぶ。言葉の意味と関係は[用語](../glossary.md)へ。

## 空間と参加者

セッションに集まり、互いの姿と作品を見ながら遊ぶ。参加者の識別にはIDを使い、表示名は人に見せるために使う。名前が同じでも同じ人とは扱わない。

セッションは持ち主が開いている間の集まりであり、閉じると配置と遊びの途中の状態は終わる。制作データや公開した作品は残り、また開いて使える。

公開されたワールドを開くことで、遊ぶ場所を選べる。ワールドを切り替えると、それまでのワールドを外し、アイテムは残す。同じリリースだけが開いているときは、そのまま続ける。

制作中の「セッションに出す」は追加配置なので、現在は複数のワールドを置ける。複数ワールドを常設の遊び方としてどう扱うかは未整理。

参加しただけでは編集を始めない。ワークスペースなしでも遊びや見学ができ、編集を終えてもセッションに残れる。作品や人を探すウィンドウを開いても、現在の集まりや作業は保つ。

フレンドは申請と承認でつながり、状態や参加先を共有する。状態は交流の意思を伝えるもので、参加や編集の権限は変えない。招待を受けても勝手には移動せず、本人が参加先を確かめて移動する。

## 操作と表現

移動や視線、物を持つ操作を基盤が受け持ち、撃つ・押すなどの入力を作品の処理へ届ける。編集で対象を選ぶ操作と、作品で遊ぶ操作が混ざらないようにする。

道具を装備することと、物を持って動かすことは分ける。装備した道具には、その人の入力だけを届ける。装備はセッションの中で扱い、別のセッションへは持ち歩かない。

入力は試し再生とセッションでの遊びのどちらを操作しているかに応じて届ける。ネットワークを通る入力の本人はサーバーが接続から決め、表示名は表示のために添える。

作品の状態から見た目や空間内の文字を描き、音や一時的な効果も参加者へ伝える。現在の文字表示は空間に置くLabel。各プレイヤーの画面に固定してスコア・残弾・残り時間を出す最小限のHUDは、初期範囲に含めるが、これから作る部分。

## 作品を組み合わせる

各配置は、自分の状態と処理を持つ。別の作品には公開された操作（Contract）で働きかける。例えば、銃はダメージを伝え、的が自分の体力をどう減らすかを決める。相手の内部の作りに依存せず組み合わせるため。

作品は、外から操作を受けるか、当たり判定だけを見せるか、相手の探索対象にしないかを選べる。ワールド側も、外から持ち込まれたアイテムに許すやり取りを制限できる。この見え方は作品間の操作の範囲であり、制作データの閲覧権限とは別の設定。

Host APIを使える範囲は、Systemが必要とする機能と配置への許可で決まる。セッションでは、さらにワールドの上限と相手が受け付ける操作を確かめる。作者が試すワークスペースの再生とは、権限の適用範囲が異なる。

今の試作はホストを信頼する協調セッション。ミニゲームを一緒に試すことを対象とし、競争の結果をサーバーで確定する仕組みはまだ持たない。ワールドの上限は、現在は最初に置かれたワールドを土台として扱う。

関連する判断：[状態・操作・機能の役割](../../adr/0011-kokostate-event-capability-package.md)、[配置間の境界と許可](../../adr/0012-runtime-authority-target-policy.md)。

## 実行を共有する

参加者で共有する作品の実行はホストのブラウザが担い、ほかの参加者は入力を送り、届いた状態を表示する。サーバーは参加と権限を管理し、編集の更新・入力・実行状態を中継する。

| 実行する場所 | ホスト | ホストが抜けたとき |
| --- | --- | --- |
| ワークスペースの試し再生 | 開いている管理者の一人（エージェントを除く） | 別の管理者へ引き継ぐ（エージェントを除く）。いなければ試し再生を止める。 |
| セッションの遊び | セッションの持ち主 | 実行を止め、猶予中に戻れば再開する。戻らなければセッションを閉じる。 |

再開には、サーバーに届いた最後の状態を使う。現在はEntityとKokoStateの値から物理を組み立て直す方式で、スクリプトの変数や物理計算の内部を丸ごと引き継ぐ方式ではない。途中で生まれた物は、どの配置に属するかも引き継ぎ、処理や削除の対象から外れないようにする。

制作中の変更を取り込む方法と、そのときに残す値は[試し再生と適用](../creation/README.md#試し再生と適用)へ。
