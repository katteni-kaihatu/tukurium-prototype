# 用語

構想・設計で使う言葉の意味と呼び方をまとめる。優先語は、新しく文章を書くときにまず使う名前の案。別の呼び方も、既存資料を読むために残す。

ここでの対応はTukuriumの文脈に限る。コード上の名前や、技術一般の説明まで一律に言い換えるものではない。

## タグ

タグは、どんな話題で使う語かを示す目印。複数付けてよい。資料の置き場所とは独立して付ける。

| タグ | 定義 |
| --- | --- |
| プロダクト | 利用者が何を扱い、何をするかを説明する言葉。 |
| システム | Tukuriumの動作・役割分担・規則を説明する言葉。 |
| 技術 | 何を使い、どんな方式で実現するかを説明する言葉。 |
| ライブラリ・作例 | 作品やライブラリで扱う内容・ルール・部品を表す言葉。 |

例えば、出力・配置は利用者が扱う単位でも、システムの動作を説明する単位でもある。実行領域はTukuriumの仕組みと、その実現方式の両方に関わる。

## 用語一覧

| 優先語 | タグ | 別の呼び方 | 意味・使い分け |
| --- | --- | --- | --- |
| プロジェクト | プロダクト、システム | リポジトリ、Repo | 制作データと履歴をまとめて残す単位。Gitの保存の仕組みを説明するときは「リポジトリ」を使う。 |
| ワークスペース | プロダクト、システム | Workspace | プロジェクトを開き、複数人で編集・試し再生する作業場所。 |
| セッション | プロダクト、システム | インスタンス、部屋、Session | 人が集まり、作品を作ったり組み合わせて遊んだりする場所。この意味では「セッション」を使う。 |
| 出力 | プロダクト、システム | アウトプット、Output | プロジェクトの一部を、アイテム・ワールド・ライブラリとして使うまとまり。 |
| 配置 | プロダクト、システム | Placement | アイテムやワールドの出力をセッションに置いた実体。同じ出力から複数作れる。 |
| 公開作品 | プロダクト、システム | 作品（公開の文脈）、Work | 出力を公開する単位。制作物全般を指す「作品」と区別した呼び方の案。 |
| 所持アイテム | プロダクト、システム | 所持品 | 入手したアイテムと版の記録。セッションに置いた実体や、装備している道具とは区別する。所持しても利用権限は増えない。 |
| マーケット | プロダクト | Market | 公開作品を探して入手する入口。現在の検索対象はアイテム。 |
| リリース | プロダクト、システム | Release | 公開作品の、特定のコミットに結び付いた版。 |
| ライブラリ | プロダクト、システム | Library | ほかの制作で使う定義や処理をまとめた出力。セッションへの配置ではなく依存として使う。 |
| Package | システム、技術 | パッケージ | 配布する部品の出所と版を扱う単位。現在はライブラリの公開作品とリリースに対応する。 |
| 依存 | プロダクト、システム | Dependency | プロジェクトやライブラリが使う別のライブラリ。版と中身を固定して参照する。 |
| フォーク | プロダクト | Fork | プロジェクトを履歴と由来ごと複製して改造すること。 |
| 抽出 | プロダクト | Extract | 選んだ出力やリソースを、必要なものと一緒に別のプロジェクトへ取り込むこと。 |
| ホスト | システム | 実行役、Host | 作品の処理を動かし、参加者へ状態を送る役。セッションとワークスペースで選び方が異なる。 |
| 実行領域 | システム、技術 | realm | スクリプトが動く領域。出所や版ごとに分け、異なる版のコードが混ざらないようにする。 |
| Contract | システム | 公開操作 | 作品が外へ公開する操作の型。受け手が処理を決める。 |
| Capability | システム | — | 作品がホストの機能を使うための許可。どの機能を使えるかを表す。 |
| Host API | システム、技術 | ホストAPI | 物理や音など、基盤の機能をスクリプトから呼ぶための入口。 |
| EKS | システム、技術 | ECS | Entity / KokoState / Systemで、データと処理を組み合わせて作品を作る方式。今のTukuriumではECSとほぼ同じ意味で使う。 |
| Entity | プロダクト、技術 | エンティティ | 的や扉など、作品の中の一つの要素。 |
| KokoState | プロダクト、技術 | ECSのComponent、コンポーネント | 位置や体力など、要素が持つ状態。UI部品などを指すComponentとは区別する。 |
| イベント | システム、技術 | Event | 押した・当たったなど、一度の出来事。継続する状態や公開操作の型（Contract）とは役割が異なる。 |
| System | プロダクト、技術 | システム | どの状態を持つかで対象を選び、動かす処理。 |
| Health | ライブラリ・作例 | 体力 | 体力を表す、[公式ライブラリcombat](../adr/0016-official-library-reference-ugc.md)のKokoState。 |
| Damage | ライブラリ・作例 | ダメージ操作 | ダメージを伝えるContract。今は基盤に組み込まれており、体力をどう変えるかは受け手が決める。 |
| Damageable | ライブラリ・作例 | — | Damageを受けてHealthの体力を減らす、公式ライブラリcombatのSystem。 |

広く参照する語をここに載せ、個々の部品の細かな説明はライブラリや作例の資料へ置く。

## 用語の関係

一つのセッションに複数のワークスペースを開ける。例えば、銃と射撃場を別のプロジェクトで編集し、それぞれの出力を同じセッションへ配置して遊ぶ。

セッションを閉じても、プロジェクトの制作データと履歴は残り、編集を再開できる。

「インスタンス」は個々の実体を指す場合もある。セッションとワールド、出力と配置のように、別の概念を同じ名前でまとめない。

プロジェクトの出力を公開作品として扱い、コミットからリリースを作る。ライブラリのリリースは依存として使い、アイテムやワールドのリリースはセッションへ配置する。
