# Tukuriumの原則

プロトタイプとしてのTukuriumが目指すことを書く。テーマは実現したい状態、原則はそのための一段具体的な方針。原則は、判断に迷ったときに頼るもの。

個々の仕組みや判断は[ADR](../adr/README.md)、実装の状況は[ロードマップ](../ROADMAP.md)、言葉の意味は[用語](glossary.md)を参照。

## テーマ：一緒に作ることを、誰もが遊びとして楽しめる場所にする

一人で作るだけでなく、人と一緒に作ることを中心に置く。居合わせた人とその場で作ることも、作品を通じて時間を越えて作ることも含む。慣れた人だけのものにせず、多くの人が気軽に加われるようにする。楽しいだけで終わらず、本当に使えるものが作れる場所にする。

## 原則

### 1. 作る場所と遊ぶ場所を同じにする

作る人・遊ぶ人・見ている人が同じ空間にいて、作っている途中もその場で一緒に試せるようにする。居合わせた人と、その場で一緒に作り始められるようにする。

### 2. 入口は低く、奥は深く

初めての人も、ほかの人の作ったものを触ったり少し変えたりするところから、すぐ加われるようにする。加わるときの壁は、見つけたらできるだけ取り除く。同時に、慣れた人が本気で作り込める道具としても使えるようにする。

迷ったときの決め方：手軽にするために、できることを削らない。奥の機能が、入口を難しくしない。

### 3. 安心して作れる

試しても、失敗しても、戻れるようにする。自分の変更がほかの人の遊びや作品を勝手に壊さず、ほかの人の変更で自分のものが勝手に変わることもない。一緒に作っている人の間ではすぐ伝わり、使っている人へは選んだときに届く。

### 4. 一度作ったものを、何度でも、誰とでも使える

同じものを何度も作らなくて済むようにする。中身を知らなくても、自分やほかの人の作ったものを部品として使い、組み合わせて動かせる。公式のものも、利用者と同じ仕組みで提供する。

### 5. その場にいない人とも、作品を通じて一緒に作れる

公開された作品の中身を開いて、仕組みを学び、改造し、自分の作品につなげられるようにする。自分の作品も、また誰かの作品の土台になる。誰の作品から来たかが分かるようにし、受け渡しのつながりを残す。同じ時間に同じ場所にいなくても、作品を受け渡すことで一緒に作っている状態をつくる。

## プロトタイプとしての割り切り

いまは、原則が成り立つかを速く確かめることを優先する。

- 対象は、まず少人数で一緒に作り、遊ぶ場面に絞る。
- 保存形式の互換性、不正への対策、性能の作り込み、APIの安定は後回しにする。

ここに書くことは、本体では変わりうる。
