# Tukuriumの原則

プロトタイプとしてのTukuriumが目指すことを書く。原則は、目指す状態を表す。判断に迷ったときに頼るもの。

個々の仕組みや判断は[ADR](adr/README.md)、実装の状況は[ロードマップ](ROADMAP.md)、言葉の意味は[用語](GLOSSARY.md)を参照。

## テーマ：クリエイターコラボレーション

誰もが、一緒に作ることを楽しめる。

## 原則

★ はTukuriumらしさの核。外したらTukuriumでなくなるもの。

### ★ 1. 作る場所と遊ぶ場所が同じ

作る人・遊ぶ人・見ている人が同じ空間にいる。作っている途中もその場で動かして試せ、居合わせた人と一緒に作り始められる。作ることが、人と過ごす遊びの一つになっている。

### ★ 2. 入口は低く、奥は深い

初めての人も、ほかの人の作ったものを触ったり少し変えたりするところから、すぐ加われる。加わるときの壁が少ない。同時に、慣れた人が本気で作り込める道具として使える。

### 3. その場にいない人とも、作品を通じて一緒に作れる

公開された作品の中身を開いて、仕組みを学び、改造し、自分の作品につなげられる。自分の作品も、また誰かの作品の土台になる。誰の作品から来たかが分かり、受け渡しのつながりが残る。

### 4. 一度作ったものを、何度でも、誰とでも使える

同じものを何度も作らなくて済む。中身を知らなくても、自分やほかの人の作ったものを部品として使い、組み合わせて動かせる。公式のものも、利用者と同じ仕組みで提供されている。

### 5. 安心して作れる

試しても、失敗しても、戻れる。自分の変更がほかの人の遊びや作品を勝手に壊さず、ほかの人の変更で自分のものが勝手に変わることもない。一緒に作っている人の間ではすぐ伝わり、使っている人へは選んだときに届く。

## プロトタイプとしての割り切り

いまは、原則が成り立つかを速く確かめることを優先する。

- 対象は、まず少人数で一緒に作り、遊ぶ場面に絞る。
- 保存形式の互換性、不正への対策、性能の作り込み、APIの安定は後回しにする。

ここに書くことは、本体では変わりうる。
