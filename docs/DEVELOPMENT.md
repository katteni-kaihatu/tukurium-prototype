# 開発メモ：詰まりやすい点

開発中に実際に時間を取られた点を、原因と対策つきでまとめる。新しく詰まったら書き足す。

## E2E（Playwright）

| 症状 | 原因 | 対策 |
| --- | --- | --- |
| 通しで流すと後半のテストが時間切れで落ちる。1 本ずつなら通る | 2 人目以降のブラウザコンテキストを閉じておらず、前のテストの画面が描画（ソフトウェア WebGL）を続けていた | `e2e/helpers.ts` の `test` と `newPerson()` を使う。テストの終わりに自動で閉じる（Biome で強制）。通しの実行時間は 8.7 分から 2.9 分に短くなった |
| 依存を足した直後の初回だけ失敗する | Vite が依存を最適化し直してページを再読み込みする | もう一度流す。CI ではビルド済みの状態で流す |
| 向きを変えた直後のレイキャストが外れる | カメラの向きは描画のフレームで反映される | `aimAt()` は 2 フレーム待つ。自前で向きを変えたら `requestAnimationFrame` を 2 回待つ |
| 撃ったのに弾が減らない | 銃のクールダウン（0.2 秒） | 撃つ間隔をあける（`fire()` は 150ms 待つ） |
| `getByText` / `getByRole` が複数に当たる | 「銃」「銃と的」などの部分一致 | `exact: true` か、名前の正規表現を詳しくする |
| 失敗の原因が分からない | — | `test-results/<テスト名>/error-context.md` に、失敗時の画面の構造（アクセシビリティツリー）が残る。まずそれを読む |
| runtime のクラス（Simulation など）にメソッドを足したのに、画面で「〜 is not a function」が出続ける。E2E は通る | 長く動かしていた開発サーバーが、変更前のモジュールを持ち続けていた（E2E は `reuseExistingServer` で同じサーバーを使うので、ページのエラーを見落とす） | packages/ のクラスの形を変えたら `pnpm dev` を起動し直す。確認用のスクリプトでは `pageerror` を数えて 0 件を確かめる |
| ポインターロック中はクリックがパネルに届かない | ヘッドレスではポインターロックが不安定 | 入力は `__workspace.getState().input(...)` などで直接渡す。パネルのクリックを確かめるときは `page.mouse.click()` で座標をクリックする |

## 3D パネル（CSS3DRenderer）

- **同じ場所に重ねて置くと、後ろのパネルがクリックを受け取れない。** 3D にするとき、画面上でいまある位置に、同じ大きさで見える奥行きに置く（`PanelLayer.tsx` の `placeInFront`）。
- **カメラの後ろにある CSS3D 要素は、画面いっぱいに広がってクリックを受け取ってしまうことがある。** 毎フレーム後ろのパネルを隠す（`PanelSpace.update`）。裏から見たときも `backface-visibility: hidden` で隠す。
- 3D のパネルを操作しづらくなったときに画面へ戻せるよう、画面左下に「空間のパネル」の一覧（画面に戻す）を出している。
- 確かめるときは `document.elementFromPoint()` で、ボタンの中心が本当にそのボタンに当たるかを調べる。
- **空間に入っている（ポインターロック中）ときは、クリックが DOM に届かない。** 照準の先の要素へイベントを合成して渡している（ADR 0009）。合成したイベントは document に返ってくるので、`isTrusted` でないものは扱わない（扱うと無限に繰り返して落ちる）。
- ヘッドレスのブラウザではポインターロックできないので、確かめるときは `controller.locked` を `Object.defineProperty` で true にして真似る。
- 3D パネルを動かしたら、置き場所を PanelLayer の状態に保存する（`PanelSpace.onMoved`）。大きさを変えたときも、幅と高さを状態に保存する。保存しないと、次の描画で元の場所・大きさに戻る。
- 持った物の位置は視点の向きだけからカメラの姿勢を作り直している（ロールは 0）。カメラの回し方を変えたら、`viewQuaternion` も合わせる。合わせないと、持った瞬間に物がずれる。
- 3D のパネルを持つときも、物と同じ `poseInView` / `placeFromView` を使う。パネルの置き場所は上下の軸まわりの角度しか覚えないので、持っている間は傾きを捨てる（`straightenRotation`）。ここを視線の先へ載せたり、こちら向きに直したりすると、持った瞬間にパネルが飛ぶ。
- 空間から出たとき（Esc など）は、`pointerlockchange` の時点で `locked` がすでに false になっている。右クリックを押したまま出たら、その場で持っている物を放す。`locked` を見てから放すと、手を離したことにならず、持ったまま残る。
- 画面下の操作説明と重なると、3D にしたパネルの右下（大きさを変えるところ）はクリックできない。パネルを少し動かせば掴める。
- 空間に入った状態のクリックは、自分で作ったマウスイベントをパネルへ渡している。`detail` を付けないと 0 になり、CodeMirror はそれを行全体の選択とみなす。カーソルが出ず、文字も意図した場所に入らない。1 回のクリックとして `detail: 1` を付ける。
- 3D パネルの中では、コードのカーソルの点滅が途中で止まったまま消えることがある。点滅を切って、線を少し太くしている。
- 3D パネルを斜めから見ると、`getBoundingClientRect` は回転で膨らんだ外接矩形を返す。コードエディタがそれで行の高さとカーソル位置を決めると、カーソルが文字からずれ、行番号も行と揃わない。3D のエディタでは変形しない配置の矩形に置き換える（`editorCoords.ts`）。
- 矩形の置き換えをエディタの中だけにすると、外側のスクロール枠（パネルの中身など）は画面上の位置のまま残る。コードエディタは両方を交差させて、描く行を決める。座標が違うので見える範囲が欠け、スクロールすると行が出たり消えたりする。エディタを包む枠にはスクロール枠の大きさで原点を覆う矩形を返す。パネルの入れ物（`data-mode` の要素）はピン留めと大きさの計算に使うので、画面上の矩形のままにする。
- 空間に入った状態のダブルクリックは、自分で `dblclick` を渡さないとパネルに届かない。リソースのスクリプトはこれで開く。1 回目のクリックで別のパネルが開くと、2 回目の照準がそちらに乗る。視点が動いていなければ、最初のパネルへ届ける。同じパネルの中のクリックは、いま照準がある場所へ届ける。

## スクリプト（QuickJS）

- QuickJS のハンドルは必ず dispose する。dispose 済みのハンドルに触ると落ちる（`alive` を確かめる）。
- QuickJS のメモリ上限は配列などの確保では効かないことがある。WASM のヒープを見て、超えたらサンドボックスを `broken` にする（ADR 0001）。
- 初回の読み込みは VM の準備で遅いので、実行用とは別に読み込み用の時間制限（既定 1 秒）がある。
- エラーの行番号はスタックの `<領域>/<System ID>.js:<行>` から取る（`lineInStack`）。
- 1 ステップの重さの大半はEntity の値を JSON にして VM に渡す部分。計測は `pnpm bench:sim`。

### 利用者のスクリプトの TypeScript（ADR 0058）

- 利用者のスクリプトの型を確かめる TypeScript は 6.0 系で、リポジトリの開発に使う TypeScript 7（Go の版。ブラウザで動かない）とは別に入れている。同じ名前の `typescript` では二つの版を一つの package.json に書けないので、`typescript6`（`npm:typescript@6.0.3`）という名前で入れ、`import ts from "typescript6"` で読む。
- 日本語の型エラーの文は、TypeScript の公開の型に無い `setLocalizedDiagnosticMessages` で差し替えている。版を上げるときは、この関数が残っているかを `packages/typecheck` のテスト（文が日本語になるか）で確かめる。
- 型を消すのは sucrase。型を消しても行の数は変わらないが、行の中の位置はずれる。import のパスの範囲は `rangeInSource()` で元のコードの範囲に戻してから書き換える。
- ブラウザでは型を確かめる処理を Worker（`typecheck.worker.ts`）に入れ、TypeScript の本体（約 4.7 MB）を画面の本体に入れない。ワークスペースの準備が終わる前に制作データを書き換えても、型の確かめは走らない（確かめ用のスクリプトでは少し待ってから書き換える）。
- 開発サーバー（Vite）は、Worker で初めて読む `typescript6` をその場で取り込み直し、ページを読み込み直してしまう（背骨の E2E の m1 が途中で落ちた）。`apps/client/vite.config.ts` の `optimizeDeps.include` に入れて、起動時に取り込んでおく。

## 物理（Rapier）

- Collider は物理を 1 回進めるまでレイキャストに当たらない。そのため各ステップでは物理を先に進めてから、入力とスクリプトを処理する。プレイヤー側の当たり判定も、形を反映したあとに一度 `step` してから移動を問い合わせる（ADR 0068）。
- 高さ 0 の地面は Entity ではない。`world.raycast` と onCollision には出てこない。剛体用は原点を中心におよそ ±200m（それより大きい一枚の板は、Rapier で足元が沈む）。プレイヤー用は、いる場所へ板を追従させる。平面の Collider は上面を見た目に合わせ、下へ 20cm の厚みがある。
- プレイヤーの移動は各クライアントが決める。ホストの剛体は、プレイヤーに押されて動かない。

## サーバー・ビルド・デプロイ

| 症状 | 原因 | 対策 |
| --- | --- | --- |
| 本番で `Cannot find package 'zod'` | バンドルの外に出した依存が、本番の node_modules に入っていない | サーバーが使うものは `apps/server/package.json` の dependencies に書く（`build.mjs` はそれだけを外部扱いにする） |
| Docker ビルドで pnpm install が失敗する | 新しいパッケージの package.json を COPY していない | Dockerfile に COPY を足す（`pnpm lint` が検査する） |
| `CLIENT_DIR` を相対パスで渡すと起動しない | @fastify/static は絶対パスしか受け付けない | `config.ts` で絶対パスに直すようにした |
| Coolify でイメージを取得できない | MinIO の公式イメージの配布が止まった・Docker Hub の取得制限 | 本番の compose には S3 互換ストレージを含めない（外部を使う）。ベースイメージは `NODE_IMAGE` で差し替えられる |
| Windows で開発サーバーが白い画面になり、`DiffTree` が export されていないと出た（型・ビルドも同じ） | `DiffTree.tsx` と `diffTree.ts` が大文字・小文字だけ違った。大文字・小文字を区別しないファイルシステムでは、`./DiffTree` が `.ts` の方に当たる | 片方を `diffTreeModel.ts` にした。同じフォルダに、大文字・小文字だけ違う名前のファイルを作らない（Linux の CI では気付けない） |
| クラウドの開発環境で Docker ビルドが TLS で失敗する | 外向きの通信が、独自 CA のプロキシを通る | 一時的な Dockerfile で CA（`/root/.ccr/ca-bundle.crt`）を入れて確かめる。リポジトリには入れない |

### AI エージェント（リモートの MCP）

- 開発サーバーでは `http://localhost:8787/mcp`。Claude Code なら `claude mcp add --transport http tukurium http://localhost:8787/mcp`。
- エージェントは、人がいるセッションに入って作る。先にブラウザでセッションとワークスペースを作り、セッションの ID（URL の `/s/` のあと）をエージェントに伝える。
- MCP のセッションは、サーバーを再起動すると消える。クライアントからつなぎ直す。
- サーバーの中で Simulation を動かすので、runtime が使う npm パッケージ（rapier・quickjs・three）は `apps/server/package.json` にも書く（バンドルでは外部扱いになる）。

## React・UI

- メインメニューのキー入力は、中身だけでなくタイトルバーも含むウィンドウ全体で止める。閉じるボタンにフォーカスした状態のTabも、制作側の「パネルを隠す」へ流さない（`PanelSpec.containKeys`）。
- 狭い画面でナビゲーションを横並びにするときは、補助メニューも横並びにする。補助メニューだけ縦のままだと、その高さに引かれて横のタブが画面を占有する。

- 入れ子のドロップ先（フォルダのタイルと、その外側の中身の欄）では、`dragover` と `drop` で `stopPropagation()` する。しないと、外側が受け取り直して元に戻る。
- パネルが重なると、後から触ったパネルが前に出る。コードを開いたときなどは `PanelSpec.focusKey` を変えて前に出す。

- フックを早期 return の後で呼ぶと、表示が切り替わったときに落ちる。Biome の `useHookAtTopLevel` で検出する。
- パネルを重ねたとき、触ったパネルを前に出す（pointerdown で z-index を上げる）。
- Inspector のメニューを階層の中に absolute で置くと、スクロール枠と右の詳細で切れる。`document.body` へ出して fixed で、詳細の上に重ねる。
- 履歴と保存の差分は、ファイルの行数ではなく制作データ同士を名前で比べる（ADR 0041）。記録を開いたときは、その記録と親の記録の snapshot を取る。モデルとマテリアルの見た目は、開いているあいだだけ描く（詳細パネルも同じ `AssetPreview`）。

## GitHub・CI

- WindowsでDockerの起動やビルドと同時に単体テストを大量実行すると、Gitを使う既存テストも5秒で時間切れになった。`pnpm exec vitest run --maxWorkers=4`で同じ全件を実行すると通った。タイムアウトを延ばす前に、同時実行数と負荷を確認する。
- PostgreSQLのJSONBフィールドへ動的な文字列を入れるとき、`JSON.stringify(value)`をJSONBパラメータとして渡すと二重に引用された文字列になる場合がある。招待の状態更新では`to_jsonb(value::text)`を使い、実際のPostgreSQLで読み戻して検査した。

- `.github/workflows/ci.yml` で、lint・型・単体テスト・ビルド（`check`）と E2E を流す。合否は `check` で決め、E2E は落ちてもマージを止めない（`continue-on-error`）。
- E2E はプロトタイプの間、背骨の 4 本だけにした。細かい E2E は画面を作り替えるたびに直す手間と、CI の遅い描画に合わせる手間が大きかった（CLAUDE.md「テストの方針」）。
