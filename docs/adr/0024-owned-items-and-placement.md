# ADR 0024：入手した版を所持し、取り出しの結果を要求に対応させる

- 状態: 採用・基盤実装済み（2026-11-05、A3）
- 関連: [ADR 0022](0022-main-menu-first-release.md)

## 所持と検索

所持一覧は利用者と作品の組で一件とし、入手時のリリースIDと時刻を保存する。同じ作品の再入手で版を上書きしない。MemoryStoreとPostgreSQLで同じ操作を用意し、同時の入手も一件にまとめる。

`GET /api/market` は既存の作品を検索する。初期範囲はアイテム、名前・作者、新着順、最大48件ずつのページ送り。作品の利用・閲覧・フォークのいずれかが公開されているものと、本人の作品を対象にする。公開作品と所持品の情報を別の台帳に複製しない。

本人の所持一覧は `GET /api/me/items`、入手は `POST /api/me/items/:workId`。本人は接続トークンから判断する。指定したリリースがその作品に属するアイテムで、利用できる場合だけ保存する。利用権限が失われた所持品は一覧に残し、利用できない理由を表示する。

## 取り出し

`placeRelease` に要求IDと対象セッションIDを合わせて指定する。サーバーは `placement.result` で、その要求の配置IDまたは失敗理由を返す。読み込みを待った後も参加先と利用権限を確認する。

同じ利用者・セッション・要求IDの再送は同じ結果を返す。別のタブから同時に送っても一度だけ配置する。同じIDで内容を変えた要求は拒む。結果は5分間、セッションごとに最大512件まで保持し、処理中の要求は追い出さない。クライアントの再試行は同じ要求IDを使う。

従来のライブラリパネルからの配置は引き続き使える。所持は整理のための一覧であり、作品の利用許可を追加するものではない。

## 確認

PostgreSQL 17とメモリ保存で同時入手・版の固定・本人の一覧を確認し、PostgreSQLは接続し直した後の保持も確認した。APIでは検索、ページ送り、別作品のリリースやワールドの入手拒否、権限変更を検査した。通信では同じ人の別タブと再送の重複、異なる内容、移動先の不一致、利用権限の取り消しを検査した。

全体の単体テストは同時実行数4で329件成功、既存の1件はスキップ。lint・型検査・ビルドが成功し、本番ビルドとPostgreSQLでセッション作成・ワークスペース作成・再生までのスモークテストも通った。

## A4の画面

マーケットと所持一覧は同じ作品情報を使う。入手後は所持済みに切り替わり、未参加ならセッション選択へ進む。参加しただけでは配置せず、本人が「取り出す」を押す。

結果が受け取れなかった場合は、次の配置をすぐ送らず「結果を確認」で同じ要求を再送する。確認期限は4分で、サーバーの保持期間より短くする。古い検索応答と異なる利用者向けの所持応答は捨てる。表示状態はメニュー側、取得データと操作結果は専用storeで管理する。
