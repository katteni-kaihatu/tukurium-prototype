# ADR 0008：権限・プライベートな作業・ワールドの編集

- 状態：採用（M5）
- 関連：要件 §6「ワールドの編集」、§8「権限・プライベートな作業」、§10 シナリオ 9・12、ADR 0004・0005・0006

## 背景

M2 までで、ワークスペースの中身（Y.Doc）とパネルの要約は、閲覧権限のある人にだけ届くようになった。
M5 では残りの経路（ワークスペースを開いていない人から見える編集中の物、独立した空間、ポータル、素材の取得）にも同じ権限をかける。
あわせて、ワールドの編集の進め方を決める。ワールドはセッションと同じ大きさになりうるので、セッションの中では編集できない。

## 決定

### 1. 編集中の見た目は、ホストが送ってサーバーが見せ分ける（`ws.preview`）

- ワークスペースのホスト（管理権限を持つ接続。ADR 0005）が、Edit の World のスナップショット、マテリアル、境界ボックス、置き場所を `ws.preview` で送る。送るのは制作データが変わったときだけで、0.4 秒以上あける。
- サーバーはワークスペースごとに最新の 1 件を持ち、そのワークスペースを開いていないセッション参加者へ配る。セッションに入ったとき・ワークスペースを閉じたとき・権限が変わったときにも送り直す。
- 閲覧できない人に届くのは `restricted: true` と境界ボックスと置き場所だけで、名前は「作業中」、`world` は null、`materials` は空になる。中身はサーバーの外へ出ない。
- ホスト以外の接続が送った見た目は捨てる。

サーバーで Y.Doc から World を組み立てる方法も考えた。ただし、組み立てにはランタイム（Rapier・QuickJS は不要だが EKS とビルド処理）が要る。ホストは M2 から実行を担っているので、ホストに任せた。

### 2. 置き場所（anchor）

| 対象 | 置き場所 |
| --- | --- |
| アイテムの編集（公開） | セッションの中。n 番目のワークスペースを x = 12n に置く（ほかの人から作業が見える） |
| 非公開のワークスペース（初期値の権限が null） | 独立した空間 x = 500 + 60n |
| ワールドの編集 | 独立した空間 x = −500 − 60n。セッションの区画（x = 12n, z = −3）にポータルを置く |

- 独立した空間に切り替わったら（ワールドのアウトプットを選ぶ、非公開にする）自動で移動し、終わったらセッションへ戻す。パネルの「編集空間へ」「セッションに戻る」でも移動できる。
- ポータルは、そのワークスペースを閲覧できる人にだけ出る。閲覧できる人は、開いていなくても中へ入って編集中のワールドを見られる。閲覧できない人には区画に「作業中」の境界だけが出て、ポータルはない（シナリオ 9）。
- 位置で分けているだけなので、独立した空間の中も物理的には同じ 3D 空間になる。閲覧できない人には中身が届かないため、移動しても何も見えない。

### 3. 非公開の作業はセッションに出せない

非公開のワークスペースからの「セッションに出す」と「適用」はサーバーで断る。非公開の作業の表示と実行は、独立した空間の中でワークスペースの再生として行う。セッションに出すには、公開（閲覧か共同編集）に切り替える。

### 4. ワールドの出力

ワールドのアウトプットは、セッションに出すとセッションの原点に、向き 0 で置く。適用・状態維持・リセットはアイテムと同じ仕組み（ADR 0006）を使う。

### 5. 素材の取得にも権限

`GET /api/assets/:id` は、本人確認（クエリ `?t=トークン` かヘッダー `x-tukurium-token`）をしたうえで、次のどれかに当たるときだけ返す。当たらなければ 404 を返し、素材があるかどうかも明かさない。

1. 自分が上げた素材（記録はメモリにあり、再起動で消える）
2. 参加中のセッションに置かれた物（作品のリリースを含む）が使っている
3. 閲覧できるワークスペースの制作データが使っている
4. 閲覧できるリポジトリの最新コミットが使っている。重い判定なので、通った組を 60 秒覚えておく

`<img>`・`TextureLoader`・`GLTFLoader` はヘッダーを付けられないため、クエリでトークンを渡す。キャッシュは `private` にして、共有キャッシュに残らないようにする。

## 影響・残課題

- 4 は、リポジトリの数に比例して重くなる。素材 → リポジトリの索引は、利用者が増えたら作る。
- トークンが URL に乗るので、アクセスログに残る。本番ではプロキシのログ設定に注意する。短命の署名付き URL に替えるのは今後の課題。
- 独立した空間は位置で分けているだけで、空間そのものを分けてはいない。参加者の位置（アバター）は全員に見える。
