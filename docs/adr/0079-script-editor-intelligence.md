# 0079: 型と説明をスクリプトのエディタに出す

- 状態: 採用・実装済み
- 日付: 2026-11-14

## 背景

スクリプトの型の確認は Worker の TypeScript Language Service で行っているが、入力候補は型を使わずに作っていた。コードを書いている場所で型と作者の説明を読めるようにし、定義も開けるようにする。

## 決定

- `TypeChecker` にホバー、入力候補、候補の詳しい説明、定義の場所を問い合わせる処理を置く。画面は文字列と位置だけを受け取り、TypeScript の本体は Worker に置く。
- Worker は型の確認とエディタの問い合わせを共用する。型の確認は System 一つごとにイベントループへ戻り、その間に届いた問い合わせを先に処理する。最初の制作データの読み込みと、各 System の TypeScript 処理の途中には割り込まない。新しい確認が来たら古い確認を打ち切る。
- 問い合わせにはファイルの ID、現在の本文、UTF-16 の文字位置、版を送る。Worker は該当ファイルの本文だけを差し替えて答え、版を返す。ほかのファイルや定義が変わった場合は、先に制作データを読み直す。
- 画面は問い合わせ時の本文、制作データの版、プロジェクトが変わった応答を捨てる。共同編集やワークスペースの終了にも同じ判定を使い、すでに出したホバーと候補も変更時に閉じる。
- CodeMirror のホバーに型、JSDoc、その位置の型エラーをまとめて出す。読み込み中は「読み込み中…」を出す。説明は HTML として解釈しない。
- Host API の自前の候補をやめ、TypeScript の候補を使う。選んだ候補の詳しい説明だけを後から問い合わせる。import のパス文字列の中では既存のパス候補を使い、両方を重ねない。
- 定義へはホバーのボタンか Ctrl＋クリックで移る。Mac では Cmd＋クリックを使う。F12 は使わない。KokoState はリソースの詳細、スクリプトと型の定義はコード内の位置を開く。Built-in とライブラリの KokoState は閲覧専用とし、ライブラリの型の定義も閲覧専用のエディタで開く。Host API と標準ライブラリの宣言には移動しない。
- KokoState とフィールドに省略可能な `description` を持たせる。各説明は対応する Y.Map のキーとして保存し、説明の変更だけで初期値や実行中の値を変えない。ライブラリにも同じ保存形式で含める。既存のエージェント操作でも説明を作成・更新できる。
- 宣言を作るときに説明を JSDoc にし、`*/` を無害な文字列に置き換える。`FieldsOf<K>` で取り出したフィールドにも JSDoc が残るため、型の取り出し方は変えない。
- 3D パネルではエディタ本体、スクロール枠、ツールチップを同じ原点で測る。クリック以外のマウス移動も文字の座標へ変換し、Firefox の `caretPositionFromPoint` にも対応する。

## 確認

型と説明の取得、定義の移動先、別ファイルの同名の定義、一ファイルの差し替え、Worker の処理順、古い応答の破棄、説明の保存と共同編集を単体テストで確認する。画面では 2D と 3D のホバー・候補選択・定義移動を確認する。Safari 実機の確認は Windows ではできないため、PR に未確認事項として残す。
