# ADR 0005：セッション・本人識別・ワークスペースのホスト（M2）

- 状態：採用（2026-11-02）。「本人識別」は [ADR 0074](0074-misskey-login-accounts.md)（Misskey でログイン）で置き換えた
- 関連：計画 §2 決定事項、ADR 0002（引き継ぎ用スナップショット）、ADR 0004（権限付き同期）

## 本人識別
- 最初の接続で、表示名に対してランダムなトークンを発行する。ブラウザに保存し、再接続時に送って同じ人として扱う。
- サーバーにはトークンの SHA-256 だけを保存する。パスワードやアカウント登録はない（試験用の最小限の識別）。

## セッション
- セッションは **開いた人（持ち主）の持ち物**。持ち主が「閉じる」か、すべての接続が切れてから 30 秒たつと閉じる（猶予中に戻れば続く）。
- 閉じたセッションは残さない。中のワークスペースは保存してから読み込みを外す（M4 でリポジトリから開き直せるようにする）。
- URL は `/s/<セッションID>`。ホームに開いているセッションの一覧を出す。

## ワークスペース
- セッションの中で作る（空・サンプル）。作った人が管理者。参加者の初期の権限は管理者が設定でき、既定は「共同編集」。「非公開」にすると、招待した人（権限を明示した人）以外は開けない。
- 中身は Y.Doc をサーバー経由で同期し（ADR 0004）、更新があれば 1 秒ごとに保存する（PostgreSQL、`DATABASE_URL` がなければメモリ）。
- 再接続したときは、サーバーの全体を受け取ったあと、サーバーにない手元の変更（切れている間の編集）を差分で送り返す（閲覧者は送らない）。
- カーソル・選択（Yjs の awareness）は、閲覧権限のある人にだけ中継する。

## ワークスペースのホストと共有の再生
- ホストは、ワークスペースを開いている **管理者の接続** の中から選ぶ（最初は作った人）。再生（Simulation）はホストだけが実行する。
- 再生の操作（Play / Pause / Resume / Stop）は、ホスト自身の操作も含めてサーバー経由でホストに届ける。共同編集以上の権限が必要。
- 入力（fire など）は閲覧以上の権限で送れ、ホストに中継する。
- ホストは 1/15 秒ごとに実行状態（EKS のスナップショット、名前、System の状態）を配る。サーバーは最後の状態を覚えておく。
- ホストが抜けたら、ワークスペースを開いている別の管理者に引き継ぐ。新しいホストは最後の状態から再開する（物理は EKS の値から作り直す：ADR 0002 の代替案を採用。Rapier のスナップショットは送っていない）。管理者がいなければ再生を止める。

## 他の人から見えるパネル
- 各自が開いているパネルの公開用情報（タイトル、2D/3D、大きさ（px）、3D なら位置、2D なら画面の中の位置と画面の大きさ、数行の要約）を送る。サーバーは受け手の閲覧権限を確かめ、権限がなければ「作業中」とだけ伝える（内容は送らない）。
- 大きさは持ち主の画面の px を、自分のパネルを空間に置くときと同じ 1px = 2.5mm で空間の大きさにする。
- 2D 表示のパネルは、持ち主の視界の中で、持ち主の画面と同じ所・同じ見かけの大きさに置き、持ち主の向き・見上げについていく（カメラの画角と目の高さは全員同じとみなす）。画面の位置が届かないときは、持ち主の前に横に並べる。入力途中の文字やスクロール位置は共有しない（要件 §6 の未決定事項。初版は要約のみ）。

## 制約・残課題
- ホストが送る実行状態は検証せずに中継している（ホストは管理者なので信頼する前提）。
- メッセージの頻度・大きさの制限は WebSocket の受信サイズ（8MB）だけ。
- ORM（Drizzle）は使わず、`postgres` パッケージで直接 SQL を書いている（テーブルが 2 つだけのため）。
