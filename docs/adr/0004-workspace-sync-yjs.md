# ADR 0004：ワークスペースの共同編集を Yjs で、権限付きで同期する

- 状態：採用（2026-11-02）
- 関連：要件 §6・§8、計画 §2「ワークスペースの権限」

## 決めたこと

- ワークスペースの制作データ（編集中）は、**ワークスペースごとに 1 つの Y.Doc** に入れる。
- サーバーの `DocRoom`（`apps/server/src/workspaces/docRoom.ts`）が Y.Doc を持ち、接続ごとに権限を確かめて同期する。
  - **閲覧**以上：内容を受け取れる。権限がなければ **ドキュメントごと送らない**（参加自体を断る）。
  - **共同編集**以上：更新を送れる。閲覧者からの更新はサーバーで捨て、他の人に届かない。
  - 権限は毎回 `roleOf` で確かめる。権限を外したら `revalidate()` で接続を外し、以後の更新は届かない。
- 同期はシンプルな方式：参加時に全体（`encodeStateAsUpdate`）を送り、以後は更新を中継する。差分同期（state vector の交換）は再接続の効率化が必要になったら入れる。
- プレゼンス（カーソル・選択）は Yjs の awareness ではなく、権限チェックを通した独自メッセージで送る（awareness は誰にでも配られやすいため）。

## 検証（`docRoom.test.ts`）
- 管理者と共同編集者の変更が互いに届く。
- 閲覧者は受け取れるが、書き込みは反映されない。
- 権限のない人には何も届かない。
- 権限を外すと、それ以降の更新は届かない。
- 途中参加でもそれまでの内容を受け取れる。

## 注意
- 閲覧者の手元の Y.Doc は、書き込みが捨てられるとサーバーとずれる。クライアントは閲覧者の編集 UI を読み取り専用にし、ずれた場合は再参加で取り直す。
- 権限の初期値はホスト（ワークスペースの管理者）が設定でき、既定は「共同編集」（計画 §2）。
