# ADR 0006：セッションの世界・適用・状態維持・素材（M3）

- 状態：採用（2026-11-02）
- 関連：要件 §5・§7、計画 §4「適用（Apply）の流れ」、ADR 0005

## セッションの世界（配置された実体）
- ワークスペースの「セッションに出す」で、アウトプットの制作データ（スナップショット）をセッションに配置する。配置は複数でき、同じアウトプットを何度でも置ける。
- セッションの世界は **持ち主（セッションのホスト）の画面** で実行し、1/15 秒ごとに状態を配る。ほかの人は届いた状態を表示し、入力をホストへ送る。持ち主がいない間は止まり、戻ると最後の状態から続く（持ち主が戻らなければセッションごと閉じる：ADR 0005）。
- サーバーは配置の台帳と、ワークスペース・アウトプットごとに最後に出した（適用した）制作データを持つ。新しいホストには、すべての配置と最後の状態を渡す。

## 複数のリポジトリを 1 つの世界に
- `Simulation` を「配置（パート）」単位にした。セッションでは
  - Entity の ID を「配置ID/EntityID」
  - KokoState とマテリアルの ID を「リポジトリ:ID」
  に付け替える。KokoState の名前はリポジトリごとのスコープで引く（別のリポジトリに同じ名前の KokoState があってよい）。
- 物理・レイキャスト・イベントは共通なので、リポジトリ A の銃で、リポジトリ B の的を撃てる（`world.emit` で B の System に届く）。
- 同じアウトプットを複数配置しても、System は 1 回ずつ（すべての配置の Entity をまとめて）動く。
- ワークスペースの再生は 1 パートで、ID を付け替えない（M1 と同じ）。

## 適用と状態維持
- 「適用」は、そのワークスペース・アウトプットにリンクしているすべての配置を、いまの制作データで作り直す（個別の配置だけの更新はしない：要件 §7）。
- 状態維持のマークは **アウトプットごと・フィールド単位**（`{entity, koko, field}`）。適用のとき、マークがあり、古い定義と新しい定義で **型が同じ** フィールドだけ、現在の実行値を引き継ぐ。それ以外は新しい制作データの値になる。
- フィールドは ID で照合するので、名前を変えても引き継げる。型が変わったら初期値に戻し、件数をログに出す。
- System のコードも読み直す。適用した人と結果（更新した配置の数、引き継いだ数、初期値に戻した数）をセッションのログに出す。
- 「リセット」は、配置をいまの制作データの初期値で作り直す（実行値は引き継がない）。
- ワークスペースの再生・一時停止はセッションの世界と独立している（セッションの世界は止まらない）。

## 入力の行き先
- ワークスペースを再生中なら、ワークスペースへ。
- そうでなければ、ワークスペースを閉じているか、パネルを隠している（Tab）ときにセッションの世界へ。ワークスペースを編集中のクリックは「選ぶ」。

## 素材（GLB・画像・音声）
- `POST /api/assets` で受け取り、中身の SHA-256 を ID にして保存する。S3 互換ストレージ（`S3_ENDPOINT`）があればそこ、なければディスク（`ASSET_DIR`）。種類は GLB・PNG・JPEG・WebP・MP3・OGG・WAV、1 ファイル 20MB まで（仮置き）。アップロードには本人確認（トークン）が要る。
- 制作データには素材の ID・名前・種類だけを入れる。`Mesh.model`（GLB。当たり判定は size のまま）、マテリアルの「画像」、Built-in の `AudioSource`。
- スクリプトの `audio.play(名前|ID, entity?, volume?)` で鳴らす。ホストが手元で鳴らし、状態と一緒に配って、ほかの人も同じ位置で鳴らす。

## 制約・残課題
- 素材の取得（GET）は、ID（ハッシュ）を知っていれば誰でもできる。権限による取得の制限は M5。
- 適用に失敗した配置（スクリプトの読み込みエラー等）は、新しい制作データで作り直したうえで、その System だけ止まる（旧版には戻さない）。
- 状態維持の互換性は「型が同じ」だけ。数値の範囲などは見ない。
- 適用のときに、実行中に `world.spawn` で増えた Entity は残る（配置の Entity だけ作り直す）。
