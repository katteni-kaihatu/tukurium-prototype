# 0080: ワークスペースのデバッグ実行

日付: 2026-11-14

## 判断

通常再生は同期版 QuickJS を使う。デバッグ実行を始めたときだけ非同期版を読み込み、文の前に加えたフックで待つ。書き換えは型と import の処理後に行い、改行数を保つ。関数ごとに変数を読む関数を持ち、停止する直前に外側の呼び出しも含めて値を写す。変数の変更は待機の返り値として渡し、再開直後にスクリプト内で行う。

通常の `step()` は変えず、デバッグ用には待てる `stepDebug()` を用意する。物理、衝突、入力、更新、イベントの順序をそろえる。ステップ実行は同じフレームの次の停止位置へ進み、なければ次のフレームへ進む。

設定はワークスペースごとの別の Y.Doc で共有し、サーバーのメモリだけに置く。制作データの Y.Doc とは分け、保存・履歴・リリースへ入れない。停止位置は制作データの Y.Text に対する相対位置で持つ。

停止中は位置、呼び出し、変数、Entity、フレーム途中の世界を配る。操作は共同編集以上の権限でホストへ送る。ホストが抜けたらフレーム開始時の世界から停止状態で引き継ぐ。

## 値の表示と実行の整合

停止画面には、実行中のスクリプトが持つ途中の値を一時的に反映する。続行前には実際の世界へ戻す。これにより、まだ返していない `e.get()` の変更を `world.get()` が先に読むことを防ぐ。利用者が停止中に変更した値だけを再適用する。変数の束縛は関数の呼び出し・ブロック・ループの周回を区別する。

フィールドの監視は代入・削除・呼び出しの直後に確認する。`e.get()` が持つ値の変化と Host API による世界の変化は別に記録し、表示のための反映で変更を消さない。型に合わず取り込めない値は監視の変化に数えない。物理と組み込みの入力処理は、処理直後に変更元を添えて確認する。

式は AST で読み取りと計算だけを許し、採取した値の写しで評価する。元のオブジェクトの getter・Proxy・関数を式から実行しない。オブジェクトの同一性は写しでは保てないため、オブジェクト同士の比較は明示的に断る。条件・ログ・監視の変更はフレームの先頭で取り直す。

例外は利用者の catch や finally に届く前にも捕捉する。伝播している同じ例外では重複停止せず、新しい throw は別の発生として扱う。例外オブジェクトの表示に `toString()` や getter を使うと発生時の値を変えるため、停止中は一般文言を出し、詳しい内容は続行後の既存のエラー欄に残す。

## ホストの交代

フレーム開始時に世界・名前・時刻・バッグ・配置の Entity・入力・待機中のイベント・System の有効状態を写す。停止状態と一緒に配り、新しいホストはこの状態を復元して止まる。途中の値を含む画面の世界から再実行しない。

QuickJS の呼び出し途中やモジュール変数は移せないため、スクリプトは読み込み直す。再実行した部分のログ・音・効果がもう一度出ることはある。これはフレーム開始時からやり直す方式の制限とする。

## 対応範囲

通常再生の構文は変えない。デバッグ実行では async 関数と generator を断る。矢印関数の既定引数内に関数があり、同じ矢印関数に rest 引数もある構文も、束縛を正しく区別できないため理由付きで断る。通常の function へ書き換えると利用できる。

## 比べた案

Worker と Atomics.wait は採らない。SharedArrayBuffer のために COOP・COEP の配信設定を変える必要があり、素材と埋め込みへの影響が大きい。非同期版ではページの配信条件を変えずに待てる。

## D0 の検証

非同期 QuickJS のホスト関数で待ち、待機前に外側と内側の値を受け取り、返した値で変数を変更して続行できた。自動テストで確認する。WASM の非圧縮サイズは同期版 503,134 bytes、非同期版 1,027,523 bytes。非同期版はデバッグ時だけ読み込む。

通常再生の変更前の計測（この開発環境、`pnpm bench:sim`）では、スクリプトありの 1 フレームが Entity 0/50/100/200/500 個で 0.27/2.23/6.89/12.90/28.37 ms。環境と計測ごとに値は変わる。実装後にも同じ計測を行う。

D8 の同じ計測では 0.24/2.33/5.12/12.36/28.76 ms。500 個で約 1.4% の差であり、この環境では通常再生の目立った低下は見られなかった。非同期版を読み込まないことは別のテストでも確認する。

`pnpm --filter @tukurium/runtime exec tsx bench/debug-vm.ts` の参考計測は同期版 0.066 ms、非同期版と 50 回のフック 0.893 ms（各 200 回、停止待ちは含まない）。同期側は Entity の受け渡し、非同期側はコードの評価を含むため、この比を製品の性能差とはみなさない。
