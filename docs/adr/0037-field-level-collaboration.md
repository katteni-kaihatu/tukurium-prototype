# ADR 0037：Entityの値をフィールド単位で同期する

- 状態: 採用・実装済み
- 関連: [Issue #61](https://github.com/katteni-kaihatu/tukurium-prototype/issues/61)

## 理由

同じKokoStateの別フィールドを二人が同時に変えると、値のオブジェクト全体が競合し、一方の編集が失われていた。実際のProjectDocとY.Doc二つの更新交換で再現した。

## 決定

保存済みのEntityと状態の形式は維持し、フィールドの変更をトップレベルの共有Mapへ記録する。キーはEntity・KokoState・フィールドの組み合わせとし、別フィールドは独立して同期する。同じフィールドの競合はYjsの選択に従う。

共有Mapをトップレベルに置くことで、旧形式のデータを開いた二人が初めて同時編集しても、入れ子のMapをそれぞれ作って競合させずに済む。読み出しとSnapshot化では、元の値にフィールドの変更を重ねる。Snapshotとファイルの形式は変えない。

状態やEntityの削除、定義の削除・型変更、全体の読み込みでは対応する変更記録も片付ける。素材やマテリアルを削除するときも、編集後の参照を対象にする。

旧クライアントは新しい共有Mapを読めないため、混在を防ぐために通信プロトコルを5へ上げる。保存済みのY.Docは引き続き読み込める。
