# ADR 0003：パネルの 2D／3D 表示

- 状態：採用（2026-11-02）
- 関連：要件 §6「2D／3D パネル」、計画 §3「3D パネルの表示方式」

## 決めたこと

### 自分のパネル
- パネルの中身は React のポータルで **1 つの DOM 要素** に描く。ピン操作で、その要素を「画面の層（2D）」と「空間（3D）」の間で移す。要素を作り直さないので、入力中の文字・スクロール位置・React の状態が保たれる。
- 3D 表示は `CSS3DRenderer` で実 DOM を空間に置く。そのまま操作できる（入力欄への入力、スライダー、チェックボックスを確認）。
- **前後関係**：CSS の層を WebGL キャンバスの **後ろ** に置き、パネルの位置に WebGL で「穴あけ用の板」（`NoBlending` で透明を書き込む）を描く。手前の物体は穴の上に描かれ、奥の物体は深度テストで隠れる。そのため WebGL は透明（`alpha: true`）にし、空はコンテナの CSS 背景で描く。
- キャンバスと CSS の層は `pointer-events: none`。パネルだけがクリックを受け取り、何もない所のクリックはコンテナに届いて空間に入る（ポインターロック）。
- 大きさは 1px = 2.5mm（幅 340px のパネルが 0.85m）。3D に切り替えると、自分の前 1.4m・目の高さより少し下に、こちらを向けて置く。

### 他の参加者のパネル
- サーバーから届く **公開用の要約**（タイトル、持ち主、閲覧権限があれば数行の簡易表示）を Canvas 2D で描いたテクスチャの板（`RemotePanelMesh`）で表示する。
- 閲覧権限がない場合は「作業中」と伏せた表示だけを描く。内容はクライアントに届かないので、ここから漏れることはない（要件 §6「非公開内容が他人向けのパネル表示から漏れない」）。

## 検証（Playwright、`apps/client`）
- 2D で入力 → 3D に切り替え → 空間のパネルの入力欄をクリックして入力 → 2D に戻す、の間ずっと値が保たれる。
- パネルと自分の間に置いた物体がパネルを隠す。下がって見ると、パネルの奥の物体はパネルに隠れる。

## 制約・残課題
- `backdrop-filter`（すりガラス）は 3D では効かないので、3D のパネルは不透明にしている。
- 3D のパネルは真正面以外から見ると文字がぼやける（CSS の変形の性質）。初版は許容。
- ポインターロック中（FPS 操作中）はパネルを操作できない。Esc で解放してから操作する。将来、レイキャストでパネル上の位置を求めて疑似的にクリックする方式も考えられる（VR 対応時に必要）。
- 3D パネルを掴んで動かす操作は未実装（M2 で追加）。

## 追記（使ってみて出た指摘への対応）

3D にしたパネルが高い確率で操作できなくなった。原因は次の 2 つ。

- どのパネルも正面の同じ位置に置いていたため、重なった後ろのパネルがクリックを受け取れなかった。
- カメラの後ろや裏側にあるパネルが、クリックを奪うことがあった。

対策として、パネルは画面上でいまある位置に、同じ大きさに見える奥行きで置く。カメラの後ろや裏側にあるパネルは隠す。さらに、画面左下に「空間のパネル」の一覧（画面に戻す）を逃げ道として出す。詳しくは docs/DEVELOPMENT.md。
