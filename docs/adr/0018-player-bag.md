# ADR 0018：プレイヤーが持ち歩くバッグ（持ち物）

- 状態：採用（2026-11-04）
- 関連：ADR 0012（権限・境界）、ADR 0015（ライブラリ）、ADR 0016（公式ライブラリ・Interact）
- 詳細計画：ロードマップの「別々の作品を中身を壊さず組み合わせて部品として使う」の U4（収集物と Inventory）

## 背景

U4 の reference UGC の三本目は「収集物と Inventory」。使い道は二つある。

- **その場所の中で集めて数える**（スコア・スタンプ）：一つの配置の中で閉じているので、今の Host API で UGC か公式ライブラリとして作れる。
- **プレイヤーが持ち歩く持ち物（バッグ）**：別の作者の作品をまたいで持ち運ぶ（A さんの作品で拾った鍵で、B さんの作品の扉を開ける）。「だれのバッグか」「他人の作品が中を見たり取り出したりしてよいか」を Host が判定しないといけないので、ライブラリでは守れない。

利用者と話して、U4 の三本目は後者（持ち歩くバッグ）とし、Platform 側（Host が持つ仕組みと Host Capability）として作ることにした。前者は必要になったら UGC・公式ライブラリで別に作る。

## 決定（利用者と決めたこと）

1. **持ち物の種類は、ライブラリで公開した KokoState**。ID は Package と版で決まる（ADR 0015 の `pkg:<Package ID>@<版>/<元の ID>`）ので、同じライブラリの同じ版を使う作品どうしだけが「同じ鍵」だと分かる。名前が同じだけの別物とは混ざらず、自分のプロジェクトの KokoState（作者ごとに区切られる）は持ち物の種類にできない。
2. **他人の作品の System がバッグに触れるのは、その人が E で押したときだけ**。プレイヤーがその物を E で押した Interact（ADR 0016）を受けている間だけ、押した人のバッグに、その System が import している種類についてだけ、入れる・数える・取り出すができる。押していない人のバッグ、import していない種類は見えない。
3. **中身は 1 個ずつ値を持つ**。中身は「種類（KokoState）＋その値」の並び（例：どの扉の鍵か）。値が同じでも 1 個ずつ数える。一つのバッグに入るのは 64 個まで。
4. **バッグはセッションが続く間だけ残る**。一度抜けても、同じセッションに戻れば中身は残っている。ホストが替わっても引き継ぐ。セッションが終わると消える（保存しない）。
5. **自分のバッグは画面の「バッグ」パネルで見る**（種類の名前・どのライブラリのものか・値）。見えるのは自分のバッグだけ。捨てる・渡すはまだ作らない。

## 決めるまでもなく入れること

- **入力のプレイヤー ID は、サーバーが接続の本人で上書きする**。今まではクライアントの自己申告をそのままホストへ渡していた（`session.input`・`ws.input`）。バッグの持ち主の元になるので、偽れないようにする。
- **バッグは Host（Simulation）が持つ**。どの配置（作品）にも属さず、各作品の System の Query には当たらない。触れるのは Host API の `bag.*` だけ。
- **ホストが替わっても残るように、バッグはフレーム（`SessionFrame` / `PlayFrame` の `bags`）に入れて配る**。次のホストは最後のフレームから戻す。サーバーは最後のフレームを持っているので、抜けて戻っても残る。
- 権限は今までどおり「System の宣言 ∩ 置いた物への付与」。`bag.*` も Capability（`bag.read` / `bag.write`）として HOST_API_SPEC に載せる。

## 形

- Host API（Interact を受けている間だけ。それ以外は拒む）：
  - `bag.add(Type, values?)`：押した人のバッグに 1 個入れる。値は Type の定義で検証する（足りないフィールドは初期値）。いっぱいなら false。
  - `bag.count(Type)`：その種類がいくつあるか。
  - `bag.list(Type)`：その種類の値の一覧。
  - `bag.take(Type, match?)`：その種類のうち、`match` のフィールドが一致する最初の 1 個を取り出して値を返す（なければ null）。
- Type は import したライブラリの KokoState だけ（`pkg:` の ID。自分のプロジェクトの KokoState・Built-in は拒む）。
- 公式ライブラリ「items」：持ち物の種類 `Key`（color）と、E で拾うと押した人のバッグに入れて自分を消す System `KeyPickup`。
- reference UGC「鍵と扉」：鍵を E で拾い、鍵のかかった扉を E で押すと、同じ色の鍵を取り出して開く（扉の側は自分の System）。別の作者の作品どうし（鍵と扉が別の配置）でも、同じ公式 items の版を使っていれば開く。

## 結果・まだ決めていないこと

- フレームは全員に配るので、ほかの人のバッグの中身も、道具を使えば読める（画面には出さない）。秘密の持ち物が要るなら、サーバーが本人にだけ配る形を別に決める。
- 捨てる・渡す・並べ替える、持ち物の見た目（3D の手に持つ）、保存（セッションをまたぐ）は次の段階。
- 改変したホストからの保護（ADR 0012 §3.7）はまだない。協調セッションの範囲。
