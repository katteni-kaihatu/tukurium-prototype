# 0083: ワークスペースは、最近開いたプロジェクトとアイテムから開く

日付: 2026-11-17

## 判断

左の欄のワークスペースの切り替えから、サンプルを外す。サンプルはプロジェクトの新規作成で選ぶ。

- 切り替えには、このセッションで開いているワークスペースの下に、最近ワークスペースで開いたプロジェクトを 5 件まで並べ、その下に「プロジェクトを開く」（プロジェクトの一覧へ移る）と「空のワークスペース」を置く。
- 最近開いたプロジェクトは、ブラウザ（localStorage）に本人ごとに覚える。サーバーには送らない。いま読めないプロジェクトは出さない。
- セッションに出ているアイテムを押すと、元のプロジェクトを開くメニューを出す。
  - 持ち主（書き込める人）は「ワークスペースで開く」。
  - 読めるだけの人は「フォークしてワークスペースで開く」。
  - 元のプロジェクトから自分がフォークしたプロジェクトがあれば、それも並べて開ける。
  - どれもできなければ、メニューは出さない。
- サーバーは、配置の情報に元のプロジェクト（`repoId`）を載せる。ワークスペースから出した配置はそのワークスペースのリポジトリ、リリースから置いた配置は作品のリポジトリ。既定値が null の項目なので、`PROTOCOL_VERSION` は上げない。

## 理由

- 新しく始めるときのひな形は、プロジェクトの新規作成に集めた。切り替えには、続きの作業に戻る入口を並べる方が役に立つ。
- 「最近開いた」は端末ごとの便利さなので、まずはブラウザに置く。端末をまたいで使いたくなったら、サーバーに移す。
- 書き込めるのは今はプロジェクトの持ち主だけ（保存は持ち主だけ）。持ち主以外は、自分のフォークで改造する。
- 読めるかどうかは、プロジェクトの一覧（`GET /api/repos`、サーバーの `canRead`）に出るかで決める。フォークの条件（`canFork`）は読める条件と少し違うので、フォークできない場合はサーバーが断り、メニューにその理由を出す。
