# ADR 0059：エージェントがまとめて作り、素材を入れ、開いている画面を撮る

- 状態：採用・実装済み（2026-11-10）
- 関連：ADR 0054（リモートの MCP）、ADR 0006（素材）、ADR 0046（撮影）、ADR 0050（Transform は親からのずれ）

## 背景

森のように同じ形をたくさん置く制作では、Entity を一つずつ作ったり変えたりすると、呼び出しの往復だけで数分かかる。素材の一覧は見えたが、新しい GLB や画像を登録する道具がなく、材質にテクスチャを貼れなかった。参照の確認と試し動かしでは、入口から池がどう見えるか、葉の光沢がどれくらい残るかは分からなかった。作成は ID を返し、更新は「変えました」という文を返していたので、成功の判定がぶれた。

## 決定

- **Entity はまとめて変える**（`apply_entities`）。作成・更新・削除・複製を、並べた順に検証する。成功したものだけを、一つの Yjs の変更に入れる。失敗は操作ごとに分け、成功した分は戻さない。処理の途中で例外を出さない。例外になると、その変更全体が戻る。
- **一度の上限**は操作 200、新しく作る Entity 400、まとめて読む Entity 200。読むときも試し動かしも、切れたかどうかと全体の件数を毎回返す。
- **複製は、画面の「中も含めて複製」に合わせる。** 根は元と同じ親に付き、名前を省くと「元の名前 のコピー」（重なるときは数を足す）。子孫の名前と、親から見た位置はそのまま。根の位置・回転・拡大だけを置き換えられる。同じ呼び出しの中では、別名（`ref`）で今作ったものを指す。
- **世界座標は、位置の足し算にしない。** 制作データの親子を、実行時と同じ行列の積で求める。再生中の配置の親は含めない。
- **欄のマテリアル・モデル・画像・音声は、ID か一意な名前で指す。**
- **作成も更新も、成功すると ID と名前を返す。** 対象は Entity・KokoState・System・アウトプット・材質。確認（`check`）の「問題はありません」はそのまま。
- **素材は、人が上げるときと同じ置き場に入れる**（`import_asset`）。種類は GLB・PNG・JPEG・WebP・MP3・OGG・WAV、20MB まで。宣言した種類とファイルの先頭が違うものは拒む。制作データの一覧に加えたあとは、ワークスペースを閲覧できる人が取得できる。
- **`/mcp` の POST だけ、本体の上限を約 28MB にする。** ほかの経路は変えない。鍵はまだ無い（ADR 0054）ので、この大きさは編集と同じ信頼の範囲とする。鍵ができたら、この上限を見直す。
- **プレビューは、開いている一人の画面で撮る**（`preview`）。サーバーでは描かない。再生中ならその再生のホスト、編集中ならワークスペースを開いている人の先頭。エージェントには頼まない。8 秒で返事がなければ、開けていないものとして返す。
- **座標は制作データの座標系。** 画面上の置き位置は、開いているクライアントが足す。手伝いの表示は写さない（サムネイルと同じ描き方）。テクスチャと GLB は、読み込みが終わるか 2 秒たつまで待つ。残っていれば、そのことを結果に書く。
- **通信の版は 7。** 撮影の依頼（`ws.capture`）と結果（`ws.shot`）を足す。

## 結果

- `apply_entities`・`get_entities`・`import_asset`・`update_material`・`preview` を MCP に足した。
- 撮影の待合せは Hub に置き、文書の読み書きは接続を知らないままにした。
- クライアントは、読み込み中の件数を持ち、頼まれたら指定した視点で PNG を返す。
