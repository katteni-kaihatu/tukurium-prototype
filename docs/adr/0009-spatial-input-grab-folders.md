# ADR 0009：空間での操作（照準クリック・右クリック）と Resources のフォルダ

- 状態：採用
- 関連：ADR 0003（パネル）、ADR 0006（セッションの世界）、要件 §6

## 背景

使ってみて、次の 3 つの指摘が出た。

- 3D に置いたパネルを、空間の中から操作できない。空間に入っている（ポインターロック中）ときは、マウスのクリックが DOM に届かないため。
- 3D のパネルを動かしたい。
- 空間の中で物を手に持ちたい。

あわせて、Resources をデザインどおりのフォルダ構造にした。

## 決定

### 1. 照準でパネルを操作する

- 空間に入っている間は、画面の中央（照準）の先を `document.elementFromPoint` で調べる。3D パネルの中なら、マウスのイベントを合成してその要素へ渡す（pointerdown・mousedown・pointerup・mouseup・click）。入力欄などにはフォーカスを移す。ホイールは、照準の先でスクロールできる要素へ渡す。
- 照準がパネルに乗っている間は、照準の見た目を変えて「クリックがパネルに届く」ことを示す。
- 自分で合成したイベントが document に返ってきて繰り返さないよう、`isTrusted` でないイベントは扱わない。

### 2. 右クリックの使い分け

| 照準・ポインターの先 | 右クリック |
| --- | --- |
| 3D のパネル | 押している間、パネルが距離を保ったままポインター（空間に入っていれば照準）についてくる。離すと置き場所を保存する |
| それ以外 | Grabbable を持つ・放す（入力 `grab`） |

右クリックのメニューは、空間の中では出さない。

### 3. 持つ（Built-in の Grabbable）

- `Grabbable`（distance：目の前に持つ距離、既定 1.2m）を Built-in に足した。物を持つと、`Held` に持ち主（`player`）が入る。`player` が空の Held は、これまでどおり「見ている人みんなの手に持つ」（銃のサンプルなど）。
- 持つ・放すは、実行する側（ワークスペースのホスト、セッションの持ち主）のランタイムが、組み込みの入力として処理する。スクリプトの onInput には渡さない。
  - `grab`：持っていなければ、レイキャスト（6m まで）で当たった物か、その親のうち Grabbable を持つものを持つ。持てるのは、いちばん上の Entity だけ。ほかの人が持っている物は取れない。持っていれば放す（その場に置く。動く剛体なら落ちる）。
  - `hold`：持っている人の視点を 0.1 秒ごとに送り、視点の先へ動かす。ほかの人には、この位置で見える。
- 持っている間の物理は、落ちないよう kinematic として扱う。
- 当てる判定に Rapier を使うので、持つには Collider も要る。

## 追記（持ったときの位置と角度）

持った瞬間に、目の前の決まった位置へ飛ばしたり、向きを視点に合わせたりしない。持ったときの位置と角度を、視点からの差として `Held.offset` と `Held.rotation` に覚える。すぐ離せば、同じ場所にある。

持っている間は、その差を保ったまま視点についてくる。

- 左クリック：傾きを直し、上下の軸まわりの向き（Y）だけ残す（`align`）。撃つ操作は、このときは送らない。
- E を押している間：マウスの動きで持っている物を回す（`twist`）。この間は視界を回さない。離すと、また見回せる。持っていないときの E は、これまでどおり `use`。

`Grabbable.distance` は、この変更のあと位置を決めない（データとしては残している）。

### 4. Resources のフォルダ

- 制作データに `folders`（id・name・parent）と `placement`（リソース ID → フォルダ ID）を足した。並べ方だけの情報で、実行には関わらない。コミットでは `folders.json` に入る。
- Built-in の KokoState は、読み取り専用のフォルダ「Built-in」にまとめて見せる。
- フォルダを消すと、中身はひとつ上へ移る。

## 影響・残課題

- 合成したイベントでは開けないもの（`<select>` の一覧など）がある。空間に入っていなければ、パネルは普通に操作できる。
- 持つ物の位置は 0.1 秒ごとにしか届かないため、ほかの人からは少しカクついて見える。
