# ADR 0054：ライブラリは Entity を持たず、含めるリソースをアウトプットごとに選ぶ

- 状態: 採用・実装済み
- 関連：ADR 0015（最小の Library Package）、ADR 0045（リリースはアウトプットごと）、ADR 0052（ほかのプロジェクトから取り込む）

## 理由

ライブラリのアウトプットも、アイテムやワールドと同じく Hierarchy で Entity を作れた。ライブラリはセッションに置くものではなく、import して使うものなので、Entity は意味を持たない。

また、ライブラリに入るものは、Resources でリソースごとに付ける「公開」の印（プロジェクトに一つの `exports`）で決めていた。どのライブラリに何が入るかが、ライブラリの画面からは見えなかった。

## 決定（利用者と決めたこと）

- ライブラリのアウトプットには **Entity を作れない**。Inspector の左は、Hierarchy の代わりに **含めるリソース** を選ぶ画面にする（KokoState・System・マテリアル・素材をチェックで選ぶ）。
- **含めるリソースは、アウトプットごとに持つ**（`OutputDef.resources`）。プロジェクトの `exports` と、Resources の「公開する」ボタンはなくす。一つのプロジェクトに、中身の違うライブラリを二つ以上作れる。
- 「ライブラリに含めたもの」が「そのライブラリが公開しているもの」になる。Package の中身（manifest）と content hash は、作品のアウトプットに含めたものだけで作る（`packageManifest(snap, outputId)`）。

## 形

- 含めたリソースを消すと、制作データ（Snapshot）からも外れる。
- 含めた System が、含めていない KokoState を import していると、使う側では見つからない。今までどおりエラーにし（`exported-system-imports-private`）、含めるリソースの画面ではその行に「要る」と出す。
- Entity があるアウトプットは、Kind をライブラリに変えられない。ライブラリから別の種類に変えると、含めるリソースの一覧は捨てる。
- ライブラリのアウトプットを、ほかのプロジェクトから取り込むと、含めたリソースも一緒に持ってきて、付け替えた ID で含め直す。
- 履歴の差分には、アウトプットの「含めるリソース」として出す。変化の丸から元に戻せる。
- プロトタイプなので、古い `exports.json` は読まない（開発用データは作り直す）。

## 残したこと

- ライブラリのアウトプットの Systems（実行する System の一覧）は、今は使われていないが画面に残っている。
