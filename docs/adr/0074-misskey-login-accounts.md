# ADR 0074：Misskey でログインするアカウント

- 状態: 採用・実装済み（2026-11-13）
- 関連: [ADR 0005](0005-sessions-identity-host.md)（本人識別。ここを置き換える）、[ADR 0054](0054-agent-remote-mcp.md)（AI エージェント）、[原則](../PRINCIPLES.md)

## 背景

これまでの本人識別は、名前を入れるとランダムなトークンを発行し、ブラウザに残すだけだった（ADR 0005）。別の端末では同じ人になれず、トークンを消すと別人になる。フレンド・所持アイテム・プロジェクトなど、人に結び付くものが増えたので、本当のアカウントが要る。

姉妹のプロトタイプ Tonarium（`katteni-kaihatu/tonarium-prototype`）は、れぞらぶの Misskey（misskey.resonite.love）でログインする。同じ仕組みにそろえる。

## 決定（利用者と決めたこと）

- **ログインは Misskey だけ**。ゲストはない。ログインしていなければ、ログインの画面だけを出す。
- **Misskey は 1 つ**。既定は `https://misskey.resonite.love`、`MISSKEY_URL` で変えられる。
- **確認コードは作らない**。Misskey で許可したあと、ログインを始めたブラウザに戻ったときだけ入れる。Tonarium にある「別のブラウザで許可したら 8 文字のコードを入れる」手順は、デスクトップアプリのためのもので、ブラウザだけの Tukurium には要らない。
- **表示名とアイコン**：表示名は最初だけ Misskey の名前（なければユーザー名）にし、アカウントのウィンドウで変えられる。変えた名前は、ログインし直しても残す。アイコンは Misskey のアバターの URL を持ち、ログインのたびに新しくする。顔の丸（グローバルメニュー・フレンド・参加者・通知・プロフィール）に出す。
- **AI エージェント（`/mcp`）は今回そのまま**。人とは別の、ログインできない利用者を作る。アカウントでトークンを発行する仕組みは、あとの作業にする。
- **過去のデータは捨てる**。保存の形に版（`tukurium_schema`）を置き、版が違えば起動時にすべての表を消して作り直す。今回 2 にした。

## 仕組み

Tonarium の `server/auth.ts` と同じ考え方で、確認コードとゲストを除いた。部品はサーバーが `apps/server/src/auth/auth.ts`、画面が `apps/client/src/auth/`。

### Misskey の OAuth 2.0（認可コード＋PKCE `S256`）

1. 画面が `POST /api/auth/misskey/start` を呼ぶ。サーバーは state と PKCE の `code_verifier` を作ってメモリに残し（10 分）、始めたブラウザにだけ「待ち合わせの秘密」を Cookie（`tukurium_login`）で渡し、Misskey の許可の画面（`/oauth/authorize`）の URL を返す。求める権限は `read:account` だけ。
2. 許可すると Misskey が `/api/auth/misskey/callback?code=…&state=…` へ戻す。サーバーは次のときだけ入れる。
   - state が分かり、期限内で、まだ使われていない（1 つの state の戻りは一度だけ受ける）
   - 待ち合わせの Cookie が、そのログインを始めたブラウザのもの（他人に許可の URL を開かせて入る、ログイン CSRF を防ぐ）
   - `iss` が付いていれば、使う Misskey と同じ
   - 認可コードを `code_verifier` と一緒にトークンに替えられ（`/oauth/token`）、`/api/i` で許可した人（ID・ユーザー名・名前・アバター）が分かる
3. 入れたら、ログインの Cookie を付けて `/` へ戻す。Misskey のトークンは本人確認にだけ使い、捨てる。うまくいかないときは、短い案内のページを出す。
4. 同じ Misskey の人は、何度ログインしても同じアカウント（`misskey:<Misskey のユーザー ID>` で引く）。

`client_id` はアプリのトップページ（`https://<アプリのドメイン>/`）。Misskey がこのページを読みに来て、`<link rel="redirect_uri">` の戻り先と `h-app`（アプリの名前）を確かめる。トップページはサーバーが返すときに `__ORIGIN__` を自分のオリジンに書き換える（`apps/client/index.html`）。そのため、本物の Misskey でログインできるのは、アプリのドメインが Misskey から HTTPS で読めるとき（本番や公開した検証環境）だけ。手元では開発用ログインを使う。

### ログインのセッション

- Cookie は `tukurium_session`（HttpOnly・SameSite=Lax、HTTPS なら Secure）。中身は乱数で、DB（`auth_sessions`）にはハッシュだけを残す。期限は 90 日で、残りが 30 日を切ると使ったときに延ばす。Cookie 自体はブラウザの上限（400 日）まで持たせ、期限はサーバーで決める。期限切れは 1 時間ごとに消す。
- 本人は、HTTP ではリクエストの Cookie、WebSocket（`/ws`）ではつないだときの Cookie で決める。画面から名乗った名前や ID は信じない。`hello` は版だけを送る（名前はエージェントの内部の接続だけが使う）。ログインしていない接続には `auth.required` を返して閉じ、画面は読み込み直してログインの画面に戻る。通信の版（`PROTOCOL_VERSION`）を 13 に上げた。
- 本人の決まった接続でも、一斉の知らせ（セッション一覧など）は `hello` を受けて `welcome` を返したあとから送る（`welcome` が最初に届くように）。
- 画面は、読み込んだらすぐ接続を始め（これまでと同じ順序）、並行して `/api/auth/me` でログインを確かめる。ログインを確かめるのを待ってから接続すると、画面の準備（3D）と重なって `hello` を送るのが遅れやすい。ログインしていなければ、サーバーが `auth.required` で閉じ、ログインの画面を出す。入ったら読み込み直す。
- ログアウトは、そのセッションを消し、そのセッションでつないでいた接続をすべて閉じる。
- ほかのサイトに Cookie を使わせない：GET 以外の `/api` は、同じオリジンからの fetch（`Origin` が自分のオリジン）だけ受ける。WebSocket も、`Origin` が付いていて自分のオリジンと違えば、ログインしていないものとして扱う。素材の URL に付けていたトークン（`?t=`）はやめ、Cookie で見分ける。
- 自分のオリジンは `X-Forwarded-Proto`・`X-Forwarded-Host`（前段のリバースプロキシが付ける）と `Host` から決める。開発サーバーの Vite の中継は、`Host` を書き換えないように設定する（`changeOrigin` にしない）。

### 開発用ログイン

`AUTH_DEV_LOGIN=1` があり、かつ `NODE_ENV` が `production` でないときだけ、名前だけで入れる `POST /api/auth/dev` を開く。同じ名前なら同じアカウント（`dev:<名前>`）。`pnpm dev` は `apps/server/dev.env` で開く。本番のイメージは `NODE_ENV=production` なので、設定しても開かない。ログインの画面に「開発用ログイン」の欄が出る。E2E は `e2e/helpers.ts` の `login()`、スモークテストも開発用ログインで入る（閉じている本番では、ログインの画面と、ログインしていない接続を断ることだけを確かめる）。

## 代わりに考えたこと

- **Tonarium と同じ確認コード**：デスクトップアプリから外のブラウザで許可する場合のためのもの。ブラウザだけなら、同じブラウザに戻るので要らない（利用者と決めた）。
- **ゲスト**：入りやすいが、ゲストにできることを決め、人に結び付くものの扱いを二通りにする手間がかかる。今は使わない（利用者と決めた）。
- **ログインの途中を DB に置く**：サーバーは 1 つなので、メモリで足りる。再起動したらログインをやり直してもらう。
- **既存のデータの移行**：プロトタイプの間は移行しない（CLAUDE.md）。

## 結果

- サーバー：`apps/server/src/auth/auth.ts`（ログイン・セッション・同じオリジンの確認）、Store に `loginUser`・`createAuthSession` などを足し、`users` に `login_key`・`account`・`avatar_url` を持たせた。`userByToken` はなくした。
- 画面：`apps/client/src/main.tsx` がログインを確かめ、ログインしていなければログインの画面だけを出す。ログインの画面（`auth/LoginPage.tsx`）、アカウントのウィンドウ（`main-menu/AccountPanel.tsx`。グローバルメニューの歯車から開く）、顔の丸（`app/AvatarFace.tsx`）。
- 通信：`UserInfo` に `account`（`@ユーザー名@ホスト`）と `avatarUrl` を足した。
- テスト：`apps/server/src/auth/auth.test.ts` が偽の Misskey を立てて、許可・別のブラウザ・一度だけ・ログアウト・ほかのサイトを確かめる。

## 残っていること

- AI エージェントのトークン（アカウントで発行し、エージェントをその人に属させる。ADR 0054）。
- アカウントの削除、Misskey 側で許可を取り消したときの扱い。
- アイコンは Misskey の URL をそのまま使う。Misskey 側で変わると、次にログインするまで古い画像（や切れた画像）になる。切れたときは名前の 1 文字目を出す。
