# ADR 0028：セッションの中で、必要なときだけワークスペースを開く

- 状態: 採用・実装済み（2026-11-05）
- 置き換え: [ADR 0027](0027-main-menu-integration.md) の「プロジェクトや探索ページへ移るときに退出を確認する」という判断
- 関連: [ADR 0005](0005-sessions-identity-host.md)、[ADR 0021](0021-main-menu-window.md)

## 背景

セッションは人が集まって過ごす場所で、ワークスペースはプロジェクトを編集するために開くもの。セッションへの参加と、編集を始める操作を分ける。

たとえば、チルしているときはワークスペースを開かない。所持アイテムから麻雀卓を取り出して遊ぶときも、Inspector を開く必要はない。麻雀卓は利用場面の例であり、この変更で麻雀の実装を追加するものではない。

## 決定

- セッションに参加しただけではワークスペースも制作開始パネルも開かない。
- プロジェクトの一覧・詳細・探索・新規作成は、共通メニューの中で開く。現在のセッション、参加者、置いたアイテム、編集中の内容を保つ。
- 一覧や詳細を見るだけでは編集を開始しない。「このセッションで編集する」、または「作る」から対象を選んだときにワークスペースを開く。
- 未参加で編集を選んだら、先にセッションを選ぶ。参加が成功した後で、選んだプロジェクトを開く。
- ワークスペースを閉じてもセッションには残る。公開アイテムの入手・取り出し・利用は、ワークスペースなしで行える。
- 別セッションへの移動と、明示的な退出・終了は従来どおり扱う。

## 画面と処理

共通メニューには五つの画面を残し、制作関連の画面にはメニュー内の履歴と戻る操作を持たせる。プロジェクト画面は単独 URL からも引き続き開ける。

編集を選んだ後は、サーバーから対象のワークスペースを受け取ってからメニューを閉じる。拒否や通信切断では理由を表示する。セッションの 3D エンジンを作り直さず、ワークスペースの有無で入力とパネルの表示を切り替える。

## 確認

2人が参加したまま、プロジェクトの閲覧・作成・公開、明示的な編集と終了、所持アイテムの取り出しを確認した。マルバツの操作もワークスペースなしで動いた。閲覧中に退出メッセージを送らず、同じ3Dエンジンと参加者を保っている。未参加から編集先のセッションを選ぶ流れと、狭い画面も確認した。

共同編集・遊んでいる横での更新・公開を含む既存 E2E は、編集する人だけがワークスペースを開く手順に変更した。
