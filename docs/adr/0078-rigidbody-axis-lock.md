# ADR 0078：RigidBody に、軸ごとの移動と回転の固定を持たせる

- 状態: 採用・実装済み（2026-11-14）
- 関連: [ADR 0068](0068-physics-collider-and-player.md)（Collider と RigidBody）

## 背景

スイカゲーム・ピンボール・エアホッケー・横から見たアクションのように、物を 1 つの平面の中で動かす遊びは多い。RigidBody には軸を固定する指定が無く、作り手は System で毎フレーム、位置と速度を書き戻していた。

この書き戻しは、物理の計算の結果をあとから上書きする。挟まれた物が一瞬はみ出したり震えたりし、物の数だけ毎フレームの読み書きも増える。Transform を書き戻す知識が要り、作り手が自分でたどり着きにくい。箱を薄くして壁で挟む方法は、大きな物が暴れ、見た目の奥行きまで縛る。

物理エンジン（Rapier）は軸ごとの固定を持っている。足りないのは、作り手に見せる入口だった。

## 決定

1. **RigidBody に、boolean のフィールドを 6 つ足す**。`lockMoveX` / `lockMoveY` / `lockMoveZ`（その軸へ動かさない）と、`lockRotateX` / `lockRotateY` / `lockRotateZ`（その軸まわりに回さない）。初期値はどれも false。
2. **軸はワールドの軸**である。親や自分の向きでは変わらない。Rapier の固定がワールドの軸で働くので、それに合わせる。
3. **効くのは `dynamic` のときだけ**。`kinematic` と `fixed` は、これまでどおり Transform に付いて動く。手に持っている間・装備している間も、Transform に付いて動く。
4. **固定した軸の位置・角度は、今の値のまま保つ**。0 へ寄せることはしない。Transform に置いた場所がそのまま平面になる。手で持って動かして放すと、放した場所で固定される。
5. **固定した軸へは、速度を書いても動かさない**。スクリプトが `linvel` / `angvel` の固定した軸の成分に書いた値は、計算の前に 0 として扱い、計算のあとには 0 を書き戻す。
6. 固定を変えたら、形や重さを変えたときと同じく、剛体を作り直す。

よくある組み合わせ：

- XY 平面で動かす（横から見た 2D）：`lockMoveZ`・`lockRotateX`・`lockRotateY`
- 倒れない箱：`lockRotateX`・`lockRotateY`・`lockRotateZ`

## 選ばなかった案

- **Vec3 を 2 つ（`lockMove` / `lockRotate` に 0 か 1）**。欄は 2 行で済むが、真偽を数で表すことになり、Inspector では数の欄に 0 / 1 を入れる形になる。スクリプトでも `rb.lockMoveZ = true` のほうが読める。
- **平面を 1 つ選ぶフィールド（xy / yz / xz）**。分かりやすいが、軸ごとの固定でできることの一部でしかない。両方持つと同じことを 2 か所で決めることになる。

## この段階でしないこと

- Inspector のプリセット（「XY 平面」をひと押しで入れるボタン）。軸ごとのフィールドを使ってみてから、別の作業で足す。
- 親や自分の向きに合わせた軸での固定。
- 固定した軸の位置を、決めた値へ寄せること。
