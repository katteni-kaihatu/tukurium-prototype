# ADR 0076：プレハブをリソースにし、インスタンスは使う所の手前で中身に展開する

- 状態: 採用・一部実装済み（P3 まで。プレハブのリソース・インスタンスを置く・展開・再生・プレハブを開いて直す・アウトプットの Entity からプレハブを作る。残りは実装計画の段階で進める）
- 関連：ADR 0004（ワークスペースの同期）、ADR 0010（リソースの同一性・参照・診断）、ADR 0012（権限と判定の場所）、ADR 0037（フィールドごとの共同編集）、ADR 0057（動作上の親）、ADR 0065（フィールドの型と値）
- ロードマップ：「プレハブを作ってインスタンスをアウトプットに置く」。原則 4 のため

## 背景

的や駒のように、同じものを何個も置いて、まとめて直したい。今は、Entity をアウトプットごとに一つずつ持っていて、同じものを置くには複製するしかない。複製したものは、あとから一緒に直せない。

構想で、Entity・KokoState・System のまとまりを「プレハブ」としてリソースに登録し、アウトプットの中に「インスタンス」として置くことを決めた。プレハブを直すと、すべてのインスタンスに反映される。

## 決定（構想で決まっていること）

- プレハブは部品で、リソースとして作る。それだけをセッションに出すことはない。
- プレハブは Entity（子を含む）・KokoState・System を含められる。別のプレハブのインスタンスも置ける。自分を含むことはできない。
- インスタンスはアウトプットの中に置き、場所・向き・大きさを決められる。
- インスタンスでは、フィールドの値を変え、Entity・KokoState・System を足し、並べ替えと親の付け替えができる。プレハブから来たものは消せない。
- プレハブの変更は、ワークスペースの中のインスタンスにはすぐ反映し、セッションに出した配置には「適用」で届く。

## 作り方（設計者・実装者が決めたこと）

### 1. プレハブは新しい種類のリソース

- 定義（`PrefabDef`）：ID・名前・いちばん上の Entity（`root`）・System の並び（`systems`）・「維持」の印（`keep`）・編集する場所（`editIn`。ないときは「その場」）。
- 論理パスと ID は、ほかのリソースと同じ扱い（ADR 0010）。拡張子は `.prefab`。名前を変えても動かしても、インスタンスは ID で結び付いているので切れない。
- Git には、`prefabs/<ID>.json`（定義）と `prefabs/<ID>/entities/<Entity の ID>.json`（中の Entity）で保存する。
- 制作データが増えるので、`PROTOCOL_VERSION` を 14 に上げる。

### 2. プレハブの中の Entity は、アウトプットの Entity とは別に持つ

実装計画の二つの案のうち、(b)「`output` はそのままにし、プレハブの Entity を別に持つ」を選んだ。

- 制作データ：`ProjectSnapshot.prefabEntities`（`PrefabEntityDef`。`output` の代わりに、属するプレハブの ID `prefab` を持つ）。
- 共同編集（Y.Doc）：`prefabEntities` という別の `Y.Map`。中の形は `entities` と同じで、値はフィールドごとの後勝ち（ADR 0037）。
- Entity の ID は、アウトプットのものとプレハブのものを通して一つ。フィールドの値を変えるなどの操作は、ID だけで、どちらの Entity にも届く。

選んだ理由：

- (a)「`output` を `owner` に置き換え、同じ `entities` に入れる」だと、`e.output` を読んでいる所（テストを除いて 90 か所ほど）を、すべて持ち主の種類で分けることになる。
- それより大きいのは、取りこぼしたときの壊れ方。依存グラフ・参照の診断・抽出・差分は「`entities` にあるものは、どれかのアウトプットの Entity」という前提で書かれている。同じ並びにプレハブの中の Entity（展開する前の、ひな形）が混ざると、直し忘れた所で、ひな形が実体として扱われる。
- (b) なら、今のコードはプレハブの中の Entity を目にしない。展開したあとの並びは、プレハブがなかったころと同じ形なので、そのまま読める。プレハブの中身を扱う所だけが、新しい並びを読む。

### 3. インスタンスの Entity が、プレハブのいちばん上の Entity に当たる

- プレハブは、いちばん上の Entity（`root`）を一つだけ持つ。プレハブの中のほかの Entity は、すべてその下に入る。空のプレハブは、いちばん上の Entity だけを持つ。
- インスタンスは、アウトプット（または別のプレハブ）の中の一つの Entity で、`instanceOf: { prefab: <プレハブの ID> }` を持つ。
- インスタンスの Entity の ID・名前・親・並び順は、インスタンスのもの。KokoState は、プレハブのいちばん上の Entity のものに、インスタンスが持っている KokoState を重ねる（同じ KokoState は、インスタンスのものが勝つ）。
- 場所・向き・大きさは、インスタンスが持つ Transform。置くときに、プレハブのいちばん上の Entity の向きと大きさを写す。あとでプレハブ側の Transform を変えても、インスタンスには届かない（「変えた所」には数えない）。

選んだ理由：アウトプットの Entity からプレハブを作る（P3）とき、選んだ親の Entity はインスタンスになり、元の ID を引き継ぐ。ほかの Entity が「親の Entity を指す参照」を持っていても、そのまま使える。インスタンスを「入れ物」にして中身を子にする形だと、その参照は KokoState のない入れ物を指してしまう。

### 4. 使う所の手前で展開する（`expandPrefabs()`）

制作データのインスタンスを、プレハブの中身に置き換えた並びを作る関数を、repo-model に置く。

- **ID**：インスタンスの Entity は、そのままの ID。中の Entity は「インスタンスの ID `/` プレハブの中の Entity の ID」。入れ子は、順につなげる（`盤のインスタンス/駒1/芯`）。決まった作り方なので、開き直しても、別の人の画面でも同じ ID になる。区切りに使うので、Entity の ID に `/` は使えない。
- **参照**：プレハブの中の Entity どうしの参照（フィールドの値。入れ子の値の中も）は、展開のときに、そのインスタンスの中の ID に付け替える。プレハブの外を指す参照は、そのまま。
- **入れ子**：プレハブの中のインスタンスも、たどって展開する。自分を含むプレハブ（輪）は、そこで展開を止め、問題として出す。プレハブがないインスタンスは、中身のない Entity として残し、問題として出す。
- **結果の形**：アウトプットの Entity の並び（`EntityDef`）。プレハブから来たものには、どのインスタンスの、どのプレハブの、どの Entity かが付く（`origin`）。展開したあとは `instanceOf` を持たないので、もう一度展開しても変わらない。アウトプットの `systems` と `keep` は、足し合わせたあとのもの（6・7）。
- **読む所**：再生（`buildWorld()`・`Simulation` の配置と適用）、空間の表示、Hierarchy、Inspector、参照の診断の「指す先があるか」。依存グラフは、展開せずに「インスタンス → プレハブ → プレハブが使うもの」の辺で持つ（インスタンスの数だけ節を増やさない）。
- **問題を出す相手**：制作データにある Entity とプレハブ。展開で作った Entity は、利用者がそこでは直せないので、問題の相手にしない。
- **プレハブの中の問題**：プレハブの中の Entity が指すリソース（マテリアル・素材）・Entity・KokoState の定義がないこと、プレハブの System がないこと、プレハブの「維持」の印がない値を指していることは、プレハブを相手にして出す。確かめは、アウトプットの Entity・アウトプットのものと同じ処理を使う。問題の場所は「`entities` / 中の Entity の ID / KokoState / フィールド」。「エラー」パネルからは、そのプレハブを開いて、その Entity と欄へ移る。プレハブの中の参照は、そのプレハブの中の Entity（入れ子の中は、展開した ID）と、アウトプットの Entity を指せる。

### 5. 展開の結果を取っておく

- プレハブごとに、入れ子まで開いた形（ひな形）を覚えておく。そのプレハブと、中で使っているプレハブの中身が変わるまで使い回す。
- インスタンスごとの展開した Entity も覚えておく。インスタンスも、ひな形も変わっていなければ、そのまま使う。
- フィールドの型が変わると、参照の付け替えが変わるので、すべて作り直す。
- 取っておいた結果は、次の展開でも使う。展開したあとの制作データは、読むだけにする。
- 計測（`pnpm bench:prefab`。3 段の入れ子、インスタンス 1 個が Entity 69 個）：インスタンス 100 個（Entity 6,900 個）で、初めの展開は 4 ms、何も変わっていなければ 0.4 ms、インスタンスを一つ動かすと 0.4 ms、いちばん内側のプレハブを変えると 4.5 ms。

### 6. System は、並びと「入・切」だけを足し合わせる

- アウトプットで動かす System は、アウトプットのものと、中のインスタンスのプレハブのもの（入れ子の中のものも）を合わせたもの。
- **並び順**：アウトプットのものが先。プレハブのものは、そのあとに、Hierarchy の並びで先に出てくるインスタンスのものから足す。一つのプレハブの中では、プレハブの並びのとおり。入れ子では、外のプレハブのものが先で、中のプレハブのものは、中のインスタンスが出てくる順。
- **同じ System**：一つにまとめる（先に出てきた所に置く）。どれかのプレハブで「入」なら「入」。
- **アウトプットが勝つ**：アウトプットにも同じ System があれば、場所も「入・切」もアウトプットのもの。アウトプットの画面で、プレハブの System を「切」にすると、アウトプットの並びに「切」で入る。
- 権限は、今と同じく System のコードから読み取る（ADR 0012）。

### 7. 「維持」の印

- アウトプットの印は、展開した Entity の ID とフィールドの組を指せる。
- プレハブの中で付けた印は、プレハブが持つ（Entity は、プレハブの中の ID）。展開のときに、インスタンスごとの ID にして、アウトプットの印に足し合わせる。
- インスタンスを消したら、その中を指すアウトプットの印も一緒に外す。
- プレハブの中の Entity を消したら、そこを指すプレハブの印と、インスタンスの中のその Entity を指すアウトプットの印も外す。

### 8. インスタンスで変えた所（上書き）の持ち方

P4 で作る。作りながら変えたら、ここを直す。

- **フィールドの値**：インスタンスの Entity が、上書きの入れ物（`Y.Map`）を持つ。キーは「プレハブの中の Entity の ID（いちばん上からの ID）・KokoState・フィールド」、値はフィールドの値。リストの一つの要素だけを変えても、フィールドまるごとを持つ（フィールドごとの後勝ちに合わせる）。
- **足した KokoState**：いちばん上の Entity（インスタンスそのもの）に足すものは、インスタンスの `states` に持つ（3 の重ね方が、そのまま使える）。中の Entity に足すものは、上書きの入れ物に、KokoState まるごとで持つ。
- **足した Entity**：アウトプットのふつうの Entity として持ち、親に、展開した Entity の ID を指す。ID が決まった作り方なので、開き直しても親を見失わない。
- **並び順と親**：プレハブから来た Entity ごとに、変えた親と並び順だけを持つ。
- **親が消えたとき**：プレハブは、消した Entity の「元の親」を覚えておく。展開のとき、親が見つからなければ、これをたどって、さらに上の親に付ける。
- **足した System**：インスタンスが、System の並びを持つ。プレハブの System と同じ扱いで足し合わせる。
- **入れ子で何段も重なったとき**：内側から順に重ね、外側が勝つ。

### 9. プレハブを開いて直す

**開く**

- プレハブを開くと、編集の対象が、アウトプットからそのプレハブに切り替わる。Hierarchy と Inspector は、アウトプットと同じ画面のまま、プレハブの中の Entity を出す。空間（Edit の表示）にも、プレハブの中身を出す。
- 開き方：Resources でダブルクリック、プレハブの詳細の「開く」、Hierarchy のインスタンスの行と Inspector の「プレハブを開く」。閉じるのは、Hierarchy の上に出る「アウトプットに戻る」。
- どのプレハブを開いているかは、画面（人）ごとに持ち、同期も保存もしない。直した中身は制作データなので、一緒に編集している人にも、すべてのインスタンスにも、すぐ反映される。
- 選んだもの（Entity・アウトプット・プレハブ）が、いつも Hierarchy に出ているものの中にあるようにする。プレハブの中の Entity を選ぶと（問題の場所から移るときなど）、そのプレハブが開く。アウトプットやその Entity を選ぶと、閉じる。アウトプットを切り替える・ワークスペースを出る・開き直す・開いていたプレハブが消える、でも閉じる。

**編集用の並び（`expandPrefabForEdit()`）**

- プレハブの中の Entity を、アウトプットを展開したものと同じ形にする。ID はそのまま、`output` にはプレハブの ID を入れる。アウトプットは、このプレハブを表す一つだけ（System と「維持」の印は、プレハブのもの）。
- いちばん上の Entity だけが親を持たない。親が見つからない Entity は、いちばん上の Entity の下に出す。
- 中に置いた別のプレハブのインスタンス（入れ子）は、「その Entity の ID `/` 中の ID」で展開する。開いているプレハブを含むもの（輪）は、展開しない。
- 表示（`buildWorld()`）・Hierarchy・Inspector は、アウトプットのときと同じ処理で読める。取っておく入れ物は、アウトプットの展開のものとは分ける。

**Entity の操作**

- `ProjectDoc` の操作（足す・名前・KokoState を付ける/外す・値・並べ替え・親の付け替え・複製・削除）は、プレハブの中の Entity にも届く。兄弟と子孫は、同じ持ち主（同じアウトプットか、同じプレハブ）の中で数える。
- いちばん上の Entity は、消せず、複製できず、ほかの Entity の下に付けられない。プレハブの中で親なしにする操作は、いちばん上の Entity の下に付ける。持ち主をまたぐ親の付け替えは断る。
- System の並びと「入・切」は、プレハブの詳細で、アウトプットと同じ画面で直す。「維持」の印は、プレハブを開いているときの Inspector の欄で付け、プレハブが持つ。
- プレハブの中にインスタンスを置く画面は、まだない（P6）。データとして入れ子があれば、展開して見せる（中の Entity は変えられない）。

**編集する場所（`PrefabDef.editIn`。ないときは「その場」。プレハブの詳細で切り替える）**

- **その場**：アウトプットはそのまま出し、同じ編集空間の中に、プレハブの中身も出す。
  - インスタンスから開いたとき：そのインスタンスの横（+X 側）に、すき間（0.5 m）をあけて出す。高さと奥行きは、インスタンスにそろえる。横にほかの物があれば、重ならなくなるまで、さらに横へ送る。
  - Resources などから開いたとき：区画に出ているもの全体の手前（+Z 側）に、床に載せて出す。
  - 置き場所の計算は、画面から切り離した関数にする（`workspace/prefabPlace.ts` の `prefabEditOrigin()`）。
- **離れた空間**：ワールドの編集と同じ仕組み（`workspace/anchor.ts`。セッションから離した独立した空間に、区画のポータルで入り、出口から戻る）を使う。場所は、ワールドの編集・非公開の作業の空間と重ならない所にする（`prefabAnchor()`）。開くとそこへ移り、閉じると元の編集空間へ戻る。アウトプットがワールドでも、開いている間は、プレハブの中身だけが見える。
- 置き場所は、開いたときに一度決め、開いている間は動かさない（直している間に、中身が動かないように）。形が決まるまで（素材の読み込みを、1.5 秒まで）待ってから決める。
- 空間でクリックして選べるのは、開いているプレハブの中身だけ（アウトプットの物を選んで、うっかり閉じないように）。境界の枠も、プレハブの中身に付く。開いているプレハブの中身にも、ぶつかる。
- ほかの人へ送る編集中の見た目（開いていない参加者に見えるもの）と、サムネイル・画面を撮る道具には、開いているプレハブの中身を出さない。アウトプットのままにする。

**再生**

- 再生中（Play mode）は、プレハブも編集できない。再生中は、プレハブを開けない。
- プレハブを開いたまま Play を始めると、プレハブを閉じて、アウトプットに戻ってから再生する。Stop しても、開き直さない。
- 「開いている間は Play できない」にしなかった理由：再生は、アウトプットを相手に、ワークスペースの全員で一つ。開いているプレハブは人ごとなので、ほかの人が始めた再生を受ける道がどのみち要る。「再生が始まったら閉じる」なら、だれが始めても一つの決まりで済む。

**最後の保存からの変化の印**

- プレハブの中の Entity にも、Hierarchy と Inspector に丸を出す（アウトプットの Entity と同じ比べ方。比べる相手は、プレハブのファイル）。
- 丸から細かく見る・戻すことは、まだできない。戻すのは、Hierarchy のいちばん上の行（プレハブそのもの）とプレハブの詳細の丸から、プレハブまるごと。

### 10. アウトプットの Entity からプレハブを作る

アウトプットの Entity（中の Entity を含む）を選び、「プレハブにする」を押すと、確認のあと、その Entity がプレハブのインスタンスになる。

**変換の中身**

- **選んだ Entity**：ID・名前・親・並び順と Transform（場所・向き・大きさ）を持ったまま、インスタンスになる（`instanceOf` が付く）。ほかの KokoState は、プレハブのいちばん上の Entity へ移す。3 の重ね方（プレハブのいちばん上の Entity の KokoState に、インスタンスの KokoState を重ねる）で、展開した結果は変換の前と同じになる。
- **プレハブのいちばん上の Entity**：新しい ID。選んだ Entity の KokoState をすべて持つ。Transform は、向きと大きさを写し、場所は原点にする（あとで置くインスタンスが、同じ向きと大きさで出る）。
- **中の Entity**：アウトプットからなくなり、新しい ID でプレハブの中の Entity になる。名前・並び順・値は、そのまま。中にインスタンスがあれば、入れ子のインスタンスとして、そのまま移す。
- **プレハブの名前**：選んだ Entity の名前から。いちばん上のフォルダに同じ名前があれば、番号を付ける。リソースの名前に使えない名前（`/` を含むなど）なら「プレハブ」。
- 変換は、一つの transaction（共同編集の相手に、途中の形が見えない）。

**参照**

- プレハブに移した Entity どうしの参照（フィールドの値。入れ子の値の中も）は、プレハブの中の新しい ID に書き換える。展開のとき、4 の付け替えで、インスタンスの中の ID になる。
- 選んだ Entity を指す参照は、ID が同じなので、そのまま。
- プレハブに移さない Entity（同じアウトプットのもの・ほかのアウトプットのもの・ほかのプレハブの中のもの）から、中の Entity を指す参照は、展開したあとの ID（選んだ Entity の ID `/` プレハブの中の新しい ID）に書き換える。中のインスタンスの中（`D/x`）を指していたものも、頭を付け替える（`選んだ Entity/D の新しい ID/x`）。
- プレハブに移した Entity から、移さない Entity を指す参照は、そのまま残す（4 のとおり、プレハブの中からアウトプットの Entity を指せる）。ほかのアウトプットに置いたインスタンスでは指す先がないので、確認の画面に出す。
- 書き換えは、フィールドの型（スキーマ）が分かるフィールドだけに届く（展開の付け替えと同じ）。

**「維持」の印**

- アウトプットの印のうち、プレハブに移した Entity を指すものは、プレハブの `keep` に移す（Entity は、プレハブの中の新しい ID）。展開のとき、7 の足し合わせで、同じ値を指す印に戻る。
- 選んだ理由：印は「この値は、適用しても引き継ぐ」という、そのものの作りの一部。プレハブに移せば、あとで置くほかのインスタンスにも効く。アウトプットに残す（展開した ID に書き換える）と、初めのインスタンスだけが維持され、同じプレハブなのに動きが分かれる。
- 選んだ Entity の Transform を指す印だけは、アウトプットに残す。Transform はインスタンスそのものが持ち、プレハブには数えないため（3）。
- 中の Entity の印は、ID が変わるので、セッションに出した配置では、次の「適用」のとき一度だけ、いまの値を引き継がない。確認の画面に、そう書く。

**System**

- 初めは、プレハブに含めない（アウトプットの System のまま）。確認の画面で、アウトプットの System から「プレハブにも入れる」ものを選べる。
- 選んだ System は、プレハブの `systems` に、アウトプットの並び順と「入・切」のまま入れる。**アウトプットの並びからは外さない。** 6 のとおり、アウトプットにもある System は、場所も「入・切」もアウトプットのものが勝つので、変換の前とあとで動く順が変わらない。外すと、その System はプレハブのものとしてアウトプットの System のあとへ回り、順番が変わる。
- どの System がその Entity のためのものかは、決めつけない（Query が合うだけでは、ほかの Entity も処理しているかもしれない）。利用者が選ぶ。あとから、プレハブの詳細でも足せる。

**確認の画面と、スクリプトの中の ID**

- 「何を移し、何を書き換えるか」の計画を作る関数（`planPrefabFromEntity()`。制作データは変えない）と、実行（`ProjectDoc.makePrefabFromEntity()`）に分ける。確認の画面は、計画を見せる：プレハブに移る Entity（元の ID → プレハブの中の ID）、書き換える参照（どの Entity の、どのフィールド）、プレハブに移す「維持」の印、プレハブの外を指す参照、プレハブにも入れる System。
- 確認を出している間に制作データが変わったら、計画を作り直す。新しい ID は、初めに出したものを使い続ける（確認に出した ID のまま変換する）。
- System のコードに、中の Entity の ID（変換で変わる ID）が文字として書いてあれば、確認の画面に注意として出す（どの System の、どの Entity か。変換のあとの ID も）。調べ方は、ID の文字が含まれるかどうか。**スクリプトは書き換えない**（文字が同じでも、ID として使っているとは限らない。直すのは利用者）。選んだ Entity の ID は変わらないので、調べない。
- 実行の結果として、計画（元の ID → プレハブの中の ID・展開したあとの ID の対応を含む）を返す。変換のあとは、Hierarchy と Inspector で、どのプレハブのどの Entity から来たかが分かる（展開した Entity の `origin`）。

**断る場合（わけを添える）**

- すでにプレハブのインスタンスである Entity。プレハブから来た Entity（展開で作ったもの）。プレハブの中の Entity（プレハブを開いている間）。ライブラリのアウトプットの Entity。
- 中のインスタンスの中の Entity（展開した ID）を親にしている Entity がある場合（8 の「足した Entity」の形。プレハブの中へ、そのまま移せない）。
- 画面では、Inspector の Entity の操作の「プレハブにする」を、これらの Entity では押せなくする。再生中も押せない。

**最後の保存からの変化**

- 変換は、Entity の変化（選んだ Entity が変わった・中の Entity が消えた・参照を書き換えた Entity が変わった）と、プレハブの追加として出る。ひとまとまりで戻す操作は作らない。出た項目を一つずつ戻すと、変換の前の形になる。
- Entity の変化の丸は、プレハブとのつながり（`instanceOf`）が変わったときにも出す（変換では、KokoState がプレハブへ移って減るだけなので、これがないと丸が出ない）。

## 影響

- 制作データに `prefabs` と `prefabEntities`、Entity に `instanceOf` が増える。古いデータ（これらがない）は、そのまま読める。
- Entity を使う所は、展開した並びを読む。展開せずに `entities` を読むと、インスタンスは Transform だけの Entity に見える。
- Hierarchy・Inspector・空間の表示は、「いま編集しているもの」（アウトプットか、開いているプレハブ）を読む。ストアに、開いているプレハブ（`editingPrefab`）が増える。通信の形は変えない。
- 独立した空間から、別の独立した空間へ移るとき（ワールドを編集していて、プレハブを離れた空間で開くなど）にも、自分の位置を移す。
- 抽出・ライブラリ・エージェントの道具は、まだプレハブを持っていかない（P7・P8）。プレハブを使っているアウトプットを抽出すると、インスタンスは「プレハブがありません」の問題になる。
- 参照の付け替えは、フィールドの型（スキーマ）が分かるフィールドだけに届く。型エラーで読めないフィールドの中の参照は、付け替わらない。
- Entity からプレハブを作ると、中の Entity の ID が変わる（「選んだ Entity の ID / プレハブの中の新しい ID」）。フィールドの値の参照と「維持」の印は書き換えるが、スクリプトに書いた ID は書き換えない。セッションに出した配置では、変換のあとの初めの「適用」のとき、中の Entity の「維持」の値は引き継がれない（いまの値を、新しい ID で引くため。選んだ Entity の値は、ID が同じなので引き継ぐ）。通信の形は変えない。
