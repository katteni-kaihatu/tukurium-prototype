# ADR 0007：リポジトリ・コミット・作品・フォークと抽出（M4）

- 状態：採用（2026-11-03）
- 関連：要件 §3・§9、計画 §2 決定事項、§5「リポジトリの中身」

## リポジトリ（画面上は「プロジェクト」）
- 履歴は Git に保存する。サーバーの `GIT_DATA_DIR` に bare リポジトリを置き、isomorphic-git で blob・tree・commit を直接書く（作業ツリーは持たない）。ブランチは main だけ。
- 中身は 1 要素 1 ファイル（`kokostates/*.json`、`systems/*.json` と `*.js`、`materials/`、`assets/`、`outputs/<id>/output.json`、`outputs/<id>/entities/*.json`、`provenance.json`、`tukurium.json`）。変換は `repo-model` の `toFiles` / `fromFiles`。
- 作ったときの公開範囲は **公開**（既定）。公開なら誰でも見られ、フォーク・抽出できる。非公開は持ち主だけ。

## ワークスペースとの関係
- ワークスペースは必ずリポジトリを持つ。セッションでワークスペースを作るとリポジトリと最初のコミットができる。
- **1 リポジトリにつき同時に開けるワークスペースは 1 つ**。別のセッションで開かれていれば断り、同じセッションならそこに参加する。開いていない間も作業途中の内容（自動保存）は残り、次に開くと続きから。
- **コミットはリポジトリの持ち主だけ**（共同制作者の権限は将来）。そのときワークスペースを開いて共同編集以上の権限を持つ人を `Co-authored-by` として残す。
- 未コミットの変更は、クライアントで最新のコミットのファイルと、いまの制作データのファイルを比べて出す。

## 作品とリリース
- 作品はアウトプットごとの公開の単位で、権限（利用・元データ閲覧・フォーク／抽出）を持つ。初期値は **すべて許可**。持ち主があとから絞れる。
- リリースは、作品の特定のコミットからのバージョン（v1, v2, …）。公開はコミットに固定される。
- 非公開のリポジトリでも、作品の「元データ閲覧」「フォーク／抽出」を許可すれば、その範囲で見せられる。
- 作品の最新リリースを、セッションの「ライブラリ」から置ける（「利用」の権限）。リリースから置いた配置はワークスペースとはリンクしない（適用の対象外）。KokoState の名前の範囲もワークスペースとは別。

## フォークと抽出
- フォークは履歴ごと複製し、由来（元のリポジトリ・コミット）を `provenance.json` とリポジトリの情報に残すコミットを積む。
- 抽出は **アウトプットかリソース（KokoState・System・マテリアル・素材）をチェックボックスで選ぶ**。依存するもの（アウトプットの Entity・System、Entity と System が使う KokoState、マテリアル、素材）は一緒に取り出す。
- 取り込み先は、新しいリポジトリか、自分の既存のリポジトリ。同じ ID で同じ中身ならそのまま、違えば ID を振り直す。KokoState の名前がぶつかれば名前を付け替え、取り出した System のコードの名前も書き換える。
- 由来を追えることと、元の更新を自動で取り込むことは別。後者はしない（要件 §9）。

## 制約・残課題
- 抽出のときの System のコードの書き換えは文字列の置き換え（`"Name"` と `.Name.`）なので、書き方によっては直らない。
- 素材の本体は Git に入れず、ハッシュで参照する（ADR 0006）。
- PR・ブランチ・マージ・revert は見た目だけ。
