# リソースパス・System 参照・全体診断

- 計画する人：れにうむ
- 書き上げた日：2026-11-05

## やりたいこと

- 別のフォルダに同じ名前の KokoState があっても、System から迷わず参照できる。
- System から、リソースを絶対パスや System からの相対パスで書ける。
- KokoState・System・マテリアル・素材・アウトプット・Entity などを変えて起きた問題を、再生する前からプロジェクト全体で確かめられる。
- 問題は、時系列のログの山ではなく「今の制作データに残っている問題」として、原因ごとにまとまって見える。
- この先の型チェック・TypeScript・抽出・フォーク・外のパッケージにも耐える依存の形を作る。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：作品が大きくなっても参照が壊れず、どこに問題があるかがすぐ分かる。
- 原則 5（安心して作れる）：名前を変えたり動かしたりしても、壊れたことに気づき、直せる。
- 原則 4（一度作ったものを、何度でも、誰とでも使える）：同じ名前の部品やライブラリを、取り違えずに組み合わせられる。
