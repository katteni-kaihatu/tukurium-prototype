# 型と説明を見ながらスクリプトを書く

- 状態：完了
- 計画者：れにうむ
- 作成完了日：2026-11-10

## やりたいこと

スクリプトのエディタで、型と説明を手がかりにしながら書ける。VS Code で TypeScript を書くときと同じ手助けを受けられる。

- 変数・式・関数・KokoState のフィールドにマウスを重ねると、その型と説明が小さな枠に出る。これを「コードホバー」と呼ぶ（VS Code の「ホバー」、TypeScript の「Quick Info」にあたるもの）。
- 入力の候補が、型をもとに出る。たとえば `e.get(Gun).` のあとに、Gun のフィールドが型と説明つきで出る。
- `Gun` などの名前から、その定義（KokoState の定義など）を開ける。
- KokoState とそのフィールドに、作者が説明を書ける。書いた説明は、コードホバーと入力の候補に出る。

何が入っているかを、動かしたり宣言を探したりせずに確かめられる。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：慣れていない人も、その場で「これは何か」「何が書けるか」が分かる。慣れた人は、型をたどって深く書ける。
- 原則 3（その場にいない人とも、作品を通じて一緒に作れる）：ほかの人が作った KokoState やライブラリも、作者の書いた説明を読んで使える。
- 原則 5（安心して作れる）：思っていた型と違うことに、動かす前に気づける。

## やること

- **コードホバー**：変数・引数・式・関数（Host API を含む）・import した KokoState とそのフィールドに重ねると、型と説明を出す。型エラーがある所では、誤りの文も一緒に出す。型の書き方は TypeScript のまま（`number`、`string | null` など）。
- **型をもとにした入力の候補**：変数・KokoState のフィールド・Host API などの候補を、型をもとに出す。候補には型と説明を添える。今の import のパスの候補は残す。
- **定義へ移動**：KokoState・System・変数などの名前から、その定義へ移る。KokoState ならその「リソースの詳細」を開き、同じスクリプトの中ならその行へ移る。コードホバーの中の「定義へ移動」と、Ctrl（Mac では Cmd）を押しながらのクリックで移る。ライブラリと Built-in のものは、中身を見られる範囲で開く。
- **KokoState とフィールドの説明**：KokoState の「リソースの詳細」で、KokoState とそのフィールドに説明を書ける。制作データとして保存し、ライブラリとして配ったときも説明が付いていく。公式のライブラリと同梱サンプルの KokoState には説明を書く。AI エージェントも、KokoState を作る・変える道具で、説明を書ける。
- 画面に出したパネルでも、空間に置いたパネルでも使える。
- 型を確かめるのと同じ、ブラウザの裏側（Worker）の TypeScript を使う。画面の本体は大きくしない。

## やらないこと

- 参照を探す・名前の一括変更など、ほかのエディタの機能。
- AI エージェントに、ある場所の型を聞く道具を渡すこと（エージェントは今の確認の道具のまま）。KokoState とフィールドの説明は、エージェントも人と同じく書ける（下の「やること」）。
- 型の書き方を日本語の画面向けに言い換えること。
- スクリプト以外（Inspector のフィールドなど）で説明を出すこと。

## 完了の条件

- 同梱サンプルのスクリプトで、変数・Host API・KokoState のフィールドに重ねると、コードホバーに型と説明が読める形で出る。
- `e.get(Gun).` と打つと、Gun のフィールドが型と説明つきで候補に出る。
- `Gun` から、その KokoState の「リソースの詳細」を開ける。
- KokoState の「リソースの詳細」で書いた説明が、コードホバーと候補に出る。
- 空間に置いたパネルでも、重ねた文字の所にコードホバーが出て、候補を選べる。
- 複数人で同じスクリプトを編集している最中でも、古い内容の型や候補を出さない。
- TypeScript を初めて読み込む間も、待てば出る（読み込み中だと分かる）。

## 決まっていること・決まっていないこと

- 決まっていること：
  - ロードマップの「スクリプトをすべてTypeScriptで書く」で入れた TypeScript（Worker で動く Language Service）を使う。
  - 型の書き方は TypeScript のまま。
  - AI エージェントには、型を聞く新しい道具を渡さない。KokoState とフィールドの説明は、今ある KokoState を作る・変える道具で書ける。
- 設計者・実装者に任せること：枠と候補の見た目、出るまでの待ち時間、今の Host API の候補を型の候補にまとめるか、説明の保存の形。
- 計画者に聞くこと：なし。
