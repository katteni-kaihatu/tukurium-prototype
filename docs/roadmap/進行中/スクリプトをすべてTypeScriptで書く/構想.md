# スクリプトをすべてTypeScriptで書く

- 状態：完了
- 計画者：れにうむ
- 作成完了日：2026-11-08

## やりたいこと

作品のスクリプトは、すべて TypeScript で書く。型チェックと入力補完で、動かす前に間違いに気づける。人も AI エージェントも同じように書く。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：入力補完で始めやすく、型で大きなコードも作り込める。
- 原則 5（安心して作れる）：動かす前に間違いに気づける。

## やること

- 新しく作る System は TypeScript で書く。
- Host API・KokoState の欄・ライブラリの KokoState・Contract の受け渡しに型が付き、入力補完と型チェックが効く。
- 型の誤りは、エディタと問題の一覧に出る。
- 型の誤りがあっても、再生は止めない（作っている途中の問題では再生を止めない。ADR 0010）。
- 実行時の誤りは、TypeScript の場所に戻して示す。
- AI エージェントも TypeScript で書き、人と同じように型の誤りを受け取る。
- 公式のもの（同梱サンプル・公式ライブラリ）を TypeScript に置き換える。
- それ以外の今あるスクリプトは移さない。TypeScript として扱い、型の誤りが出てよい。

## やらないこと

- npm のパッケージや、その型定義を取り込むこと
- 利用者が型チェックの設定（tsconfig）を変えること
- JavaScript で書けるまま残すこと
- System 以外のスクリプトのファイル（共通の処理をまとめたファイル）を作れるようにすること（ロードマップの「共通の処理をまとめたスクリプトを複数のSystemから使う」）

## 完了の条件

- 公式のサンプルとライブラリが TypeScript で書かれていて、今と同じように動く。
- 新しい System を作ると TypeScript で始まり、KokoState の欄の名前や型の間違いがエディタで分かる。
- 型の誤りと実行時の誤りが、問題の一覧から TypeScript の場所へ移れる。
- AI エージェントが TypeScript で書いた System も、人のものと同じように型チェックされる。

## 決まっていること・決まっていないこと

- 決まっていること：
  - スクリプトはすべて TypeScript で書く。もとの計画の「型付きの JavaScript の必要性を確かめてから、TypeScript を正式な形式にするかを決める」はやめる。
  - 公式のものは TypeScript に置き換え、それ以外は移さない。
  - 型の誤りがあっても再生は止めない。
- 設計者・実装者に任せること：TypeScript をどこでどう JavaScript に変えるか、どの道具を使うか、Git での保存の形。
- 計画者に聞くこと：特になし。
