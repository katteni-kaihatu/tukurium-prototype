## 作り方の方針

### 今の仕組み（調べた結果）

- スクリプトを JavaScript として扱う入口は、ほぼ `compileSystem()`（`packages/repo-model/src/systemCompiler.ts`）一つに集まっている。acorn で import を読み、KokoState の import を安定 ID に書き換える。行の数を保つ書き換えなので、実行時の誤りの行番号がそのまま元のコードの行になる。
- `compileSystem()` を呼ぶ所：実行（`packages/runtime` の Simulation。ホストのブラウザとサーバーの試し動かし）、編集中の確認（`apps/client` の `checkScripts`）、エージェントの確認（`apps/server/src/agent/tools.ts`）、依存グラフ・参照の診断・抽出（repo-model）。
- 実行は QuickJS が ES モジュールとして読む（`packages/script` の `loadSystem`）。
- Host API の型の宣言（`.d.ts`）は `hostApiDeclarations()` で作っている。ただし `system<T>(def: T): T` と型が付かず、Entity や KokoState の欄には型がない。
- エディタは CodeMirror の JavaScript モード。Host API と import の入力補完は自前で出している。
- Git には `systems/<ID>.js` として保存している。
- 公式のサンプルの一部（「銃と的」の Shoot など）は、まだ名前で書いた Query（`with: ["Gun"]`、`e.Gun`）を使っている。

### 方針

1. **型を消すのと、型を確かめるのを分ける。**
   - 型を消して JavaScript にする処理は、`compileSystem()` の最初で行う。軽く、行の位置を保つ道具を使う（候補：sucrase。型を消しても行番号が変わらない）。これで、実行・確認・エージェント・抽出のどの道も、今の仕組みのまま TypeScript を読める。実行時の誤りの行も、そのまま TypeScript の行になる（source map が要らない）。
   - 型の確かめは、TypeScript の本体（`typescript` パッケージの Language Service）で、別に行う。重いので、ブラウザでは Web Worker で、使うときに読み込む。サーバーでは Node で動かす。
2. **型の確かめは新しいパッケージにまとめる。** `packages/typecheck`（仮）に、制作データと依存の中身から型の誤りを `Diagnostic` で返す純粋な関数を置き、ブラウザの Worker とサーバーの両方から使う。
   - 制作データの KokoState は、論理パスに合わせた仮想のファイル（例：`/Combat/States/Gun.koko.d.ts`）として宣言する。TypeScript は `import Gun from "../States/Gun.koko"` を、この宣言に結び付けられる。Built-in（`@builtin/`）とライブラリ（`@別名/`）も同じように宣言する。
   - Host API の宣言（`hostApiDeclarations()`）に、System・Entity・KokoState の型を足す。`system()` に渡す定義から、Query に書いた KokoState と `e.get(Gun)` の欄の型が分かるようにする。
3. **型の誤りは再生を止めない。** 「作っている途中の問題」（ADR 0010）として問題の一覧とエディタに出すだけにする。型を消す段階の構文の誤りは、今と同じく読み込めない問題として出す。
4. **保存の形を変える。** Git には `systems/<ID>.ts` として保存する。読むときは `.js` も受け付ける（プロトタイプなので互換は求めないが、手間が小さいので受け付ける）。
5. **大きな判断は ADR に残す**（道具の選び方、型の確かめの場所、名前で書いた Query の扱い、厳しさの設定）。

## 確かめ方

- 単体テスト：型を消しても行番号が変わらないこと、TypeScript の書き方（型注釈・interface・`as` など）で書いた System が QuickJS で動くこと、KokoState の欄の名前と型の誤りが問題として出ること、型の誤りがあっても再生が止まらないこと。
- 背骨の E2E：T1 のあとと T5 のあとに流す（m1 はエディタでスクリプトを書くので、TypeScript になっても通ることを確かめる）。
- 画面：エディタに型の誤りが出ること、問題の一覧から TypeScript の行へ移れることを、使い捨てのスクリプトのスクリーンショットで確かめる。
