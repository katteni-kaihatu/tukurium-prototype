## 作り方の方針

### 今の仕組み（調べた結果）

- スクリプトを JavaScript として扱う入口は、ほぼ `compileSystem()`（`packages/repo-model/src/systemCompiler.ts`）一つに集まっている。acorn で import を読み、KokoState の import を安定 ID に書き換える。行の数を保つ書き換えなので、実行時の誤りの行番号がそのまま元のコードの行になる。
- `compileSystem()` を呼ぶ所：実行（`packages/runtime` の Simulation。ホストのブラウザとサーバーの試し動かし）、編集中の確認（`apps/client` の `checkScripts`）、エージェントの確認（`apps/server/src/agent/tools.ts`）、依存グラフ・参照の診断・抽出（repo-model）。
- 実行は QuickJS が ES モジュールとして読む（`packages/script` の `loadSystem`）。
- Host API の型の宣言（`.d.ts`）は `hostApiDeclarations()` で作っている。ただし `system<T>(def: T): T` と型が付かず、Entity や KokoState の欄には型がない。
- エディタは CodeMirror の JavaScript モード。Host API と import の入力補完は自前で出している。
- Git には `systems/<ID>.js` として保存している。
- 公式のサンプルの一部（「銃と的」の Shoot など）は、まだ名前で書いた Query（`with: ["Gun"]`、`e.Gun`）を使っている。

### 方針

1. **型を消すのと、型を確かめるのを分ける。**
   - 型を消して JavaScript にする処理は、`compileSystem()` の最初で行う。軽く、行の位置を保つ道具を使う（候補：sucrase。型を消しても行番号が変わらない）。これで、実行・確認・エージェント・抽出のどの道も、今の仕組みのまま TypeScript を読める。実行時の誤りの行も、そのまま TypeScript の行になる（source map が要らない）。
   - 型の確かめは、TypeScript の本体（`typescript` パッケージの Language Service）で、別に行う。重いので、ブラウザでは Web Worker で、使うときに読み込む。サーバーでは Node で動かす。
2. **型の確かめは新しいパッケージにまとめる。** `packages/typecheck`（仮）に、制作データと依存の中身から型の誤りを `Diagnostic` で返す純粋な関数を置き、ブラウザの Worker とサーバーの両方から使う。
   - 制作データの KokoState は、論理パスに合わせた仮想のファイル（例：`/Combat/States/Gun.koko.d.ts`）として宣言する。TypeScript は `import Gun from "../States/Gun.koko"` を、この宣言に結び付けられる。Built-in（`@builtin/`）とライブラリ（`@別名/`）も同じように宣言する。
   - Host API の宣言（`hostApiDeclarations()`）に、System・Entity・KokoState の型を足す。`system()` に渡す定義から、Query に書いた KokoState と `e.get(Gun)` の欄の型が分かるようにする。
3. **TypeScript の厳しい判定をすべて入れる**（`strict: true`。計画者と決めた）。
4. **名前で書いた Query をやめる**（計画者と決めた）。`with: ["Gun"]` のような文字列の Query と、`e.Gun` のような名前での読み書きは、読み込めない問題（エラー）にする。KokoState は import して使う。
5. **`e.get()` で触れるのは、Query に書いた KokoState だけにする**（計画者と決めた）。型の上でも（Query に書いていない KokoState を渡すと型の誤り）、実行でも（Query にない KokoState を渡すと誤りにする）、同じ決まりにする。
6. **型の誤りは再生を止めない。** 「作っている途中の問題」（ADR 0010）として問題の一覧とエディタに出すだけにする。型を消す段階の構文の誤りは、今と同じく読み込めない問題として出す。
7. **保存の形を変える。** Git には `systems/<ID>.ts` として保存する。読むときは `.js` も受け付ける（プロトタイプなので互換は求めないが、手間が小さいので受け付ける）。
8. **大きな判断は ADR に残す**（道具の選び方、型の確かめの場所、名前で書いた Query をやめること、`e.get()` の決まり、厳しさの設定）。ADR 0010 の「移行の間は名前で書いた Query も動く」は、新しい ADR で置き換える。

## 確かめ方

- 単体テスト：型を消しても行番号が変わらないこと、TypeScript の書き方（型注釈・interface・`as` など）で書いた System が QuickJS で動くこと、名前で書いた Query が読み込めない問題になること、Query にない KokoState を `e.get()` すると誤りになること、KokoState の欄の名前と型の誤りが問題として出ること、型の誤りがあっても再生が止まらないこと。
- 背骨の E2E：T1・T3・T7 のあとに流す（m1 はエディタでスクリプトを書くので、TypeScript と import の書き方で通ることを確かめる）。
- 画面：エディタに型の誤りが出ること、問題の一覧から TypeScript の行へ移れることを、使い捨てのスクリプトのスクリーンショットで確かめる。

## 分かったこと・残り

- T5：`typecheck.worker.ts` で `TypeChecker` を動かす。標準ライブラリの宣言（`lib.es*`・`lib.decorators*`）と日本語の文は Worker に同梱する。`useTypeCheck()` が、ワークスペースを開いて初めて Worker を作り、制作データが変わるたびに 0.6 秒待って全部の System を確かめ直す（変わっていないファイルの解析は Language Service が使い回すので、影響を受ける System だけに絞る仕組みは入れていない）。結果は `typeProblems` に入れ、問題の一覧とエディタのコードの下に出す。型の誤りは書いている途中にたくさん出るので、エラーパネルを自動で開く合図にはしない。本番ビルドでは TypeScript の本体は Worker の chunk（約 4.7 MB）だけに入り、画面の本体の大きさはほぼ変わらない。
- T4：`hostApiDeclarations()` に、`KokoState<Id, F>`（ID と欄の型を持つ）・`FieldsOf<K>`・`SystemEntity<Q>`・`SystemDef<W>`・`system()` の型を足した。`e.get()` は `[K] extends [Q]` で Query の with に書いた KokoState だけを受け、違えば「queryのwithに書いていないKokoStateです」という印の型の誤りを一つだけ出す。`world.get()`・`world.set()` も KokoState の欄の型を返す・受ける形にした。`packages/typecheck` の `TypeChecker` は、KokoState を論理パスに合わせた `*.koko.d.ts`、Built-in を `/__builtin/`、ライブラリを `/__packages/<別名>/` に置き、paths でつなぐ。TypeScript 6.0 はリポジトリの開発用の TypeScript 7 とぶつからないよう、`typescript6`（`npm:typescript@6.0.3`）の名前で入れた。日本語の文は TypeScript の内部の関数（`setLocalizedDiagnosticMessages`）で差し替える。公式のもの（公式ライブラリ 3 つ・それを使うサンプル 3 つ・マルバツ・銃と的）が、厳しい判定で型の誤りがないことをテストで守る。マルバツには型を書き足し、`world.spawn()` の states のキーは `[Transform.id]` と書く形にした。
- T3：Query に文字列を書くと、`system()` の定義を読むところ（`__define`）で「名前の文字列は使えません」の誤りにし、読み込めない問題にする。`e.get()` は import した KokoState だけを受け、Query の with にないものは誤りにする。`e.名前` と `e[ID]` での読み書きはなくした。スクリプトに渡す Entity の状態も、Query の with に書いた KokoState だけにした。`e.get()` と `e.名前` のどちらにするかは計画者と相談し、名前を変えても同じ名前があっても壊れない `e.get()` にした。名前で書いた Query のための依存グラフの名前の節・`parseQuery()`・抽出の名前の読み替えも片付けた。Host API（`world.get(id, "Target")` など）の名前での指定はそのまま。
- T2：公式ライブラリ（combat・interaction・items）と、そのサンプル、マルバツは、もとから import で書いた Query と `e.get()` だった。名前で書いた Query が残っていたのは「銃と的」（「銃」「射撃場」も同じコード）の Shoot と TargetHit だけで、これを import と `e.get()` に書き直した。型を書き足すのは、System の型の宣言ができる T4 で行う（今は型を書かなくても文脈から決まる形にしている）。
- T1：型を消すのは `stripTypes()`（repo-model）。`compileSystem()` の最初で呼び、書き方の誤りは `script-syntax` の問題（行つき）にする。import のパスの範囲は `rangeInSource()` で元のコードの範囲に戻す（名前の変更での書き直し・抽出の書き直しが、TypeScript のコードにそのまま効く）。`inferCapabilities()`・`readSystemQuery()`・`rewriteImports()` も型を消してから読む。編集中の確認は、import がなくても必ず `compileSystem()` を通す。sucrase は repo-model と、実行時に使うサーバーの dependencies に入れた。新しい System の雛形はもとから TypeScript として正しいので変えていない。
- T0：型を消す道具は sucrase、型を確かめる道具は TypeScript 6.0 系の Language Service にした（ADR 0058）。リポジトリの開発に使う TypeScript 7 はブラウザでは動かないため。試した結果も ADR に残した。
