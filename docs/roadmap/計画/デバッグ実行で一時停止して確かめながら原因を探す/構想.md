# デバッグ実行で一時停止して確かめながら原因を探す

- 状態：完了
- 計画者：れにうむ
- 作成完了日：2026-11-10

## やりたいこと

ワークスペースの再生をデバッグ実行にして、決めた条件で一時停止し、その時点の変数や KokoState の値を確かめ、ステップ実行で 1 行ずつ進めたり値を変えたりできる。VS Code のデバッグ（デバッグ実行・ブレイクポイント・ステップ実行）と同じ体験を、一緒に作っている全員で共有する。

今は、思ったとおりに動かないとき、`log()` を書き足して再生し直すしかない。一時停止して中を見られれば、どこで何が違っているかを、書き足さずに確かめられる。一時停止した所は参加者全員に見えるので、一緒に原因を探せる。

## 原則とのつながり

- 原則 1（作る場所と遊ぶ場所が同じ）：遊びながら作っている場で、そのまま一時停止して中を見られる。
- 原則 2（入口は低く、奥は深い）：慣れた人は、一時停止して値をたどって、込み入った処理も直せる。
- 原則 5（安心して作れる）：うまく動かない理由を、推測でなく確かめて直せる。

## やること

### デバッグモードとデバッグ実行

- デバッグモードを入れて再生することを、デバッグ実行と呼ぶ。デバッグ実行では、一時停止の条件で一時停止する。
- デバッグ用のパネルのいちばん上にあるトグルで入れたり切ったりする。切り替えは再生を始める前に行う（再生の途中で切り替えられなくてよい）。
- トグルはワークスペースの参加者全員で共有する。誰かが入れると全員の再生がデバッグ実行になる。
- 一時停止の条件とログポイントは、デバッグモードのときだけ働く。
- デバッグモードを入れている間だけ、エディタのブレイクポイント・ログポイントの印が出る。一時停止の条件やログポイントを足す操作（行番号の横を押す、右クリックの項目など）も、その間だけ使える。
- デバッグモードを切っても、一時停止の条件とログポイントは消えない。次に入れたときに、そのまま出る。

### デバッグ用のパネル

- ほかのパネルと同じく、ワークスペースのパネルの一覧から、いつでも開いたり閉じたりできる。
- デバッグモードが切れているときは、トグルと短い説明（例：「一時停止の条件 3 件。デバッグモードを入れると働きます」）だけを出す。
- デバッグモードが入っているときは、一時停止の条件の一覧、一時停止したときの値・呼び出しの順・操作のボタンを出す。
- 誰かがデバッグモードを入れても、ほかの人の画面でパネルが勝手に開くことはない。再生の操作のそばに「デバッグモード」と出して、入っていることを全員に知らせる。そこを押すと、デバッグ用のパネルが開く。

```
┌ デバッグ ─────────────────────────────────────┐
│ デバッグモード  [ 入 ]                            │
│                                                   │
│ 一時停止の条件　（どれか一つに当てはまったら一時停止する）│
│  [✓] 1. コードの行：Shoot.ts 12 行目               │
│  [✓] 2. 欄の変化：Health.hp かつ Entity：的 3      │
│  ＋ 一時停止の条件を足す                          │
│                                                   │
│ （一時停止したとき：値・呼び出しの順・操作のボタン）│
└───────────────────────────────────────────────────┘
```

### 一時停止の条件

デバッグ用のパネルに、一時停止の条件を一つずつ並べる。**一時停止の条件どうしは OR**（どれか一つに当てはまったら一時停止する）、**一つの一時停止の条件の中は AND**（中の条件が全部そろったら一時停止する）。

```
一時停止の条件　（どれか一つに当てはまったら一時停止する）

 [✓] 1. コードの行：Shoot.ts 12 行目
 [✓] 2. 欄の変化：Health.hp   かつ   Entity：的 3
 [ ] 3. コードの行：Hit.ts 8 行目   かつ   Entity：銃 A   かつ   式：damage > 10
 [✓] 4. 欄の変化：Health.hp   かつ   式：新しい値 <= 0
 [✓] 5. 実行中のエラー
```

一つの一時停止の条件には、きっかけを必ず一つ入れ、絞り込みを足せる（絞り込みだけでは、いつ一時停止するかが決まらないため）。

| 種類 | 中身 |
| --- | --- |
| きっかけ：コードの行 | スクリプトのその行に来たら一時停止する。エディタの行番号の横に印（ブレイクポイント）が出る |
| きっかけ：欄の変化 | KokoState の欄（例：`Health.hp`）が書き換わったら、書き換えた行のすぐあとで一時停止する。物理など、スクリプト以外が書き換えたときは、一時停止する行の代わりに出どころを出す。同じ値を書いたときは一時停止しない。`e.get()` と `world.set()` のどちらから書き換えても一時停止する |
| きっかけ：実行中のエラー | スクリプトが実行中にエラーを起こしたら、その行で一時停止する |
| 絞り込み：Entity | その Entity を処理しているとき（欄の変化なら、その Entity の欄が変わったとき）だけ |
| 絞り込み：式 | 式が成り立つときだけ（例：`damage > 10`）。欄の変化では、前の値と新しい値を使える |

- 一時停止の条件ごとにチェックを外して休ませられる。休んでいるものは消えず、エディタの印も休んでいると分かる見た目になる。
- 一時停止の条件はワークスペースの上のもので、参加者全員で共有する。保存の履歴やリリースには含めない。
- デバッグ実行でないときは、実行中のエラーは今と同じように「エラー」パネルに記録して先へ進む。

### 一時停止の条件の足し方

どれも、デバッグモードを入れている間だけ使える。

| 足す場所 | 操作 | 足されるもの |
| --- | --- | --- |
| スクリプトのエディタ | 行番号の横を押す | 「コードの行」の一時停止の条件（ブレイクポイント） |
| スクリプトのエディタ | 行番号の横を右クリック →「ログポイント」 | ログポイント |
| 空間・Hierarchy | Entity を右クリック →「このときだけ一時停止する」 | パネルで選んでいる一時停止の条件に「かつ Entity」 |
| 一時停止しているときの値 | 欄を右クリック →「変わったら一時停止する」 | 「欄の変化」の一時停止の条件 |
| デバッグ用のパネル | 「一時停止の条件を足す」「かつ」を押す | 新しい一時停止の条件、その中への条件 |

### ログポイント

一時停止せずに、書いた文や式の値を「ログ」に書き出す。デバッグモードのときだけ書き出す。

### 一時停止したとき

- 再生がまるごと一時停止する。ほかの参加者の再生も一時停止し、どの条件で、どのスクリプトの何行目で一時停止しているかが全員に見える。
- 一時停止した行と、変数・引数・`e.get()` で読んだ KokoState の値が見える。欄の変化で一時停止したときは、前の値と新しい値（例：「`hp`：10 → 0」）と、書き換えた System と行（スクリプト以外なら出どころ）が分かる。
- 処理している途中の Entity が、3D 空間で光って分かる。
- 呼び出しの順（どの関数からどの関数を呼んで今の行に来たか）が並び、選ぶとその時点の行と値を見られる。
- 値は、デバッグ用のパネルと、コードホバー（重ねた変数の今の値）で見られる。

### 一時停止してからの操作

デバッグ実行で一時停止したときにできる。一時停止の条件に当てはまったときも、一時停止のボタンを押したときも同じ。ボタンで一時停止したときはフレームの切れ目で一時停止しているので、そこからステップ実行すると、次に動くスクリプトの最初の行で一時停止する。

- 続ける（次に条件に当てはまるまで動かす）
- ステップ実行（1 行ずつ進める）：次の行へ（ステップオーバー）・関数の中に入る（ステップイン）・関数から出る（ステップアウト）を選べる
- 次のフレームまで進める
- 変数や KokoState の値を変えて、続きを動かす（変えるのは実行状態だけで、制作データは変わらない）

### そのほか

- デバッグモードの切り替え、一時停止の条件とログポイントを足す・外す、一時停止した再生を進めるのは、共同編集か管理の権限がある人。
- 画面に出したパネルでも、空間に置いたパネルでも使える。

## やらないこと

- セッションに出した配置（みんなで遊んでいるもの）を一時停止すること。
- AI エージェントに、一時停止の条件を足したり一時停止したときの値を受け取ったりする道具を渡すこと。
- 一時停止する前に戻る（巻き戻し）こと。
- System の中の変数（関数の中の `const` など）が変わったら一時停止すること。必要なときは「コードの行」かつ「式」で代わりにする。

## 完了の条件

- 同梱サンプルをデバッグ実行し、スクリプトの行にブレイクポイントを置くと、その行で一時停止し、デバッグ用のパネルとコードホバーで変数と KokoState の値が見える。
- デバッグモードを切って再生すると、一時停止の条件があっても一時停止せず、ログポイントも書き出さない。
- デバッグモードを切っている間は、デバッグ用のパネルにはトグルと説明だけが出て、エディタのブレイクポイント・ログポイントの印も出ず、足す操作もできない。入れ直すと、前の一時停止の条件とログポイントがそのまま出る。
- 一人がデバッグモードを入れても、ほかの人の画面でパネルは勝手に開かず、再生の操作のそばの「デバッグモード」の表示から開ける。
- デバッグモードにしないときの再生は、今と同じ速さで動く。
- 一時停止の条件どうしは OR、一つの一時停止の条件の中は AND で働く。休ませた一時停止の条件では一時停止しない。
- 欄の変化で、欄が別の値に書き換わった瞬間に一時停止し、前の値と新しい値、書き換えた System と行（スクリプト以外なら出どころ）が分かる。同じ値を書いたときは一時停止しない。Entity と式で絞れる。
- 実行中のエラーで、エラーが起きた行で一時停止し、その時点の値が見える。
- 一時停止したとき、処理している途中の Entity が空間で光り、呼び出しの順が見え、選んだ時点の行と値に移れる。
- ステップ実行（次の行へ・関数の中に入る・関数から出る）・次のフレームまで進める・続ける、がそれぞれできる。
- デバッグ実行中にボタンで一時停止したときも、ステップ実行で次に動くスクリプトの最初の行から進められる。
- 一時停止している間に値を変えて続けると、変えた値で動く。
- ログポイントは一時停止せずにログへ書き出す。
- 共同編集の権限を持つ 2 人が同じワークスペースにいるとき、一人が足した一時停止の条件と入れたデバッグモードがもう一人にも見え、一時停止すると両方の再生が一時停止し、どちらからも進められる。
- 一時停止の条件は、保存の履歴にもリリースにも入らない。
- 一時停止している間に再生を動かしているホストが抜けても、再生が壊れない。

## 決まっていること・決まっていないこと

- 決まっていること：
  - デバッグモードはトグルで切り替え、参加者全員で共有する。再生の途中では切り替えなくてよい。
  - 一時停止の条件とログポイントは、デバッグモードのときだけ働く。
  - デバッグモードのトグルは、デバッグ用のパネルに置く。パネルはいつでも開け、デバッグモードが切れている間はトグルと説明だけを出す。
  - エディタのブレイクポイント・ログポイントの印と、足す操作は、デバッグモードのときだけ出る。切っても一時停止の条件とログポイントは消えない。
  - 誰かがデバッグモードを入れても、ほかの人の画面でパネルは勝手に開かない。入っていることは、再生の操作のそばの表示で全員に知らせる。
  - 一時停止の条件どうしは OR、一つの一時停止の条件の中は AND にする。きっかけはコードの行・欄の変化・実行中のエラーの 3 つで、一つの一時停止の条件に必ず一つ入れる。絞り込みは Entity と式。
  - 欄の変化は KokoState の欄が対象で、同じ値を書いたときは一時停止しない。式では前の値と新しい値を使える。
  - 一時停止すると、そのワークスペースの再生は参加者全員で一時停止する。
  - 一時停止の条件はワークスペースの上のもので、参加者全員で共有し、保存の履歴やリリースに含めない。
  - 操作できるのは、共同編集か管理の権限がある人。
  - 値は、デバッグ用のパネルとコードホバーで見せる。
  - デバッグモードにしないときの再生は、今より遅くしない。デバッグモードの間は遅くなってもよい。
  - AI エージェントには、新しい道具を渡さない。
  - ワークスペースの再生にはすでに一時停止があり、それを土台にする。デバッグ実行中は、ボタンでの一時停止からもステップ実行に入れる。
  - ロードマップの「型と説明を見ながらスクリプトを書く」を先に終える（一時停止している間の値を、コードホバーでも見せるため）。
- 設計者・実装者に任せること：
  - 一時停止する仕組み。スクリプトは QuickJS（`quickjs-emscripten-core` の同期版）で、フレームごとに System を呼んでいる。行の途中で一時停止して続けるには、非同期版（asyncify）に変える、実行を Worker に移して待たせる、などが要る。デバッグモードにしない再生を遅くしない作りにする。まずここを確かめる。
  - 一時停止している間のホストの引き継ぎ、物理と時間の扱い。
  - 式で、値を書き換えてしまわないようにする方法。式の中の「前の値」「新しい値」の書き方。
  - 欄の書き換えを見張る方法。スクリプト以外（物理・Built-in の処理など）が書き換えたときの、出どころの見せ方。
  - 再生の途中で生まれた Entity（Hierarchy にないもの）の選び方。
  - デバッグ用のパネルの形。
- 計画者に聞くこと：なし。
