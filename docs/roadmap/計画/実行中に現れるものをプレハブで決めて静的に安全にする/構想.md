# 実行中に現れるものをプレハブで決めて静的に安全にする

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

実行中に作品の形を変える操作（Entity を作る・消す）を、プレハブのインスタンスに限る。こうすると、作品の中に、どんな形の Entity が、どんな KokoState を持って現れうるかが、制作データ・プレハブ・インターフェイスから、すべて静的に分かる。

あわせて、消えうるものを指す参照を、型の上で「いつでも消えうるもの」として扱う。静的に確かめて問題がなかったスクリプトが、実行中に、消えたものを指して壊れることがないようにする。

## 原則とのつながり

- 原則 5（安心して作れる）：型の確かめを通ったスクリプトは、実行中に、なくなったものを指して壊れない。
- 原則 2（入口は低く、奥は深い）：何が現れうるかが分かるので、型の候補・コードホバー・デバッグが、実行中のものにも正しく働く。

## やること

### Entity を作る

- 実行中に作れるのは、プレハブのインスタンスだけにする。プレハブから値を渡して作る `Prefab.spawn(Bullet, パラメータの値)` と、作ったインスタンスを消す `Prefab.destroy` は、ロードマップの「プレハブを型で扱ってコードからインスタンスを作る」で先に作る。
- この項目では、名前と KokoState を文字で指定して、どんな Entity でも作れる今の `world.spawn` を使えなくする。

### Entity を消す

- 実行中に消せるのは、実行中に作ったインスタンスだけにする。制作データに置いた Entity は消せない。作ったインスタンスを消す `Prefab.destroy` は、先の項目で作る。この項目では、ID の文字で何でも消せる今の `world.destroy` を使えなくする。
- 消せるもの（例：公式ライブラリ items の「拾うと消える」もの）は、実行中に作るインスタンスとして置く。たとえば、拾えるものの一覧を KokoState のフィールドに持ち、ロードマップの「プレハブのリストから子を組み立てる」のリストから作る。拾ったら一覧から外すと、消える。どう置くかは設計者に任せる。

### 作る・消す・切り替えるのは、すぐ

- 作る・消す・切り替えるのはすぐ行い、System に渡す前に確かめ、`e.get()` の書き込みもその場で届く。この仕組みは、ロードマップの「プレハブを型で扱ってコードからインスタンスを作る」で先に作る。この項目では、型で守ることだけを足す。

### KokoState を付ける・外す

- 実行中に、KokoState を付けたり外したりすることはやめる。付いていない KokoState に書こうとしたら、型エラーにする（型で分からないときは、書かずに問題として出す）。
- 持つ KokoState を変えたいときは、リストの中のプレハブを替えて切り替える（ロードマップの「プレハブのリストから子を組み立てる」）か、子のインスタンスを作る・消すことで表す。

### 参照

- **ID の文字で Entity を指すことはやめる。** Entity は、型の付いた参照（`EntityRef`・`KokoStateRef`・`FieldRef` など）でだけ指す。
- **いつでも消えうるもの**：実行中に作ったインスタンス（とその中の Entity・KokoState・フィールド）を指す参照は、型の上で「いつでも消えうるもの」として扱う。作ったインスタンスは、インスタンス型の消えうる参照として扱う（`Prefab.spawn` の戻り値も）。リストの切り替えで消えるものも、ここに入る。
  - 参照から値を読み書きするたびに、結果を確かめる形にする（例：`{ status: "ok", value }` か `{ status: "gone" }`、または `値 | undefined`）。
  - 参照は、値そのもの（オブジェクト）を持ち続けない。一度確かめても、そのあとで消えることがあるので、読み書きは毎回、参照を通して行う。読んだ値は写しなので、あとで消えても壊れない。書くときに消えていたら、結果で分かる。
- **消えないもの**：制作データに置いた Entity（プレハブのインスタンスと、その中の Entity を含む）は、実行中に消えない。制作データに置いたインスタンスは切り替えないので、中のものも消えない。そこを指す参照は、今のまま、消えうるものとしては扱わない。
- **Entity を受け取ったり返したりする Host API とイベントは、すべて型の付いた参照にする**（例：`world.get`・`world.set`・`world.destroy` の引数、`world.raycast` の当たった Entity、`Prefab.spawn` の戻り値、Query の `e.id`、`Interact` や `onCollision` で渡される相手）。実行中に作ったものを指す場合は、消えうる参照にする。
- **どれが来るか分からない相手**：`onCollision` でぶつかった相手や、`world.raycast` で当たったものは、自分の制作データの Entity（消えない参照）・実行中に作ったインスタンス（消えうる参照）・ほかの作品（窓口）・プレイヤーのどれでもありうる。これらは、種類を見分けられる形（`{ kind: "player", … }` のような、種類の付いた組み合わせ）で渡す。スクリプトは、種類を確かめてから使う。
- 名前で探す `world.find` はやめる。探していたものは、フィールドの参照（`EntityRef` など）で指す形にする（例：マルバツのマスや表示）。

### ほかの作品とのやり取り

- ほかの作品には、専用の API（Contract など）でだけ働きかける。ほかの作品の Entity や KokoState を、直接指したり読み書きしたりすることはなくす。
- ほかの作品とやり取りするための「窓口」の参照を用意する。`world.raycast` は、ほかの作品に当たったら、Entity ではなく窓口を返す。Contract は窓口に送る。
- 窓口は、相手がいなくなりうるので、消えうる参照と同じく、使うたびに結果を確かめる。

### プレイヤー

- プレイヤーは、セッションに入ったり出たりするので、消えうる参照として扱う。`Interact` などのイベントで渡される押した人や、プレイヤーに働きかける Host API（バッグなど）は、この参照を使う。

### AI エージェント

- 制作データを編集する道具は、今のまま ID や名前で Entity を指してよい（制作データの Entity は消えないため）。
- 実行中に働く道具（試しに動かす道具など）だけを、同じ決まりに合わせる。

### 危ないものに印を付ける

- 静的に危ない Host API と書き方には、安全な書き方ができるのを待たずに、先に TypeScript の `@deprecated` を付け、理由と代わりの書き方を書く（エディタで打ち消し線が出て、コードホバーで理由が読める）。代わりの書き方がまだないものは、「代わりの書き方は追加予定」と書き、できたら書き換える。
  - 付けるのは、ロードマップの「プレハブを型で扱ってコードからインスタンスを作る」の始め（プレハブの続きの項目のいちばん初め）。
  - 例：名前と KokoState を文字で指定する `world.spawn`、制作データの Entity も消せる `world.destroy`、名前で探す `world.find`、Entity を ID の文字で受け取る・返す Host API。
- この項目の終わりに、`@deprecated` を付けたものを使えなくする（型エラーにする）。

### 公式のものと既存のもの

- プロトタイプなので、今ある作品やスクリプトは壊れてよい。
- 公式ライブラリと同梱サンプルは、新しい仕組みで作り直す（例：マルバツの駒を作る所、公式ライブラリ items の「拾うと消える」所）。

## やらないこと

- 実行中に KokoState を付けたり外したりすること（必要になったら、「あってもなくてもよい KokoState」をプレハブに書ける形で、別に検討する）。

## 完了の条件

- 実行中に作れるのはプレハブのインスタンスだけになり、名前と KokoState を文字で指定して作る書き方は型エラーになる。
- 制作データに置いた Entity を消そうとすると型エラーになる。実行中に作ったインスタンスは消せる。
- 実行中に作ったインスタンスを指す参照は、読み書きのたびに結果を確かめる型になり、確かめずに使うと型エラーになる。消えたあとの読み書きは、結果で「消えている」と分かり、スクリプトは壊れない。
- ID の文字で Entity を指す書き方と、`world.find` は使えない（型エラー）。
- マルバツは、駒をプレハブのインスタンスとして作り、マスや表示をフィールドの参照で指す形で動く。
- 公式ライブラリ items の拾えるものは、実行中に作るインスタンスとして置かれ、拾うと消える。
- 公式ライブラリと同梱サンプルが、型エラーなしで動く。
- ほかの作品には窓口の参照でだけ働きかけ、プレイヤーは消えうる参照で扱われる。ぶつかった相手と当たったものは、種類を確かめてから使う形になる。

## 決まっていること・決まっていないこと

- 決まっていること：
  - 実行中に作れるのはプレハブのインスタンスだけ。消せるのは、実行中に作ったインスタンスだけ。
  - 実行中に KokoState を付けたり外したりしない。
  - ID の文字で Entity を指すことはやめ、型の付いた参照でだけ指す。
  - 実行中に作ったインスタンスを指す参照は、いつでも消えうるものとして扱い、読み書きのたびに結果を確かめる。
  - 作る・消す・切り替えるのはすぐ行う仕組みは、インターフェイスの項目で先に作る。
  - 静的に危ない Host API と書き方には、代わりがまだなくても先に `@deprecated` と理由を付ける（代わりがないものは「追加予定」）。この項目の終わりに使えなくする。
  - 今ある作品は壊れてよい。公式ライブラリと同梱サンプルは作り直す。
  - 消せるもの（拾えるものなど）は、実行中に作るインスタンスとして置く（リストから作るなど）。
  - `world.find` はやめ、フィールドの参照で指す。
  - Entity を受け取ったり返したりする Host API とイベントは、すべて型の付いた参照にする。
  - ほかの作品には、専用の API でだけ働きかけ、Entity や KokoState を直接指さない。窓口の参照でやり取りし、窓口は消えうるものとして扱う。
  - プレイヤーは、消えうる参照として扱う。
  - どれが来るか分からない相手（ぶつかった相手・当たったもの）は、種類の付いた組み合わせで渡す。
  - 付いていない KokoState に書こうとしたら型エラーにする。
  - エージェントの、制作データを編集する道具は、今のまま ID や名前で指してよい。
- 設計者・実装者に任せること：結果の形（`{ status, value }` か `値 | undefined` か）、消えうる参照の型の名前と書き方、拾えるものの置き方。

## 関係するもの

- 前に終わっている必要があるもの：ロードマップの「プレハブを型で扱ってコードからインスタンスを作る」（作る・消す・切り替えるのはすぐ、渡す前に確かめる、書き込みもすぐ届く、の仕組みを先に作る）「プレハブのリストから子を組み立てる」（作りやすい順にするため、この項目を最後にする。それまでは、途中で危険な所があってもよい）
- このあとに続く項目：ロードマップの「インターフェイス型でプレハブの構造を決めて入れ替えて使う」（構造の違うものが入れ替わると消えるものが増えるので、この項目のあとに作る）
- ロードマップの「Systemの可変データを次の呼び出しに持ち越さない」（実行中の値を KokoState に置く）
- ADR 0012（権限と判定の場所。Host API の一覧 `HOST_API_SPEC`）、ADR 0065（フィールドの型と参照）、ADR 0076（プレハブとインスタンス）
