# 実行中に現れるものをプレハブで決めて静的に安全にする

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

実行中に作品の形を変える操作（Entity を作る・消す）を、プレハブのインスタンスに限る。こうすると、作品の中に、どんな形の Entity が、どんな KokoState を持って現れうるかが、制作データ・プレハブ・インターフェイスから、すべて静的に分かる。

あわせて、消えうるものを指す参照を、型の上で「いつでも消えうるもの」として扱う。静的に確かめて問題がなかったスクリプトが、実行中に、消えたものを指して壊れることがないようにする。

## 原則とのつながり

- 原則 5（安心して作れる）：型の確かめを通ったスクリプトは、実行中に、なくなったものを指して壊れない。
- 原則 2（入口は低く、奥は深い）：何が現れうるかが分かるので、型の候補・コードホバー・デバッグが、実行中のものにも正しく働く。

## やること

### Entity を作る

- 実行中に作れるのは、プレハブのインスタンスだけにする（例：`world.spawn(弾, …)`）。
- 名前と KokoState を文字で指定して、どんな Entity でも作れる今の `world.spawn` はやめる。

### Entity を消す

- 実行中に消せるのは、実行中に作ったインスタンスだけにする。制作データに置いた Entity は消せない。
- 制作データに置いた Entity を「なくしたい」ときは、見えない・働かない状態を表すフィールドなどで表す。

### KokoState を付ける・外す

- 実行中に、KokoState を付けたり外したりすることはやめる。
- 持つ KokoState を変えたいときは、バリアントへの切り替え（ロードマップの「プレハブのインターフェイスを決めてインスタンスを別のプレハブに切り替える」）や、子のインスタンスを作る・消すことで表す。

### 参照

- **ID の文字で Entity を指すことはやめる。** Entity は、型の付いた参照（`EntityRef`・`KokoStateRef`・`FieldRef` など）でだけ指す。
- **いつでも消えうるもの**：実行中に作ったインスタンス（とその中の Entity・KokoState）を指す参照は、型の上で「いつでも消えうるもの」として扱う。
  - 参照から値を読み書きするたびに、結果を確かめる形にする（例：`{ status: "ok", value }` か `{ status: "gone" }`、または `値 | undefined`）。
  - 参照は、値そのもの（オブジェクト）を持ち続けない。一度確かめても、そのあとで消えることがあるので、読み書きは毎回、参照を通して行う。読んだ値は写しなので、あとで消えても壊れない。書くときに消えていたら、結果で分かる。
- **消えないもの**：制作データに置いた Entity と、そのインスタンスの、インターフェイスに書いた子の Entity は、実行中に消えない。そこを指す参照は、今のまま、消えうるものとしては扱わない。
- 名前で探す（`world.find`）など、型で確かめられない探し方の結果も、「見つからないことがある」結果の形で返す。

### 公式のものと既存のもの

- プロトタイプなので、今ある作品やスクリプトは壊れてよい。
- 公式ライブラリと同梱サンプルは、新しい仕組みで作り直す（例：マルバツの駒を作る所、公式ライブラリ items の「拾うと消える」所）。

## やらないこと

- 実行中に KokoState を付けたり外したりすること（必要になったら、「あってもなくてもよい KokoState」をプレハブに書ける形で、別に検討する）。

## 決まっていること・決まっていないこと

- 決まっていること：
  - 実行中に作れるのはプレハブのインスタンスだけ。消せるのは、実行中に作ったインスタンスだけ。
  - 実行中に KokoState を付けたり外したりしない。
  - ID の文字で Entity を指すことはやめ、型の付いた参照でだけ指す。
  - 実行中に作ったインスタンスを指す参照は、いつでも消えうるものとして扱い、読み書きのたびに結果を確かめる。
  - 今ある作品は壊れてよい。公式ライブラリと同梱サンプルは作り直す。
- 設計者・実装者に任せること：結果の形（`{ status, value }` か `値 | undefined` か）、消えうる参照の型の名前と書き方。
- 計画者に聞くこと：
  - 制作データに置いた Entity を「なくしたい」とき（items の「拾う」など）は、見えない・働かない状態にする、でよいか。それとも、拾えるものは実行中に作ったインスタンスとして置く決まりにするか。
  - `world.find`（名前で探す）を残すか。残すなら、結果は「見つからないことがある」形で返す。

## 関係するもの

- ロードマップの「プレハブのインターフェイスを決めてインスタンスを別のプレハブに切り替える」（切り替えで消える子を、インターフェイスと消えうる参照で守る）
- ロードマップの「プレハブのリストから子を組み立てる」（状態から作る子は、実行中に作るインスタンス）
- ロードマップの「Systemの可変データを次の呼び出しに持ち越さない」（実行中の値を KokoState に置く）
- ADR 0012（権限と判定の場所。Host API の一覧 `HOST_API_SPEC`）、ADR 0065（フィールドの型と参照）、ADR 0076（プレハブとインスタンス）
