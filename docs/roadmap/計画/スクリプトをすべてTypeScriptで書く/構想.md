## やりたいこと

作品のスクリプトは、すべて TypeScript で書く。型チェックと入力補完で、動かす前に間違いに気づける。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：入力補完で始めやすく、型で大きなコードも作り込める。
- 原則 5（安心して作れる）：動かす前に間違いに気づける。

## やること

もとの計画（リソースパス・System 参照・全体診断の Phase 8）をもとにした内容。Host API の型の宣言と入力補完は、すでにできている。

1. Host API の schema と KokoState の定義から `.d.ts` を作る。
2. スクリプトを `.ts` で書き、TS から JS に変えて動かす。
3. 問題の一覧に型の誤りを出す。
4. source map で、QuickJS の実行時の誤りを、もとの TS の場所に戻す。
