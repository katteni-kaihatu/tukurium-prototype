# プレハブの一部を上書きしてバリアントを作る

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

プレハブの一部を上書きして、バリアント（派生）を作れる。たとえば「的」から「固い的」を作る。上書きしていない所には、元のプレハブの変更が反映される。

バリアントは、**いちばん上の Entity が、元のプレハブのインスタンスになっているプレハブ**として作る。インスタンスで変える仕組み（上書き）と、入れ子のプレハブの仕組みを、そのまま使う。

```
プレハブ「固い的」（バリアント）
  いちばん上の Entity ＝ 「的」のインスタンス
    上書き：Health.hp = 300
```

## 原則とのつながり

- 原則 4（一度作ったものを、何度でも、誰とでも使える）：少しだけ違うものを、複製せずに作れる。元を直せば、派生にも反映される。

## やること

- バリアントは、プレハブの一種。プレハブと同じように、置いてインスタンスを作れ、開いて直せる。
- 作り方は二つ。
  - **プレハブから作る**：プレハブの「バリアントを作る」で、上書きのないバリアントを作る。
  - **インスタンスで変えたことから作る**：インスタンスの「バリアントとして保存する」で、インスタンスで変えたことを上書きに持つバリアントを作る。「プレハブに適用する」と並べて出す。保存したあと、そのインスタンスは新しいバリアントのインスタンスになる。
- バリアントで変えたことを、確認して元のプレハブに書き戻せる（インスタンスの「プレハブに適用する」と同じ）。
- バリアントから、さらにバリアントを作れる（何段でも。自分を含む形はできない）。
- 上書きの印と戻し方、上書き先が消えたときの扱いは、インスタンスと同じ。
- 元のプレハブを消したときは、バリアントを残して、問題として出す（インスタンスと同じ）。
- Inspector と Resources で、どのプレハブのバリアントかが分かる。

## やらないこと

- インスタンスを別のバリアントや別のプレハブに切り替えること（ロードマップの「プレハブのインターフェイスを決めてインスタンスを別のプレハブに切り替える」で扱う）。

## 完了の条件

- 「的」から「固い的」を、プレハブから作る方法と、インスタンスで変えたことから作る方法の両方で作れる。
- 「固い的」のインスタンスを置くと、上書きした hp で動く。「的」を直すと、上書きしていない所は「固い的」とそのインスタンスにも反映される。
- 「固い的」で変えたことを、確認して「的」に書き戻せる。
- 「固い的」から、さらにバリアントを作れる。
- 「的」を消すと、「固い的」は残り、問題として出る。

## 決まっていること・決まっていないこと

- 決まっていること：
  - バリアントは、いちばん上の Entity が元のプレハブのインスタンスになっているプレハブ。
  - 作り方は、プレハブから作る・インスタンスで変えたことから作る、の二つ。
  - バリアントで変えたことを、元のプレハブに書き戻せる。
  - 何段でも作れる。上書きの印と戻し方・上書き先が消えたとき・元を消したときは、インスタンスと同じ。
- 設計者・実装者に任せること：バリアントの見分け方（Resources の印など）、「バリアントとして保存する」の名前の付け方。
