# スクリプトを途中で止めて中の値を確かめる

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

ワークスペースの再生を、スクリプトの決めた行で止め、その時点の変数や KokoState の値を確かめられる。VS Code のデバッグ（デバッグモードとブレイクポイント）と同じ体験にする。

今は、思ったとおりに動かないとき、`log()` を書き足して再生し直すしかない。止めて中を見られれば、どこで何が違っているかを、書き足さずに確かめられる。

## 原則とのつながり

- 原則 1（作る場所と遊ぶ場所が同じ）：遊びながら作っている場で、そのまま止めて中を見られる。
- 原則 2（入口は低く、奥は深い）：慣れた人は、止めて値をたどって、込み入った処理も直せる。
- 原則 5（安心して作れる）：うまく動かない理由を、推測でなく確かめて直せる。

## やること（案）

- **デバッグモード**：ワークスペースの再生を、ブレイクポイントで止まる形で動かす。
- **ブレイクポイント**：スクリプトのエディタで、行番号の横を押して止める行を決める。
- **止まったとき**：止まった行が分かり、その時点の変数・引数・`e.get()` で読んだ KokoState の値が見える。
- **続ける**：続けて動かす（次のブレイクポイントまで）。

## やらないこと（案）

- セッションに出した配置（みんなで遊んでいるもの）を止めること。

未定（やることが決まってから書く）。

## 決まっていること・決まっていないこと

- 決まっていること：ワークスペースの再生にはすでに一時停止がある。
- 設計者・実装者に任せること：未定。
- 設計者に先に見てほしいこと：スクリプトは QuickJS（`quickjs-emscripten-core` の同期版）で、フレームごとに System を呼んでいる。行の途中で止めて、あとから続けるには、非同期版（asyncify）に変えるか、実行を Worker に移して待たせるなどが要る。1 行ずつ進める（ステップ実行）ができるかは、これで決まる。
- 計画者に聞くこと：
  1. 止めたとき、同じワークスペースのほかの参加者の再生も止まるか（再生は参加者で共有している）。
  2. 止まっている間にできること：値を見るだけか、1 行ずつ進める・次のフレームまで進める・値を書き換えるも入れるか。
  3. ブレイクポイントは、制作データとして保存してみんなで共有するか、置いた人だけのものか。
  4. 条件付きのブレイクポイント（`hp < 0` のときだけ止まる）や、止まらずに値を書き出すログポイントも入れるか。
  5. AI エージェントにも、ブレイクポイントを置いて止まった値を受け取る道具を渡すか。
