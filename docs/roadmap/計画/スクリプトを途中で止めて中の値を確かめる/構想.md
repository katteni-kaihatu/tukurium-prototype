# スクリプトを途中で止めて中の値を確かめる

- 状態：完了
- 計画者：れにうむ
- 作成完了日：2026-11-10

## やりたいこと

ワークスペースの再生を、スクリプトの決めた行で止め、その時点の変数や KokoState の値を確かめ、1 行ずつ進めたり値を変えたりできる。VS Code のデバッグ（デバッグモードとブレイクポイント）と同じ体験を、一緒に作っている全員で共有する。

今は、思ったとおりに動かないとき、`log()` を書き足して再生し直すしかない。止めて中を見られれば、どこで何が違っているかを、書き足さずに確かめられる。止まった所は参加者全員に見えるので、一緒に原因を探せる。

## 原則とのつながり

- 原則 1（作る場所と遊ぶ場所が同じ）：遊びながら作っている場で、そのまま止めて中を見られる。
- 原則 2（入口は低く、奥は深い）：慣れた人は、止めて値をたどって、込み入った処理も直せる。
- 原則 5（安心して作れる）：うまく動かない理由を、推測でなく確かめて直せる。

## やること

- **デバッグモード**：ワークスペースの再生を、ブレイクポイントで止まる形で動かす。
  - 再生の操作のそばにあるトグルで入れたり切ったりする。切り替えは再生を始める前に行う（再生の途中で切り替えられなくてよい）。
  - トグルはワークスペースの参加者全員で共有する。誰かが入れると全員の再生がデバッグモードになり、入っているかどうかが全員に見える。
- **ブレイクポイント**：スクリプトのエディタで、行番号の横を押して止める行を決める。ブレイクポイントはワークスペースの上のもので、参加者全員で共有する。保存の履歴やリリースには含めない。
  - デバッグモードのときだけ止まる。切れている間は、消さずに、休んでいることが分かる見た目にする。
- **条件付きのブレイクポイント**：式を書き、それが成り立つときだけ止まる（例：`hp < 0`）。
- **ログポイント**：止まらずに、書いた文や式の値を「ログ」に書き出す。デバッグモードのときだけ書き出す。
- **誤りで止まる**：スクリプトが実行中に誤りを起こしたら、その行で止まる。止まらずに「エラー」パネルに記録して先へ進む今の動きは、デバッグモードでないときのまま残す。
- **値が変わったら止まる**：KokoState の欄（例：的の `hp`）を選んでおくと、その欄が書き換わった瞬間に止まり、どの System の何行目が変えたかが分かる。「Entity を選んで止まる」と組み合わせると、特定の的の `hp` だけを見張れる。
- **Entity を選んで止まる**：空間や Hierarchy で Entity を選び、「この Entity を処理するときだけ止まる」ようにできる。ブレイクポイントと組み合わせられる。
- **止まったとき**：
  - 再生がまるごと止まる。ほかの参加者の再生も止まり、どのスクリプトの何行目で止まっているかが全員に見える。
  - 止まった行と、変数・引数・`e.get()` で読んだ KokoState の値が見える。どの Entity を処理している途中かも分かる。
  - 処理している途中の Entity が、3D 空間で光って分かる。
  - 呼び出しの順（どの関数からどの関数を呼んで今の行に来たか）が並び、選ぶとその時点の行と値を見られる。
  - 値は、デバッグ用のパネルと、コードホバー（重ねた変数の今の値）で見られる。
- **止まってからの操作**：
  - 続ける（次のブレイクポイントまで動かす）
  - 1 行ずつ進める（関数の中に入る・関数から出る・次の行へ、を選べる）
  - 次のフレームまで進める
  - 変数や KokoState の値を変えて、続きを動かす（変えるのは実行状態だけで、制作データは変わらない）
- **操作できる人**：デバッグモードの切り替え、ブレイクポイントを置く・外す、止まった再生を進めるのは、共同編集か管理の権限がある人。
- 画面に出したパネルでも、空間に置いたパネルでも使える。

## やらないこと

- セッションに出した配置（みんなで遊んでいるもの）を止めること。
- AI エージェントに、ブレイクポイントを置いたり止まった値を受け取ったりする道具を渡すこと。
- 止める前に戻る（巻き戻し）こと。

## 完了の条件

- デバッグモードを入れて同梱サンプルを再生し、スクリプトの行にブレイクポイントを置くと、その行で止まり、デバッグ用のパネルとコードホバーで変数と KokoState の値が見える。
- デバッグモードを切って再生すると、ブレイクポイントがあっても止まらず、ログポイントも書き出さない。
- デバッグモードにしないときの再生は、今と同じ速さで動く。
- 1 行ずつ進める・関数の中に入る・関数から出る・次のフレームまで進める・続ける、がそれぞれできる。
- 止まっている間に値を変えて続けると、変えた値で動く。
- 実行中の誤りが起きると、その行で止まり、その時点の値が見える。
- 欄を選んでおくと、その欄が書き換わった瞬間に止まり、書き換えた System と行が分かる。
- Entity を選んでおくと、その Entity を処理するときだけ止まる。止まったとき、処理している途中の Entity が空間で光る。
- 止まったとき、呼び出しの順が見え、選んだ時点の行と値に移れる。
- 条件付きのブレイクポイントは条件が成り立つときだけ止まり、ログポイントは止まらずにログへ書き出す。
- 共同編集の権限を持つ 2 人が同じワークスペースにいるとき、一人が置いたブレイクポイントと入れたデバッグモードがもう一人にも見え、止まると両方の再生が止まり、どちらからも進められる。
- ブレイクポイントは、保存の履歴にもリリースにも入らない。
- 止まっている間に再生を動かしているホストが抜けても、再生が壊れない。

## 決まっていること・決まっていないこと

- 決まっていること：
  - デバッグモードはトグルで切り替え、参加者全員で共有する。再生の途中では切り替えなくてよい。
  - ブレイクポイントとログポイントは、デバッグモードのときだけ働く。
  - 止めると、そのワークスペースの再生は参加者全員で止まる。
  - ブレイクポイントはワークスペースの上のもので、参加者全員で共有し、保存の履歴やリリースに含めない。
  - 操作できるのは、共同編集か管理の権限がある人。
  - 値は、デバッグ用のパネルとコードホバーで見せる。
  - 止まるきっかけは、ブレイクポイント（条件付きを含む）・誤り・欄の値の変化・選んだ Entity の 4 つ。どれもデバッグモードのときだけ働く。
  - 見張る欄と選んだ Entity も、ブレイクポイントと同じく、ワークスペースの上で参加者全員で共有し、保存の履歴やリリースに含めない。
  - デバッグモードにしないときの再生は、今より遅くしない。デバッグモードの間は遅くなってもよい。
  - AI エージェントには、新しい道具を渡さない。
  - ワークスペースの再生にはすでに一時停止があり、それを土台にする。
- 設計者・実装者に任せること：
  - 止める仕組み。スクリプトは QuickJS（`quickjs-emscripten-core` の同期版）で、フレームごとに System を呼んでいる。行の途中で止めて続けるには、非同期版（asyncify）に変える、実行を Worker に移して待たせる、などが要る。デバッグモードにしない再生を遅くしない作りにする。まずここを確かめる。
  - 止まっている間のホストの引き継ぎ、物理と時間の扱い。
  - 条件付きのブレイクポイントの式で、値を書き換えてしまわないようにする方法。
  - デバッグ用のパネルの形。
  - 欄の書き換えを見張る方法（`e.get()` と `world.set()` のどちらから書き換えても止まるようにする）。
  - 再生の途中で生まれた Entity（Hierarchy にないもの）の選び方。
- 計画者に聞くこと：なし。
