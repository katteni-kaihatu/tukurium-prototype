# スクリプトを途中で止めて中の値を確かめる

- 状態：完了
- 計画者：れにうむ
- 作成完了日：2026-11-10

## やりたいこと

ワークスペースの再生を、決めた条件で止め、その時点の変数や KokoState の値を確かめ、1 行ずつ進めたり値を変えたりできる。VS Code のデバッグ（デバッグモードとブレイクポイント）と同じ体験を、一緒に作っている全員で共有する。

今は、思ったとおりに動かないとき、`log()` を書き足して再生し直すしかない。止めて中を見られれば、どこで何が違っているかを、書き足さずに確かめられる。止まった所は参加者全員に見えるので、一緒に原因を探せる。

## 原則とのつながり

- 原則 1（作る場所と遊ぶ場所が同じ）：遊びながら作っている場で、そのまま止めて中を見られる。
- 原則 2（入口は低く、奥は深い）：慣れた人は、止めて値をたどって、込み入った処理も直せる。
- 原則 5（安心して作れる）：うまく動かない理由を、推測でなく確かめて直せる。

## やること

### デバッグモード

- ワークスペースの再生を、止まる条件で止まる形で動かす。
- 再生の操作のそばにあるトグルで入れたり切ったりする。切り替えは再生を始める前に行う（再生の途中で切り替えられなくてよい）。
- トグルはワークスペースの参加者全員で共有する。誰かが入れると全員の再生がデバッグモードになり、入っているかどうかが全員に見える。
- 止まる条件とログポイントは、デバッグモードのときだけ働く。

### 止まる条件

デバッグ用のパネルに、止まる条件を一つずつ並べる。**止まる条件どうしは OR**（どれか一つに当てはまったら止まる）、**一つの止まる条件の中は AND**（中の条件が全部そろったら止まる）。

```
止まる条件　（どれか一つに当てはまったら止まる）

 [✓] 1. コードの行：Shoot.ts 12 行目
 [✓] 2. 欄の変化：Health.hp   かつ   Entity：的 3
 [ ] 3. コードの行：Hit.ts 8 行目   かつ   Entity：銃 A   かつ   式：damage > 10
 [✓] 4. 欄の変化：Health.hp   かつ   式：新しい値 <= 0
 [✓] 5. 実行中の誤り
```

一つの止まる条件には、きっかけを必ず一つ入れ、絞り込みを足せる（絞り込みだけでは、いつ止まるかが決まらないため）。

| 種類 | 中身 |
| --- | --- |
| きっかけ：コードの行 | スクリプトのその行に来たら止まる。エディタの行番号の横に印（ブレイクポイント）が出る |
| きっかけ：欄の変化 | KokoState の欄（例：`Health.hp`）が書き換わったら、書き換えた行のすぐあとで止まる。物理など、スクリプト以外が書き換えたときは、止まる行の代わりに出どころを出す。同じ値を書いたときは止まらない。`e.get()` と `world.set()` のどちらから書き換えても止まる |
| きっかけ：実行中の誤り | スクリプトが実行中に誤りを起こしたら、その行で止まる |
| 絞り込み：Entity | その Entity を処理しているとき（欄の変化なら、その Entity の欄が変わったとき）だけ |
| 絞り込み：式 | 式が成り立つときだけ（例：`damage > 10`）。欄の変化では、前の値と新しい値を使える |

- 止まる条件ごとにチェックを外して休ませられる。休んでいるものは消えず、エディタの印も休んでいると分かる見た目になる。
- 止まる条件はワークスペースの上のもので、参加者全員で共有する。保存の履歴やリリースには含めない。
- デバッグモードでないときは、実行中の誤りは今と同じように「エラー」パネルに記録して先へ進む。

### 止まる条件の足し方

| 足す場所 | 操作 | 足されるもの |
| --- | --- | --- |
| スクリプトのエディタ | 行番号の横を押す | 「コードの行」の止まる条件（ブレイクポイント） |
| スクリプトのエディタ | 行番号の横を右クリック →「ログポイント」 | ログポイント |
| 空間・Hierarchy | Entity を右クリック →「このときだけ止まる」 | パネルで選んでいる止まる条件に「かつ Entity」 |
| 止まっているときの値 | 欄を右クリック →「変わったら止まる」 | 「欄の変化」の止まる条件 |
| デバッグ用のパネル | 「止まる条件を足す」「かつ」を押す | 新しい止まる条件、その中への条件 |

### ログポイント

止まらずに、書いた文や式の値を「ログ」に書き出す。デバッグモードのときだけ書き出す。

### 止まったとき

- 再生がまるごと止まる。ほかの参加者の再生も止まり、どの条件で、どのスクリプトの何行目で止まっているかが全員に見える。
- 止まった行と、変数・引数・`e.get()` で読んだ KokoState の値が見える。欄の変化で止まったときは、前の値と新しい値（例：「`hp`：10 → 0」）と、書き換えた System と行（スクリプト以外なら出どころ）が分かる。
- 処理している途中の Entity が、3D 空間で光って分かる。
- 呼び出しの順（どの関数からどの関数を呼んで今の行に来たか）が並び、選ぶとその時点の行と値を見られる。
- 値は、デバッグ用のパネルと、コードホバー（重ねた変数の今の値）で見られる。

### 止まってからの操作

- 続ける（次に条件に当てはまるまで動かす）
- 1 行ずつ進める（関数の中に入る・関数から出る・次の行へ、を選べる）
- 次のフレームまで進める
- 変数や KokoState の値を変えて、続きを動かす（変えるのは実行状態だけで、制作データは変わらない）

### そのほか

- デバッグモードの切り替え、止まる条件とログポイントを足す・外す、止まった再生を進めるのは、共同編集か管理の権限がある人。
- 画面に出したパネルでも、空間に置いたパネルでも使える。

## やらないこと

- セッションに出した配置（みんなで遊んでいるもの）を止めること。
- AI エージェントに、止まる条件を足したり止まった値を受け取ったりする道具を渡すこと。
- 止める前に戻る（巻き戻し）こと。
- System の中の変数（関数の中の `const` など）が変わったら止まること。必要なときは「コードの行」かつ「式」で代わりにする。

## 完了の条件

- デバッグモードを入れて同梱サンプルを再生し、スクリプトの行にブレイクポイントを置くと、その行で止まり、デバッグ用のパネルとコードホバーで変数と KokoState の値が見える。
- デバッグモードを切って再生すると、止まる条件があっても止まらず、ログポイントも書き出さない。
- デバッグモードにしないときの再生は、今と同じ速さで動く。
- 止まる条件どうしは OR、一つの止まる条件の中は AND で働く。休ませた止まる条件では止まらない。
- 欄の変化で、欄が別の値に書き換わった瞬間に止まり、前の値と新しい値、書き換えた System と行（スクリプト以外なら出どころ）が分かる。同じ値を書いたときは止まらない。Entity と式で絞れる。
- 実行中の誤りで、誤りが起きた行で止まり、その時点の値が見える。
- 止まったとき、処理している途中の Entity が空間で光り、呼び出しの順が見え、選んだ時点の行と値に移れる。
- 1 行ずつ進める・関数の中に入る・関数から出る・次のフレームまで進める・続ける、がそれぞれできる。
- 止まっている間に値を変えて続けると、変えた値で動く。
- ログポイントは止まらずにログへ書き出す。
- 共同編集の権限を持つ 2 人が同じワークスペースにいるとき、一人が足した止まる条件と入れたデバッグモードがもう一人にも見え、止まると両方の再生が止まり、どちらからも進められる。
- 止まる条件は、保存の履歴にもリリースにも入らない。
- 止まっている間に再生を動かしているホストが抜けても、再生が壊れない。

## 決まっていること・決まっていないこと

- 決まっていること：
  - デバッグモードはトグルで切り替え、参加者全員で共有する。再生の途中では切り替えなくてよい。
  - 止まる条件とログポイントは、デバッグモードのときだけ働く。
  - 止まる条件どうしは OR、一つの止まる条件の中は AND にする。きっかけはコードの行・欄の変化・実行中の誤りの 3 つで、一つの止まる条件に必ず一つ入れる。絞り込みは Entity と式。
  - 欄の変化は KokoState の欄が対象で、同じ値を書いたときは止まらない。式では前の値と新しい値を使える。
  - 止めると、そのワークスペースの再生は参加者全員で止まる。
  - 止まる条件はワークスペースの上のもので、参加者全員で共有し、保存の履歴やリリースに含めない。
  - 操作できるのは、共同編集か管理の権限がある人。
  - 値は、デバッグ用のパネルとコードホバーで見せる。
  - デバッグモードにしないときの再生は、今より遅くしない。デバッグモードの間は遅くなってもよい。
  - AI エージェントには、新しい道具を渡さない。
  - ワークスペースの再生にはすでに一時停止があり、それを土台にする。
- 設計者・実装者に任せること：
  - 止める仕組み。スクリプトは QuickJS（`quickjs-emscripten-core` の同期版）で、フレームごとに System を呼んでいる。行の途中で止めて続けるには、非同期版（asyncify）に変える、実行を Worker に移して待たせる、などが要る。デバッグモードにしない再生を遅くしない作りにする。まずここを確かめる。
  - 止まっている間のホストの引き継ぎ、物理と時間の扱い。
  - 式で、値を書き換えてしまわないようにする方法。式の中の「前の値」「新しい値」の書き方。
  - 欄の書き換えを見張る方法。スクリプト以外（物理・Built-in の処理など）が書き換えたときの、出どころの見せ方。
  - 再生の途中で生まれた Entity（Hierarchy にないもの）の選び方。
  - デバッグ用のパネルの形。
- 計画者に聞くこと：「型と説明を見ながらスクリプトを書く」を先に終えるか、デバッグ用のパネルだけで先に作り、コードホバーで値を見せるのはあとで足すか。
