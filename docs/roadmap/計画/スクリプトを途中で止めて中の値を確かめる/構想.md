# スクリプトを途中で止めて中の値を確かめる

- 状態：完了
- 計画者：れにうむ
- 作成完了日：2026-11-10

## やりたいこと

ワークスペースの再生を、スクリプトの決めた行で止め、その時点の変数や KokoState の値を確かめ、1 行ずつ進めたり値を変えたりできる。VS Code のデバッグ（デバッグモードとブレイクポイント）と同じ体験を、一緒に作っている全員で共有する。

今は、思ったとおりに動かないとき、`log()` を書き足して再生し直すしかない。止めて中を見られれば、どこで何が違っているかを、書き足さずに確かめられる。止まった所は参加者全員に見えるので、一緒に原因を探せる。

## 原則とのつながり

- 原則 1（作る場所と遊ぶ場所が同じ）：遊びながら作っている場で、そのまま止めて中を見られる。
- 原則 2（入口は低く、奥は深い）：慣れた人は、止めて値をたどって、込み入った処理も直せる。
- 原則 5（安心して作れる）：うまく動かない理由を、推測でなく確かめて直せる。

## やること

- **デバッグモード**：ワークスペースの再生を、ブレイクポイントで止まる形で動かす。
- **ブレイクポイント**：スクリプトのエディタで、行番号の横を押して止める行を決める。ブレイクポイントはワークスペースの参加者全員で共有する（同じ再生を、同じブレイクポイントで動かしている）。
- **条件付きのブレイクポイント**：式を書き、それが成り立つときだけ止まる（例：`hp < 0`）。
- **ログポイント**：止まらずに、書いた文や式の値を「ログ」に書き出す。
- **止まったとき**：
  - 再生がまるごと止まる。ほかの参加者の再生も止まり、どのスクリプトの何行目で止まっているかが全員に見える。
  - 止まった行と、変数・引数・`e.get()` で読んだ KokoState の値が見える。どの Entity を処理している途中かも分かる。
- **止まってからの操作**：
  - 続ける（次のブレイクポイントまで動かす）
  - 1 行ずつ進める（関数の中に入る・関数から出る・次の行へ、を選べる）
  - 次のフレームまで進める
  - 変数や KokoState の値を変えて、続きを動かす（変えるのは実行状態だけで、制作データは変わらない）
- 画面に出したパネルでも、空間に置いたパネルでも使える。

## やらないこと

- セッションに出した配置（みんなで遊んでいるもの）を止めること。
- AI エージェントに、ブレイクポイントを置いたり止まった値を受け取ったりする道具を渡すこと。
- 止める前に戻る（巻き戻し）こと。

## 完了の条件

- 同梱サンプルで、スクリプトの行にブレイクポイントを置いて再生すると、その行で止まり、変数と KokoState の値が見える。
- 1 行ずつ進める・関数の中に入る・関数から出る・次のフレームまで進める・続ける、がそれぞれできる。
- 止まっている間に値を変えて続けると、変えた値で動く。
- 条件付きのブレイクポイントは条件が成り立つときだけ止まり、ログポイントは止まらずにログへ書き出す。
- 共同編集の権限を持つ 2 人が同じワークスペースにいるとき、一人が置いたブレイクポイントがもう一人にも見え、止まると両方の再生が止まり、どちらからも進められる。
- 止まっている間に再生を動かしているホストが抜けても、再生が壊れない。

## 決まっていること・決まっていないこと

- 決まっていること：
  - 止めると、そのワークスペースの再生は参加者全員で止まる。
  - ブレイクポイントは参加者全員で共有する。
  - AI エージェントには、新しい道具を渡さない。
  - ワークスペースの再生にはすでに一時停止があり、それを土台にする。
- 設計者・実装者に任せること：
  - 止める仕組み。スクリプトは QuickJS（`quickjs-emscripten-core` の同期版）で、フレームごとに System を呼んでいる。行の途中で止めて続けるには、非同期版（asyncify）に変える、実行を Worker に移して待たせる、などが要る。まずここを確かめる。
  - ブレイクポイントを保存の履歴やリリースに含めるか（共有はワークスペースの中で行う）。
  - 誰がブレイクポイントを置け、止まった再生を進められるか（再生を操作できる人に合わせるのを基本にする）。
  - 止まっている間のホストの引き継ぎ、物理と時間の扱い。
  - 条件付きのブレイクポイントの式で、値を書き換えてしまわないようにする方法。
  - 値の見せ方（専用のパネル・コードホバーとの関係）。
- 計画者に聞くこと：なし。
