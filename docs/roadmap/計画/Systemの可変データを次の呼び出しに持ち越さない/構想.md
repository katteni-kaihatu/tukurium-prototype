# Systemの可変データを次の呼び出しに持ち越さない

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

System のスクリプトの中に置いた変数などの可変データを、次の呼び出しに持ち越せないようにする。次回も使う値は KokoState に書く。こうすると、作品の実行状態はすべて EKS のスナップショット（その時点の Entity と KokoState の値。制作データのスナップショットとは別）に入り、実行環境を作り直しても、同じスナップショットと次の入力から同じ結果になる。

## 原則とのつながり

- 原則 5（安心して作れる）：再生を動かしているホストが抜けて別の人が引き継いでも、動きが変わらない。状態が KokoState に見えているので、どこに何があるか分かる。

## やること

- System の呼び出しをまたいで可変データを持ち越せないようにする（スクリプトの一番外に置いた変数を書き換えるなど）。
- 共通スクリプト（ロードマップの「共通の処理をまとめたスクリプトを複数のSystemから使う」）にも同じ決まりを当てはめる。
- 持ち越そうとしたことを、問題として作者に知らせる。
- 実行環境を作り直しても、同じスナップショットと次の入力から同じ結果になることを、テストで確かめる。

- 決まっていること：次回も使う値は KokoState に書く。

  - 定数（書き換えない値）や、毎回作り直す表のようなものは、一番外に置いてよいか。
  - 乱数や時刻のような、毎回変わる値をどう扱うか（同じ結果にするために、ホストから渡すか）。
