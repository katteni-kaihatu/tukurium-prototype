# 改変したホストからもほかの人の状態を守る

- 状態：作成中（見直す予定）
- 計画者：れにうむ
- 作成完了日：（作成中。元の計画は 2026-11-05）

## やりたいこと

改変したホストからも、ほかの人の状態・権限・競争の結果を守れる。今の「ホストを信頼する協調セッション」と「守られたセッション」が、画面と資料で区別できる。

## 原則とのつながり

- 原則 5（安心して作れる）：ほかの人の変更で、自分のものが勝手に変わらない。

## やること

もとの計画（UGC API・権限・Library Package の U2 と 3.7 節）と、古いロードマップから移した内容。

- サーバーで確かめる・動かす最初の操作と、世界の状態を持つか操作の記録だけを確かめるか、ホストが替わったときの扱いを ADR で決める。候補は `bag.add / take`、`world.destroy`、Contract の受け渡し。
- サーバーでも、公開 Contract・opaque handle・World の上限に基づいて、相手の側の許可を判定する。
- ほかの参加者へ配る一時的な効果と音の数と大きさを、サーバーで確かめる。
- 入力の表示名 `playerName` も、サーバーが設定する。
- 「協調セッション（ホストを信頼）」か「守られている」かを、画面と資料に示す。
- 少なくとも state.write、entity.spawn / destroy、公開 Contract による残る変更、権限の変更は、サーバーでの判定がないまま「守られている」としない。
- Damage などの Contract の依頼は、判定する側が出す依頼の ID を持ち、同じ範囲で重なったものを一度だけ当てる。

`HOST_API_SPEC` の `authority` が `server-revalidate` / `server-execute` の操作をサーバーで確かめ・動かせるまでは、「守られている」と表示しない。
