# プレハブのリストから子を組み立てる

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

プレハブのリストから、Entity の子を実行中に組み立てられる。チェスの駒や合法手のガイドのように、数や中身が状態で変わる子を、一つずつ置かずに作れる。

リストの一つずつには、どのプレハブを使うか（インターフェイスで型の付いた値）と、インスタンスに渡す値を持つ。実行中に、リストの中のプレハブを替えると、同じ子のインスタンスのまま、別のプレハブに切り替わる。たとえば、チェスのポーンが成ってクイーンになるとき、駒を消して作り直さずに、同じ駒のまま切り替える。ここが Unity のプレハブと違う所。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：盤面やリストの表示を、短い決まりで組み立てられる。状態に合わせて中身が変わるものを、作り直しの手間なしに作れる。
- 原則 4（一度作ったものを、何度でも、誰とでも使える）：駒などのプレハブを、リストで何度も使える。

## やること

### リスト

- リストで受け付けるプレハブを、インターフェイスで決める（例：駒のインターフェイス `Piece` を満たすプレハブだけ）。
- リストの一つずつは、次のものを持つ。
  - 使うプレハブ（`Prefab<Piece>` のような、型の付いた値）
  - 置く場所・向き・大きさ
  - インスタンスに渡す値（ロードマップの「プレハブのインターフェイスを型で決めて値を渡してインスタンスを作る」の、上書きの値の形）。型で確かめられるので、安全に渡せる。
- **リストと子の関係**：リストが決めるのは、子があるか（キー）と、どのプレハブか。置き方と渡す値は、子を作るときと切り替えるときの初めの値として使う。そのあとは、子が自分の値を持ち、System が自由に変えられる。
  - リストに表示を預けたいとき（子に状態を持たせず、リストの値をそのまま見せたいとき）は、インターフェイスで「受け取るだけのフィールド」を決める（ロードマップの「プレハブのインターフェイスを型で決めて値を渡してインスタンスを作る」）。受け取るだけのフィールドは、リストの値が変わるたびに書き込み直され、スクリプトからは書けないことを静的に確かめる。
- リストは、KokoState のフィールドの値（リスト）から、安定したキーで子を足す・直す・消す。チェスの駒と合法手のガイドは、これで作れる。
- リストを使うのは、データに合わせて切り替えたり、動的に変わったりするものを表すとき。同じものを並べて置くだけなら、制作データにインスタンスを置く（プレハブの編集中の役割）。

### 実行中の子

- リストから作った子は、実行中に作ったインスタンス。保存せず、再生のたびに作り直す。
- Inspector と Hierarchy では見えるだけで、直すことはできない。

### 切り替え

- 同じキーの子で、使うプレハブが替わったら、消して作り直さずに、同じインスタンスのまま別のプレハブに切り替える。切り替えは、リストが変わったその場ですぐ行う。System に Entity を渡す前に、実行環境が、まだ Query に合うかを確かめる（ロードマップの「プレハブのインターフェイスを型で決めて値を渡してインスタンスを作る」の実行の仕組み）。切り替えられるのは、リストで受け付けるインターフェイスを満たすプレハブどうし。
- 切り替えたとき：
  - Entity（ID）と、キーは残る。ほかの Entity からの参照も切れない。
  - 両方のプレハブにある KokoState・フィールド・子の Entity は、実行中の値が残る。子の Entity は、インターフェイスに書いた子の名前で対応させる。
  - 新しいプレハブにしかないものは、新しいプレハブの初期値で足す。前のプレハブにしかなかったものは、消す。
  - 置き方と渡す値は、新しいプレハブにしかないものの初めの値として使う。両方にある値は、実行中の値を残す（受け取るだけのフィールドは、リストの値を書き込む）。
  - インスタンスの中の参照（フィールドの値）は、インターフェイスに書いた子の名前で、新しいプレハブの同じ子を指し直す。対応する子がなければ「なし」にする。
  - System は、切り替えに合わせて足したり外したりする。新しいプレハブにしかない System は足し、前のプレハブにしかなかった System は、ほかにそれを使うインスタンスが残っていなければ外す。
- リストのキーと、子の Entity の対応も、ホストが抜けて別の人が再生を引き継ぐときの実行状態に含める。
- 切り替えで消えるものを指す参照は、途中では実行中に壊れることがある。型で守るのは、ロードマップの「実行中に現れるものをプレハブで決めて静的に安全にする」で行う（実行中に作ったインスタンスを指す参照を、いつでも消えうるものとして扱う）。

### 適用

- セッションに出した配置を「適用」で更新するときは、リストから作った子をすべて消し、新しい中身で作り直す（リストのデータは、「維持」の決まりで残る）。
- 将来は、適用のやり方を選べるようにしたい（今はこの一つだけ）。

### AI エージェント

- AI エージェントも、人と同じく、リストを書き、リストの中のプレハブを替えられる。

## やらないこと

- 入れ子の構成まで状態から組み立てる仕組み（仮想ツリー）。平らなリストで足りない用途が出たら、別に検討する。
- リストから作った子を、Inspector で直すこと。
- 制作データに置いたインスタンスを切り替えること。
- 制作データに固定のリストを書き、再生を始めたときに子を作ること（使う場面が少ないため）。

## 完了の条件

チェスで確かめる。

- 駒のインターフェイスを受け付けるリストを、盤の KokoState のフィールドの値から作り、駒が並ぶ。合法手のガイドも、同じくリストから作る。
- リストの一つずつに渡した値（駒の色など）が、型で確かめられてインスタンスに渡る。形に合わない値は型エラーになる。
- 受け取るだけのフィールドを持つプレハブでは、リストの値を変えると、子の表示がその場で変わる。そのフィールドにスクリプトから書こうとすると型エラーになる。
- 切り替えたとき、インスタンスの中の参照が、新しいプレハブの同じ名前の子を指す。
- ポーンが端まで進んで、リストの中のプレハブがクイーンに替わると、同じ駒のインスタンスのまま切り替わる。
  - Entity の ID とキーは残る。
  - 両方にある値（位置や「動いた回数」など）は、実行中の値のまま残る。
  - クイーンにしかない KokoState と子の Entity は、クイーンの初期値で足され、ポーンにしかなかったものは消える。
  - クイーンのプレハブにしかない System が動き始め、ポーンが一つも残っていなければ、ポーンにしかなかった System は止まる。
- リストから作った駒は、Inspector と Hierarchy で見えるが、直せない。保存されず、再生のたびに作り直される。

## 決まっていること・決まっていないこと

- 決まっていること：
  - リストで受け付けるプレハブは、インターフェイスで決める。リストの一つずつは、プレハブ・置き方・渡す値を持つ。
  - リストから作った子は、実行中のインスタンス。保存せず、Inspector では見えるだけ。
  - 切り替えは、リストの中のプレハブを替えることで行う。切り替えたときの残し方・足し方・消し方・System の扱いは、上のとおり。
  - リストが決めるのは、子があるかと、どのプレハブか。置き方と渡す値は、作るときと切り替えるときの初めの値。リストに表示を預けたいときは、インターフェイスの受け取るだけのフィールドを使う。
  - インスタンスの中の参照は、切り替えるときにインターフェイスの子の名前で指し直す。
  - 適用のときは、リストから作った子をすべて消して作り直す。
  - 途中で危険な所があってもよい。参照を型で守るのは、最後の項目で行う。
  - AI エージェントも同じことができる。
- 設計者・実装者に任せること：リストの書き方、キーの持ち方。
- 計画者に聞くこと：なし。
