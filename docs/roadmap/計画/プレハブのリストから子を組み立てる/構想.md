# プレハブのリストから子を組み立てる

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

プレハブのリストから、Entity の子を組み立てられる。チェスの駒や合法手のガイドのように、数や中身が状態で変わる子を、一つずつ置かずに作れる。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：盤面やリストの表示を、短い決まりで組み立てられる。
- 原則 4（一度作ったものを、何度でも、誰とでも使える）：駒などのプレハブを、リストで何度も使える。

## やること

二つの段階で進める。

1. **固定のリスト**：プレハブやバリアントの参照・置く場所と向きと大きさを持つリストを使えるようにする。
2. **状態から作るリスト**：KokoState から表示用のリストを作り、安定したキーで子を足す・直す・消す。チェスの駒と合法手のガイドは、この段階で作れる。
   - 同じキーの子で、使うプレハブが変わったときは、消して作り直さずに、インスタンスを別のプレハブに切り替える（ロードマップの「プレハブのインターフェイスを決めてインスタンスを別のプレハブに切り替える」）。Entity・参照・実行中の値が残る。例：駒の種類が「クイーン」になったら、同じ駒のまま、クイーンのプレハブに切り替わる。

## やらないこと

- 入れ子の構成まで状態から組み立てる仕組み（仮想ツリー）。平らなリストで足りない用途が出たら、別に検討する。

## 決まっていること・決まっていないこと

- 決まっていること：固定のリストを先に作り、状態から作るリストをそのあとに作る。
- 設計者・実装者に任せること：
- 計画者に聞くこと：
  - 状態から作った子を、Inspector で直接直せるか（見るだけか）。
  - 状態から作った子は、保存するか、毎回作り直すか。

## 関係するもの

- 前に終わっている必要があるもの：ロードマップの「プレハブを作ってインスタンスをアウトプットに置く」
- ロードマップの「KokoStateのフィールドをTypeScriptの型で書いてレコード・リスト・マップ・参照を扱えるようにする」（状態から作るリストに使う）
- ロードマップの「プレハブの一部を上書きしてバリアントを作る」（リストにバリアントも入れる）
- 前に終わっている必要があるもの：ロードマップの「プレハブのインターフェイスを決めてインスタンスを別のプレハブに切り替える」（状態に合わせて切り替えるため）
