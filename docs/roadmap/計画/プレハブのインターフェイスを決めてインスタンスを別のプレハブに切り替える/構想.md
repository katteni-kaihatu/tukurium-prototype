# プレハブのインターフェイスを決めてインスタンスを別のプレハブに切り替える

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

プレハブが持つ形（どの KokoState とフィールドを持つか）を、TypeScript のインターフェイスとして決められる。同じインターフェイスを満たすプレハブ（バリアントを含む）どうしなら、インスタンスを、同じインスタンスのまま別のプレハブに切り替えられる。

たとえば、チェスのポーンが成ってクイーンになるとき、駒を消して作り直さずに、同じ駒のインスタンスのまま「ポーン」から「クイーン」に切り替える。Entity も、参照も、実行中の値も残る。ここが Unity のプレハブと違う所。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：状態に合わせて見た目や中身が変わるものを、作り直しの手間なしに作れる。
- 原則 4（一度作ったものを、何度でも、誰とでも使える）：同じインターフェイスを満たすプレハブを、入れ替えて使える。

## やること

- **プレハブのインターフェイス**：TypeScript で、プレハブが持つ KokoState とフィールドの形を、インターフェイスとして書ける。プレハブは、どのインターフェイスを満たすかを持ち、満たしているかを型で確かめる。
- **切り替えられる条件**：切り替える前と後のプレハブが、同じインターフェイスを満たしていること。元のプレハブが違っても、インターフェイスが合えば切り替えられる。
- **切り替えたときに残すもの**：すべて残す。
  - Entity（ID）。ほかの Entity からの参照も切れない。
  - 実行中の値。
  - インスタンスで上書きした所。
- **切り替え方**
  - Inspector で、インスタンスのプレハブを選び直す。選べるのは、同じインターフェイスを満たすプレハブだけ。
  - ロードマップの「プレハブのリストから子を組み立てる」で、状態に合わせて切り替わる（例：駒の種類のフィールドが「クイーン」になったら、クイーンのプレハブに切り替わる）。

## やらないこと

- スクリプトから直接切り替えること（状態を変えると、リストの仕組みが切り替える）。
- プレハブに振る舞い（そのインスタンスだけに働く System）を持たせること。

## 決まっていること・決まっていないこと

- 決まっていること：
  - インターフェイスは TypeScript で書く。KokoState の形ではなく、プレハブのインターフェイスとして決める。
  - インターフェイスが合えば、元のプレハブが違っても切り替えられる。
  - 切り替えても、Entity・参照・実行中の値・上書きは、すべて残す。
  - 切り替えは、Inspector と、リストから子を組み立てる仕組みから行う。
- 設計者・実装者に任せること：インターフェイスの書き方（型の定義のリソースに書くか）、満たしているかの確かめ方。
- 計画者に聞くこと：
  - インターフェイスが決めるのは、いちばん上の Entity の KokoState だけか、子の Entity の形も含むか。
  - 切り替えたあと、新しいプレハブにしかない KokoState やフィールドは、新しいプレハブの初期値で足す、でよいか。前のプレハブにしかなかったものは、残すのか、外すのか。
  - スクリプトから、インスタンスがどのインターフェイスを満たすかを使えるか（例：`e.get()` のように、インターフェイスで読み書きする）。
