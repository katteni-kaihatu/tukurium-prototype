# プレハブのインターフェイスを決めてインスタンスを別のプレハブに切り替える

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

プレハブが持つ形（いちばん上の Entity と子の Entity が、どの KokoState とフィールドを持つか）を、TypeScript のインターフェイスとして決められる。同じインターフェイスを満たすプレハブ（バリアントを含む）どうしなら、インスタンスを、同じインスタンスのまま別のプレハブに切り替えられる。

たとえば、チェスのポーンが成ってクイーンになるとき、駒を消して作り直さずに、同じ駒のインスタンスのまま「ポーン」から「クイーン」に切り替える。Entity も、参照も、実行中の値も残る。ここが Unity のプレハブと違う所。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：状態に合わせて見た目や中身が変わるものを、作り直しの手間なしに作れる。
- 原則 4（一度作ったものを、何度でも、誰とでも使える）：同じインターフェイスを満たすプレハブを、入れ替えて使える。

## やること

- **プレハブのインターフェイス**：TypeScript で、プレハブが持つ KokoState とフィールドの形を、インターフェイスとして書ける。いちばん上の Entity だけでなく、子の Entity の形も含める。プレハブは、どのインターフェイスを満たすかを持ち、満たしているかを型で確かめる。
- **実行中もつながりを持ち続ける**：再生中も、どの Entity がどのプレハブのインスタンスか、子の Entity がプレハブのどの Entity に当たるかを持ち続ける（今は再生の手前で展開し、実行中はつながりがない）。実行中に切り替えるために要る。
- **切り替えられる条件**：切り替える前と後のプレハブが、同じインターフェイスを満たしていること。元のプレハブが違っても、インターフェイスが合えば切り替えられる。
- **子の Entity の対応**：切り替える前と後のプレハブの子の Entity は、インターフェイスに書いた子の名前で対応させる。インターフェイスにない子は、片方にしかないものとして扱う。
- **切り替えたときに残すもの**：
  - Entity（ID）。ほかの Entity からの参照も切れない。
  - インスタンスで足した Entity・KokoState・System。
  - 両方のプレハブにある KokoState・フィールド・子の Entity の、実行中の値と、インスタンスで上書きした所。
- **片方にしかないもの**：
  - 新しいプレハブにしかない KokoState・フィールド・子の Entity は、新しいプレハブの初期値で足す。
  - 前のプレハブにしかなかったものは、消す（そこへの上書きも消す）。
- **System**：切り替えに合わせて、動いている再生の System も足したり外したりする。新しいプレハブにしかない System は足す。前のプレハブにしかなかった System は、ほかにそれを使うインスタンスが残っていなければ外す。
- **切り替え方**
  - Inspector で、インスタンスのプレハブを選び直す。選べるのは、同じインターフェイスを満たすプレハブだけ。
  - ロードマップの「プレハブのリストから子を組み立てる」で、状態に合わせて切り替わる（例：駒の種類のフィールドが「クイーン」になったら、クイーンのプレハブに切り替わる）。

## やらないこと

- スクリプトから直接切り替えること（状態を変えると、リストの仕組みが切り替える）。
- プレハブに振る舞い（そのインスタンスだけに働く System）を持たせること。
- スクリプトから、インターフェイスを使って Entity を探したり読み書きしたりすること（例：`query: { prefab: Piece }` で、そのインターフェイスを満たすインスタンスだけを選ぶ。`e.child("見た目").get(Mesh)` のように、インターフェイスに書いた子の Entity に型付きで触れる）。必要になったら、別のロードマップの項目にする。

## 完了の条件

チェスで確かめる。

- 駒のインターフェイス（いちばん上の Entity の KokoState と、子の Entity「見た目」）を書き、ポーンとクイーンのプレハブがそれを満たす。満たしていないプレハブは、型エラーとして出る。
- Inspector で、置いたポーンのインスタンスをクイーンに切り替えられる。選べるのは、インターフェイスを満たすプレハブだけ。
- 再生中、ポーンが端まで進んで駒の種類が「クイーン」になると、リストの仕組みで、同じ駒のインスタンスのままクイーンに切り替わる。
  - Entity の ID と、ほかの Entity からの参照は残る。
  - 両方にある値（位置や「動いた回数」など）は、実行中の値のまま残る。
  - クイーンにしかない KokoState と子の Entity は、クイーンの初期値で足され、ポーンにしかなかったものは消える。
  - クイーンのプレハブにしかない System が動き始め、ポーンが一つも残っていなければ、ポーンにしかなかった System は止まる。
- インスタンスで足した Entity・KokoState・System は、切り替えても残る。

## 決まっていること・決まっていないこと

- 決まっていること：
  - インターフェイスは TypeScript で書く。KokoState の形ではなく、プレハブのインターフェイスとして決める。
  - インターフェイスが合えば、元のプレハブが違っても切り替えられる。
  - インターフェイスは、子の Entity の形も含める。
  - 切り替えても、Entity・参照は残す。両方にあるものは、実行中の値と上書きも残す。新しいプレハブにしかないものは初期値で足し、前のプレハブにしかなかったものは消す。
  - 切り替えは、Inspector と、リストから子を組み立てる仕組みから行う。
  - 実行中も、プレハブとのつながり（どのプレハブか、子の Entity の対応）を持ち続ける。
  - 子の Entity は、インターフェイスに書いた名前で対応させる。
  - System は、切り替えに合わせて足したり外したりする。
  - インスタンスで足したものは、切り替えても残す。
- 設計者・実装者に任せること：インターフェイスの書き方（型の定義のリソースに書くか）、満たしているかの確かめ方。
- 計画者に聞くこと：なし。
