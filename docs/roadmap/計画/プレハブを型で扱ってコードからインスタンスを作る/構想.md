# プレハブを型で扱ってコードからインスタンスを作る

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

プレハブを、ただの TypeScript の型で扱えるようにし、スクリプトから実行中にインスタンスを作れるようにする。プレハブを活かすための、いちばん初めの土台。

- プレハブを import すると、そのプレハブを表す型が二つ使える（C# や TypeScript のクラスと同じ関係）。
  - **プレハブ型**：作るためのもの（クラスそのもの、`typeof 駒` に当たる）。パラメータを受け取って、インスタンスを作る。
  - **インスタンス型**：作ったあとのもの（クラスのインスタンス、`駒` に当たる）。KokoState・フィールド・子の Entity を持つ。
  - どちらも、同じ構造でも、別のプレハブは当てはまらない。
- KokoState のフィールドや System の中で、プレハブをプレハブ型の値として持てる（例：「駒」のプレハブ型の値には、「駒」と、パラメータの合うそのバリアントを入れられる）。
- そのプレハブから、実行中にインスタンスを作れる。作るときに、プレハブが決めた**パラメータ**に値を渡して、初めの値を上書きできる（例：`world.spawn(Bullet, { Speed: 20, Damage: 5 })`）。

プレハブには、二つの役割がある。

- 編集中：同じものを楽に管理する（置いて使い回し、まとめて直す）。
- 実行中：動的に変わるもの（作る・消す・切り替える）を、安全に扱う。

この項目は、実行中の役割の土台になる。構造で当てはまるインターフェイス型は、ロードマップの「インターフェイス型でプレハブの構造を決めて入れ替えて使う」で、あとから足す。

## 原則とのつながり

- 原則 4（一度作ったものを、何度でも、誰とでも使える）：作ったプレハブを、スクリプトから何度でも作れる。
- 原則 5（安心して作れる）：どのプレハブが入るか、どの値を渡せるかが、型で確かめられる。

## やること

### プレハブ型・インスタンス型と、値を渡して作る

- **インスタンス型**：作ったインスタンスの型。当てはまるのは、そのプレハブとそのバリアントから作ったもの。バリアントは元のプレハブから Entity や KokoState を消さないので、継承と考え、バリアントのインスタンスは、いつでも元のプレハブのインスタンス型に当てはまる。
- **プレハブ型**：インスタンスを作るための型。パラメータを受け取って作る。
  - バリアントのプレハブは、パラメータが合うときだけ、元のプレハブのプレハブ型に当てはまる。バリアントが必須のパラメータを足したら当てはまらない（元のプレハブ型として作る人は、そのパラメータを渡さないため）。足したのが省略できるパラメータだけなら当てはまる。TypeScript で、子のクラスのコンストラクタが必須の引数を足すと、親のクラスの型に代入できないのと同じ。
  - バリアントに「省略できるパラメータしか足せない」といった制限はかけない。当てはまるかどうかは、型が決める。
- **プレハブを値として受け取る**：プレハブを、プレハブ型の値として扱える。KokoState のフィールドの型にも書ける。当てはまるかは、型で確かめる。
  - Inspector では、フィールドの値を、そのプレハブ型に当てはまるプレハブ（そのプレハブと、パラメータの合うバリアント）の中から選ぶ。
- **import**：
  - KokoState と型の定義のリソースは、プレハブ型とインスタンス型を import して使える。
  - System は、プレハブ・マテリアル・3D モデルなどのリソースの参照を、値として import できる（例：`import Bullet from "./Bullet.prefab"` のあとに `world.spawn(Bullet, …)`）。
  - フィールドの値や import で指したプレハブも、マテリアルや素材の参照と同じく、依存グラフ・抽出・ライブラリで一緒にたどる。
- **パラメータ**：プレハブで、外から受け取る値（パラメータ）を決められる。
  - パラメータは、プレハブの中のフィールド（いちばん上の Entity のものも、子の Entity のものも）を一つずつ指定して作る。例：Bullet のプレハブで、Speed と Damage のフィールドをパラメータにする。
  - パラメータには名前を付ける。子の Entity のフィールドなど、フィールドの名前が重なることがあるので、名前は自分で決められる（初めはフィールドの名前）。一つのプレハブの中で、パラメータの名前は重ならない。
  - パラメータごとに、次の設定を持つ。
    - **必須**：渡さないと型エラー。
    - **省略できる**（初めの設定）：渡さなければ、プレハブの値を使う。
    - **説明**：コードホバーに出す。
  - 実行中に作るとき（`world.spawn` とリスト）に外から渡せるのは、パラメータだけ。ほかのフィールドは、プレハブの値のまま（使う側が、プレハブの中の構造を知らなくて済む）。制作データに置いたインスタンスは、これとは関係なく、今のまま、どのフィールドでも変えられる。
  - 制作データに置いたインスタンスで、必須のパラメータの値を決めていなければ、問題（エラー）として出す。
  - プレハブを編集していて、パラメータが指すフィールドや子の Entity を消そうとしたときは、確認を出す。消したら、そのパラメータは問題（エラー）として出す。実行中は、プレハブの中身は変わらないので、パラメータが指すものは消えない。
  - バリアントで足すパラメータも、元のプレハブのパラメータと同じ名前にはできない。
  - パラメータは、プレハブの「プレハブの設定」にまとめて並ぶ。プレハブを編集しているときは、パラメータにしたフィールドが、Inspector の個々のフィールドでも目立つように見える。
  - 制作データに置いたインスタンスでも、Inspector の「プレハブの設定」に、パラメータがまとめて並び、そこで値を変えられる。個々のフィールドでも、パラメータのフィールドは目立つように見える。
- **値を渡してインスタンスを作る**：スクリプトから、プレハブのインスタンスを実行中に作れる（例：`world.spawn(Bullet, { Speed: 20, Damage: 5 })`）。
  - 第二引数に、パラメータの名前と値の組を渡すと、そのフィールドの初めの値を上書きして作る。
  - 渡せるパラメータと値の型は、プレハブから型で決まる。ないパラメータや、合わない値、必須のパラメータが足りないときは、型エラーになる。
  - 同じ渡し方を、ロードマップの「プレハブのリストから子を組み立てる」でも使う。
- 作ったインスタンスは、すぐに現れる。同じフレームのあとの処理からも見える。
- セッションに出した配置を「適用」で更新するときは、実行中に作ったインスタンスをすべて消す。将来は、適用のやり方を選べるようにしたい。
- 実行中に作ったインスタンスは、どのプレハブから作ったかを、実行中も持ち続ける（リストで切り替えるため）。このつながりは、ホストが抜けて別の人が再生を引き継ぐときの実行状態にも含める。
- 実行中に作ったプレハブが System を持っていて、その System がまだ動いていなければ、動いている再生に足す（プレハブの System は、アウトプットの System に足し合わせる。ADR 0076）。セッションでは、足した System の権限も、今と同じくコードから読み取って確かめる（ADR 0012）。

### 実行の仕組み：作る・消す・切り替える・書くのは、すぐ

プレハブを実行中に扱う土台として、この項目で先に作る。

- 作る・消す・リストの切り替えは、呼んだその場ですぐ行う。作ったものは、同じフレームのあとの処理からも見える。
- そのかわり、System に Entity を渡す前に、実行環境が、その Entity がまだあり、まだ Query に合うかを確かめる。消えた Entity や、切り替えで Query に合わなくなった Entity は、そこで飛ばす。System の呼び出しが始まるときには、受け取った Entity（`e`）は必ずあり、Query に合っている。
- 確かめの重さ：今の実行環境は、System に渡す Entity をまとめて実行環境（QuickJS）に送り、その中で順に回している。一つの呼び出しの間に Entity を消したり切り替えたりできるのは、その System 自身だけ（一度に一つの System しか動かない）。そのため、確かめは、呼び出しの中で「この呼び出しで消えた・切り替わった Entity」の一覧を持ち、順に回すときにそれと照らすだけで済む。Entity ごとに実行環境の外へ問い合わせることはしない。
- **書き込みもすぐ届く**：`e.get(X).y = 1` のような書き込みも、その場で届く（今は、System の呼び出しが終わってからまとめて届く）。書いたあとに、ほかの読み方（`world.get`・参照からの読み込み・リスト）で読んでも、書いた値になる。リストへの書き込みで起きる切り替えも、その場で起きる。今の「まとめて届ける」作りより遅くならないかを、`pnpm bench:sim` で確かめる。
- 一つの呼び出しの中で、自分で消したり切り替えたりした Entity を、そのあと読み書きした場合は、この項目では型で防がない（型で守るのは、ロードマップの「実行中に現れるものをプレハブで決めて静的に安全にする」）。実行環境が、その読み書きを行わず、問題として出す。
### AI エージェント

- AI エージェントも、人と同じく、プレハブを型の付いた値として扱い、パラメータを決められる。

## やらないこと

- 構造で当てはまるインターフェイス型（ロードマップの「インターフェイス型でプレハブの構造を決めて入れ替えて使う」で扱う）。
- 制作データに置いたインスタンスを、別のプレハブに切り替えること。切り替えは、リストで実行中に作ったインスタンスだけ（ロードマップの「プレハブのリストから子を組み立てる」）。プレハブの中の参照には、制限をかけない。
- プレハブに振る舞い（そのインスタンスだけに働く System）を持たせること。
- 名前と KokoState を文字で指定して作る、今の `world.spawn` をやめること（ロードマップの「実行中に現れるものをプレハブで決めて静的に安全にする」で扱う）。この項目の始めに、静的に危ない Host API と書き方すべてに `@deprecated` と理由を付ける（代わりの書き方がまだないものは「追加予定」と書く。ロードマップの「実行中に現れるものをプレハブで決めて静的に安全にする」の「危ないものに印を付ける」）。今の書き方は、並べて使えるまま残す。

## 完了の条件

- Bullet のプレハブで Speed（必須）と Damage（省略できる）をパラメータにし、`world.spawn(Bullet, { Speed: 20 })` で作ると、Speed は 20、Damage はプレハブの値で作られる。Speed を渡さない・ないパラメータを渡す・型の合わない値を渡すと、型エラーになる。Bullet のプレハブが持つ System が、アウトプットに Bullet のインスタンスがなくても、作った Bullet で動く。
- 制作データに置いた Bullet のインスタンスで、Inspector の「プレハブの設定」にパラメータが並び、値を変えられる。パラメータのフィールドは、個々のフィールドでも目立つ。
- 「駒」のプレハブ型のフィールドに、「駒」と、パラメータの合うバリアントは入れられる。必須のパラメータを足したバリアントと、同じ構造の別のプレハブは入れられない（型エラー）。Inspector では、当てはまるプレハブだけが選べる。
- `world.spawn` で作ったバリアントのインスタンスは、元のプレハブのインスタンス型に当てはまる。
- 静的に危ない Host API と書き方に `@deprecated` が付き、エディタで打ち消し線が出て、コードホバーで理由（代わりがないものは「追加予定」）が読める。
- ホストが抜けて別の人が再生を引き継いでも、実行中に作ったインスタンスは、どのプレハブから作ったかを持ったまま。
- `e.get(X).y = 1` で書いたあと、`world.get` で読むと、書いた値になっている。
- 一つの System の中で、実行中に作ったインスタンスを消すと、そのあとの Entity の順番では、消えたものが渡されない。

## 決まっていること・決まっていないこと

- 決まっていること：
  - 型は、ただの TypeScript の型。この項目では、プレハブ型（作るため。バリアントはパラメータが合うときだけ当てはまる）とインスタンス型（作ったあと。バリアントはいつも当てはまる）を作る。
  - KokoState のフィールドに書けるのは、プレハブ型とインスタンス型。
  - プレハブは、パラメータ（名前・指すフィールド・必須か省略できるか・説明）を決められる。実行中に作るとき外から渡せるのはパラメータだけ（制作データに置いたインスタンスは関係なく、どのフィールドでも変えられる）。
  - 制作データに置いたインスタンスで必須のパラメータが埋まっていなければ、エラーにする。パラメータが指すものを編集中に消すときは確認を出し、消したらエラーにする。
  - パラメータの名前は、バリアントで足すものも含めて重ならない。
  - 実行中にインスタンスを作るとき、第二引数で、パラメータの名前と値の組を渡せる。この渡し方はリストでも使う。
  - パラメータは「プレハブの設定」にまとまり、個々のフィールドでも目立つように見える。
  - KokoState と型の定義はプレハブ型とインスタンス型を import でき、System はプレハブ・マテリアル・3D モデルの参照を import できる。
  - 切り替えは、リストで実行中に作ったインスタンスだけ。制作データに置いたインスタンスは切り替えない。
  - 適用のときは、実行中に作ったインスタンスをすべて消す。
  - 作る・消す・切り替える・書くのは、すぐ行う。System に Entity を渡す前に、まだあるか・Query に合うかを確かめる。
  - AI エージェントも同じことができる。
- 設計者・実装者に任せること：プレハブを値として表す型の書き方。
- 計画者に聞くこと：なし。
