# プレハブを型で扱ってコードからインスタンスを作る

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

プレハブを、ただの TypeScript の型で扱えるようにし、スクリプトから実行中にインスタンスを作れるようにする。プレハブを活かすための、いちばん初めの土台。

- プレハブを import すると、そのプレハブを直接表す型（プレハブの型）が使える。当てはまるのは、そのプレハブと、そのバリアントだけ（C# のクラス型に近い）。同じ構造でも、別のプレハブは当てはまらない。
- KokoState のフィールドや System の中で、プレハブを型の付いた値として持てる（例：ポーンの型なら、ポーンとそのバリアント）。
- そのプレハブから、実行中にインスタンスを作れる。作るときに、初めの値を上書きするデータを、型の付いた形で渡せる（例：`world.spawn(弾, { 向き, 速さ })`）。

プレハブには、二つの役割がある。

- 編集中：同じものを楽に管理する（置いて使い回し、まとめて直す）。
- 実行中：動的に変わるもの（作る・消す・切り替える）を、安全に扱う。

この項目は、実行中の役割の土台になる。構造で当てはまるインターフェイス型は、ロードマップの「インターフェイス型でプレハブの構造を決めて入れ替えて使う」で、あとから足す。

## 原則とのつながり

- 原則 4（一度作ったものを、何度でも、誰とでも使える）：作ったプレハブを、スクリプトから何度でも作れる。
- 原則 5（安心して作れる）：どのプレハブが入るか、どの値を渡せるかが、型で確かめられる。

## やること

### プレハブの型と、値を渡して作る

- **プレハブの型**：プレハブを import すると、そのプレハブを直接表す型が使える。当てはまるのは、そのプレハブと、そのバリアント（バリアントは元のプレハブから Entity や KokoState を消さないので、継承と考える）。同じ構造でも、別のプレハブは当てはまらない。
- **プレハブを値として受け取る**：プレハブを、プレハブの型で型の付いた値として扱える。KokoState のフィールドの型にも書ける。当てはまるかは、型で確かめる。
  - Inspector では、フィールドの値を、その型に当てはまるプレハブ（そのプレハブとバリアント）の中から選ぶ。
- **import**：
  - KokoState と型の定義のリソースは、プレハブの型を import して使える。
  - System は、プレハブ・マテリアル・3D モデルなどのリソースの参照を、値として import できる（例：`import 弾 from "./弾.prefab"` のあとに `world.spawn(弾, …)`）。
  - フィールドの値や import で指したプレハブも、マテリアルや素材の参照と同じく、依存グラフ・抽出・ライブラリで一緒にたどる。
- **値を渡してインスタンスを作る**：スクリプトから、プレハブのインスタンスを実行中に作れる（例：`world.spawn(弾, 上書きの値)`）。
  - 第二引数に、プレハブの形に合った「上書きの値」を渡すと、初めの値を上書きして作る。
  - 上書きの値の形は、プレハブの形から型で決まる。合わない値は型エラーになる。
  - 上書きの値のデータの形は、ロードマップの「プレハブのリストから子を組み立てる」でも使う。
- 作ったインスタンスは、すぐに現れる。同じフレームのあとの処理からも見える。
- セッションに出した配置を「適用」で更新するときは、実行中に作ったインスタンスをすべて消す。将来は、適用のやり方を選べるようにしたい。
- 実行中に作ったインスタンスは、どのプレハブから作ったかを、実行中も持ち続ける（リストで切り替えるため）。このつながりは、ホストが抜けて別の人が再生を引き継ぐときの実行状態にも含める。
- 実行中に作ったプレハブが System を持っていて、その System がまだ動いていなければ、動いている再生に足す（プレハブの System は、アウトプットの System に足し合わせる。ADR 0076）。セッションでは、足した System の権限も、今と同じくコードから読み取って確かめる（ADR 0012）。

### 実行の仕組み：作る・消す・切り替える・書くのは、すぐ

プレハブを実行中に扱う土台として、この項目で先に作る。

- 作る・消す・リストの切り替えは、呼んだその場ですぐ行う。作ったものは、同じフレームのあとの処理からも見える。
- そのかわり、System に Entity を渡す前に、実行環境が、その Entity がまだあり、まだ Query に合うかを確かめる。消えた Entity や、切り替えで Query に合わなくなった Entity は、そこで飛ばす。System の呼び出しが始まるときには、受け取った Entity（`e`）は必ずあり、Query に合っている。
- 確かめの重さ：今の実行環境は、System に渡す Entity をまとめて実行環境（QuickJS）に送り、その中で順に回している。一つの呼び出しの間に Entity を消したり切り替えたりできるのは、その System 自身だけ（一度に一つの System しか動かない）。そのため、確かめは、呼び出しの中で「この呼び出しで消えた・切り替わった Entity」の一覧を持ち、順に回すときにそれと照らすだけで済む。Entity ごとに実行環境の外へ問い合わせることはしない。
- **書き込みもすぐ届く**：`e.get(X).y = 1` のような書き込みも、その場で届く（今は、System の呼び出しが終わってからまとめて届く）。書いたあとに、ほかの読み方（`world.get`・参照からの読み込み・リスト）で読んでも、書いた値になる。リストへの書き込みで起きる切り替えも、その場で起きる。今の「まとめて届ける」作りより遅くならないかを、`pnpm bench:sim` で確かめる。
- 一つの呼び出しの中で、自分で消したり切り替えたりした Entity を、そのあと読み書きした場合は、この項目では型で防がない（型で守るのは、ロードマップの「実行中に現れるものをプレハブで決めて静的に安全にする」）。実行環境が、その読み書きを行わず、問題として出す。
### AI エージェント

- AI エージェントも、人と同じく、プレハブを型の付いた値として扱える。

## やらないこと

- 構造で当てはまるインターフェイス型（ロードマップの「インターフェイス型でプレハブの構造を決めて入れ替えて使う」で扱う）。
- 制作データに置いたインスタンスを、別のプレハブに切り替えること。切り替えは、リストで実行中に作ったインスタンスだけ（ロードマップの「プレハブのリストから子を組み立てる」）。プレハブの中の参照には、制限をかけない。
- プレハブに振る舞い（そのインスタンスだけに働く System）を持たせること。
- 名前と KokoState を文字で指定して作る、今の `world.spawn` をやめること（ロードマップの「実行中に現れるものをプレハブで決めて静的に安全にする」で扱う）。この項目の始めに、静的に危ない Host API と書き方すべてに `@deprecated` と理由を付ける（代わりの書き方がまだないものは「追加予定」と書く。ロードマップの「実行中に現れるものをプレハブで決めて静的に安全にする」の「危ないものに印を付ける」）。今の書き方は、並べて使えるまま残す。

## 完了の条件

- 弾のプレハブを import し、`world.spawn(弾, { 向き, 速さ })` で、値を上書きしてインスタンスを作れる。形に合わない値を渡すと型エラーになる。弾のプレハブが持つ System が、アウトプットに弾のインスタンスがなくても、作った弾で動く。
- ポーンの型のフィールドに、ポーンとそのバリアントは入れられ、同じ構造の別のプレハブは入れられない。Inspector では、当てはまるプレハブだけが選べる。
- 静的に危ない Host API と書き方に `@deprecated` が付き、エディタで打ち消し線が出て、コードホバーで理由（代わりがないものは「追加予定」）が読める。
- ホストが抜けて別の人が再生を引き継いでも、実行中に作ったインスタンスは、どのプレハブから作ったかを持ったまま。
- `e.get(X).y = 1` で書いたあと、`world.get` で読むと、書いた値になっている。
- 一つの System の中で、実行中に作ったインスタンスを消すと、そのあとの Entity の順番では、消えたものが渡されない。

## 決まっていること・決まっていないこと

- 決まっていること：
  - 型は、ただの TypeScript の型。この項目では、プレハブの型（import で使える。そのプレハブとバリアントだけが当てはまる）だけを作る。
  - KokoState のフィールドに書けるのは、プレハブの型。
  - 実行中にインスタンスを作るとき、第二引数で、型の付いた上書きの値を渡せる。この形はリストでも使う。
  - KokoState と型の定義はプレハブの型を import でき、System はプレハブ・マテリアル・3D モデルの参照を import できる。
  - 切り替えは、リストで実行中に作ったインスタンスだけ。制作データに置いたインスタンスは切り替えない。
  - 適用のときは、実行中に作ったインスタンスをすべて消す。
  - 作る・消す・切り替える・書くのは、すぐ行う。System に Entity を渡す前に、まだあるか・Query に合うかを確かめる。
  - AI エージェントも同じことができる。
- 設計者・実装者に任せること：プレハブを値として表す型の書き方。
- 計画者に聞くこと：
  - 上書きの値のデータの形（計画者がこれから考える）。
