# インターフェイス型でプレハブの構造を決めて入れ替えて使う

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

プレハブの構造（いちばん上の Entity と子の Entity が、どの KokoState とフィールドを持つか）を表す型（インターフェイス型）を、TypeScript で書いて定義できる。構造が合うプレハブは、元のプレハブが違っても、同じインターフェイス型に当てはまる（C# のインターフェイス型に近いが、宣言は要らず、TypeScript と同じく構造で決まる）。

ふつうの一つのプロジェクトでは、プレハブ型とインスタンス型（ロードマップの「プレハブを型で扱ってコードからインスタンスを作る」）で足りる。インターフェイス型は、ライブラリのように広く使うものや、これから足す予定のジェネリクス（ロードマップの「型を指定してKokoStateのテンプレートを使う」）と組み合わせて使うためのもの。

## 原則とのつながり

- 原則 4（一度作ったものを、何度でも、誰とでも使える）：元が違っても構造の合うプレハブを、入れ替えて使える。ライブラリのように広く使うものも作れる。

## やること

- **インターフェイス型**：TypeScript の型で、プレハブが持つ KokoState とフィールドの構造を書ける。いちばん上の Entity だけでなく、子の Entity の構造も含める。どのプレハブも指さずに、構造だけを書く。構造が合うプレハブは、宣言しなくても当てはまる。インスタンス型を広げて、インターフェイス型を作ることもできる。
- **インスタンスの側**：インスタンス型を使える所（作ったインスタンスを指す参照、KokoState のフィールドの型、パラメータの型）には、インターフェイス型も使える。構造が合うインスタンスなら、元のプレハブが違っても当てはまる。
- **作る側**：プレハブ型を使える所（`world.spawn` に渡すプレハブ、リストで受け付けるプレハブ、KokoState のフィールドの型）には、「インスタンスがインターフェイス型に当てはまり、決まったパラメータを受け取るプレハブ」を表す型を使える。当てはまるかは、インスタンスの構造とパラメータの両方で決まる（パラメータの合わせ方は、プレハブ型と同じ）。Inspector では、当てはまるプレハブの中から選ぶ。
- **リストでの切り替え**：リストの型がインターフェイス型のときは、構造が合う、元の違うプレハブどうしでも切り替えられる。
  - 切り替えで残すのは、インターフェイス型に書いた KokoState・フィールド・子の Entity だけ。子の Entity は、インターフェイス型に書いた子の名前で対応させる。
  - それ以外は、前のプレハブのものを消し、新しいプレハブのものを初期値で足す。
  - インターフェイス型に書いたもののうち、実行中の値を残すか、新しいプレハブの値にするかは、この項目で決める（元の違うプレハブどうしには、バリアントの差分のような「元との差」がないため。リストの構想の、バリアントの差分を入れ替える決まりを手本にする）。
  - 残したフィールドの値が参照なら、その指す先もインターフェイス型の中（残るもの）になるので、切り替えても壊れない。
- KokoState と型の定義のリソースは、インターフェイス型を import して使える。ライブラリで配れる。
- AI エージェントも、人と同じく、インターフェイス型を書いて使える。

## やらないこと

- プレハブに、どのインターフェイス型に当てはまるかを宣言させること（構造で決まる）。
- スクリプトから、インターフェイス型を使って Entity を探したり読み書きしたりすること（例：`query: { prefab: Piece }`、`e.child("見た目").get(Mesh)`）。必要になったら、別のロードマップの項目にする。

## 決まっていること・決まっていないこと

- 決まっていること：
  - インターフェイス型は、ただの TypeScript の型。構造で当てはまり、宣言は要らない。子の Entity の構造も含める。
  - リストの型がインターフェイス型なら、切り替えで残すのはインターフェイス型に書いたものだけ。
- 設計者・実装者に任せること：インターフェイス型の書き方（型の定義のリソースに書くか）。
- 計画者に聞くこと：
  - 元の違うプレハブどうしを切り替えるとき、インターフェイス型に書いたフィールドの値を、実行中の値のまま残すか、新しいプレハブの値にするか。

## 関係するもの

- 前に終わっている必要があるもの：ロードマップの「実行中に現れるものをプレハブで決めて静的に安全にする」（構造の違うものが入れ替わると、消えるものが増えるので、型で守る仕組みを先に作る）
- ロードマップの「プレハブを型で扱ってコードからインスタンスを作る」（プレハブ型とインスタンス型）
- ロードマップの「プレハブのリストから子を組み立てる」（リストの型にインターフェイス型も使えるようにする）
- ロードマップの「型を指定してKokoStateのテンプレートを使う」（ジェネリクスと組み合わせて使う）
