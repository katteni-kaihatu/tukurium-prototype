# KokoStateに型付きのレコード・リスト・マップを持てる

- 状態：作成中
- 計画者：れにうむ
- 作成完了日：

## やりたいこと

KokoState の欄に、数や文字や `vec3` だけでなく、型の決まったレコード（いくつかの欄の組）・リスト・マップを持てる。欄の参照（どの KokoState のどの欄か、どの Entity のどの欄か）も値として持てる。Inspector と System の両方で扱え、入れ子の値も型を確かめたうえで保存・復元できる。

たとえば、チェスの盤（マスの名前から駒へのマップ）、トランプの手札（カードのレコードのリスト）、「的 3 の `Health.hp`」を出すゲージが、欄を並べる工夫なしに作れる。

## 原則とのつながり

- 原則 2（入口は低く、奥は深い）：盤面・手札・持ち物のようなまとまったデータを、欄を並べる工夫なしに作れる。
- 原則 4（一度作ったものを、何度でも、誰とでも使える）：名前を付けたレコードの形を、いくつもの KokoState で使い回せる。
- 原則 5（安心して作れる）：入れ子の値も型で確かめるので、壊れた値が保存されない。

## やること

### 新しい欄の型

| 型 | 中身 | 例 |
| --- | --- | --- |
| レコード | 名前と型の決まった欄の組 | カード：`{ suit: 文字, rank: 数 }` |
| リスト | 同じ型の値の並び | 手札：カードのリスト |
| マップ | 文字のキーから、同じ型の値への対応 | 盤：`"e4"` → 駒 |
| 欄の参照 | KokoState と欄の組（例：`Health.hp`） | ゲージに「どの欄を出すか」 |
| Entity の欄の参照 | Entity・KokoState・欄の組（例：「的 3 の `Health.hp`」） | ゲージに「どの値を出すか」 |

- レコード・リスト・マップは入れ子にできる（例：リストのマップ、レコードのリスト）。
- レコードの形は、欄ごとにその場で決めることも、名前を付けた形（例：`Card`）をリソースとして作り、いくつもの欄や KokoState から使うこともできる。
- 欄の参照は、欄の名前ではなく ID で結び付ける。欄や KokoState の名前を変えても切れない。

### 空の値

- リストとマップは空でよい。
- 欄の参照・Entity の欄の参照は「なし」でよい（今の Entity の参照と同じ）。
- レコードの中の欄は、必ず値を持つ。

### Inspector

- 入れ子の値を、見る・足す・消す・並べ替える・直すことができる。
- 欄の参照は、KokoState と欄を選んで決める。Entity の欄の参照は、Entity も選ぶ。

### System

- 型の付いた値として読み書きできる（ロードマップの「スクリプトをすべてTypeScriptで書く」の型に載る）。レコードの欄の名前の打ち間違いや、リストに違う型の値を入れたことは、型の誤りとして出る。
- Entity の欄の参照から、その値を読み書きできる。欄の参照は、Entity と組み合わせて読み書きする（例：ゲージに決めた `Health.hp` を、選んだ的から読む）。
- ほかの Entity の値を参照から読み書きするときも、今の `world.get()`・`world.set()` と同じ権限の決まりに従う。

### 保存・復元・共同編集

- 保存・復元のときに、入れ子の値の型を確かめる。合わない値は問題として出す。
- 同じリストやマップの別の要素を 2 人が同時に変えても、両方の変更が残る（今、同じ Entity の別の欄を同時に変えたときと同じ）。
- 「維持」を付けた入れ子の欄は、適用したあと、欄をまるごと引き継ぐ。中の一部だけを維持することはしない。

## やらないこと

- 型の引数を持つ形（`Deck<T>` など）。ロードマップの「型を指定してKokoStateのテンプレートを使う」で扱う。
- KokoState の種類そのものの参照（「どの KokoState か」だけを持つ値）と、ある Entity に付いた KokoState まるごとの参照。
- マップのキーを、文字以外（数・Entity など）にすること。
- レコードの中の欄を省略できるようにすること。
- 入れ子の中の一部だけに「維持」を付けること。

## 完了の条件

- Inspector で、チェスの盤（マスの名前から駒のレコードへのマップ）とトランプの手札（カードのレコードのリスト）を作り、直し、保存して開き直すと元どおりに戻る。
- 名前を付けたレコードの形を、二つの KokoState で使える。
- System から盤と手札を読み書きでき、レコードの欄の名前の打ち間違いが型の誤りとして出る。
- ゲージのような KokoState に欄の参照（`Health.hp`）と Entity の欄の参照（「的 3 の `Health.hp`」）を持たせ、System からその値を読める（欄の参照は、選んだ Entity と組み合わせて読む）。欄や KokoState の名前を変えても参照が切れない。
- 型の合わない値を保存しようとしたとき、または読み込んだときに、問題として出る。
- 2 人が同じリストの別の要素を同時に変えても、両方の変更が残る。
- 「維持」を付けた入れ子の欄が、適用したあとも値を保つ。

## 決まっていること・決まっていないこと

- 決まっていること：
  - 欄の参照は、KokoState と欄の組、Entity・KokoState・欄の組の 2 つ。
  - レコードの形は、その場で決めることも、名前を付けてリソースにすることもできる。
  - マップのキーは文字だけ。
  - 共同編集では、要素ごとに変更を残す。
  - 「維持」は、欄をまるごと引き継ぐ。
  - 空の値：リストとマップは空でよい、参照は「なし」でよい、レコードの中の欄は必ず値を持つ。
- 設計者・実装者に任せること：
  - 入れ子の深さ、リストやマップの大きさの上限。
  - 保存の形、共同編集で要素ごとに変更を残す仕組み。
  - Inspector で大きなリストやマップを見やすくする方法。
- 計画者に聞くこと：
  - 項目の名前。欄の参照も入ったので、名前を変えるか。
  - 欄の参照に、指せる欄の型を付けるか（例：「数の欄だけを指せる参照」にして、ゲージに文字の欄を指定できないようにする）。
  - 参照している Entity・KokoState・欄が消えたときにどうするか（「なし」に戻すか、問題として出すか）。
  - 名前を付けたレコードの形を変えたとき、すでにある値をどうするか（例：足した欄は初期値で埋める、消した欄は捨てる、型が変わった欄は問題として出す）。
