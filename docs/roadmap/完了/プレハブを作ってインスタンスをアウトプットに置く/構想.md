# プレハブを作ってインスタンスをアウトプットに置く

- 状態：完了
- 計画者：れにうむ
- 作成完了日：2026-11-11

## やりたいこと

Entity・KokoState・System のまとまりを、プレハブとしてリソースに登録できる。プレハブのインスタンスを、アウトプットの中に置ける。元のプレハブに変更を加えると、すべてのインスタンスにも反映される。インスタンスで変えたことを、確認してプレハブに適用し、それを正として保存することもできる。

プレハブは部品で、アウトプットは作品。プレハブはリソースとして作り、それだけをセッションに出すことはない。

## 原則とのつながり

- 原則 4（一度作ったものを、何度でも、誰とでも使える）：一度作った的や駒を、何個でも置き、まとめて直せる。

## やること

### プレハブを作る

- 次の二つの方法で作れる。
  - **新しく作る**：空のプレハブを作る。
  - **アウトプットの Entity から作る**：アウトプットの中の Entity（子を含む）を選び、プレハブにする。元の Entity は、そのプレハブのインスタンスに置き換わる。ほかの Entity から元の Entity とその子への参照は、置き換えたあとのインスタンスと、その中の対応する Entity を指したまま切れない。どの Entity がプレハブのどの Entity に対応しているかが分かる。
- プレハブには、Entity（子を含む）・KokoState・System を含められる。
- System は、アウトプットと同じ扱いにする。プレハブに含めた System は、そのインスタンスを入れたアウトプットで動く。
- プレハブの中に、別のプレハブのインスタンスを置ける（例：「盤」のプレハブに「駒」のプレハブを置く）。プレハブが自分自身を含むことはできない。
- プレハブはリソースなので、名前を変えたり、フォルダに動かしたりできる。

### プレハブを編集する

- アウトプットと同じように、プレハブの中の Entity の並びを Hierarchy で開き、Inspector で直せる。
- 編集する場所は、プレハブの設定で決める（アウトプットのワールドとアイテムのように）。
  - **その場で編集する**（初めの設定）：小さなプレハブ向け。今いるワークスペースの空間に出して直す。インスタンスから開いたときは、そのインスタンスと重ならないように、少しずらした所に出す。
  - **離れた空間で編集する**：大きなプレハブ向け。ワールドの編集のように、セッションから離した空間で直す。
- 元のプレハブに変更を加えると、ワークスペースの中のすべてのインスタンスにも反映される。セッションに出した配置には、今と同じく「適用」したときに届く。

### インスタンスを置いて変える

- プレハブを、リソース ID で参照して、アウトプットの中にインスタンスとして置く。名前や置き場所を変えても、参照は切れない。
- インスタンスごとに、場所・向き・大きさを決められる。これはインスタンスそのものの置き方なので、「変えた所」には数えず、プレハブに適用もしない。
- インスタンスは、Inspector と Hierarchy で変えられる。
  - フィールドの値を変える。
  - Entity・KokoState・System を足す。
  - Entity を並べ替える、親を付け替える（プレハブから来た Entity も、インスタンスで足した Entity も）。
- **消すことだけはできない。** インスタンスで、プレハブから来た Entity・KokoState・System を消すことはできない（プレハブとの対応が切れるため）。インスタンスで足したものは消せる。決まりは「プレハブから来たものは、インスタンスで消せない。ほかは変えられる」の一つにする。
- インスタンスそのものは、ふつうの Entity と同じく消せる。
- 複製：インスタンスの親（ルート）を複製すると、同じプレハブのインスタンスが一つ増える（上書きも写す）。インスタンスの中の Entity を複製すると、インスタンスで足した Entity として扱う。
- 付け替えた先の親（またはインスタンスで足した Entity の親）が、プレハブ側で消えたときは、消えた親のさらに親に付け替わる。その親も消えていれば、もう一つ上に付け替わる。
- 親子が輪になる付け替え（親を自分の子の下に付けるなど）は、できないようにする。
- インスタンスで変えた所は、プレハブに変更を加えても残る。変えていない所には、プレハブの変更が反映される。
- Inspector と Hierarchy で、インスタンスの中のプレハブから来た Entity・KokoState・System と、インスタンスで足したものを見分けられる。
- インスタンスで変えた所（フィールドの値・並び順・親・足したもの）に印を付け、一つずつプレハブの形に戻せる（今の「最後の保存から変わった所に印を付け、戻せる」と同じ考え方）。
- **プレハブに適用する**：インスタンスで変えたことを、確認したうえでプレハブに書き戻し、それを正として保存する。ほかのインスタンスにも反映される。ライブラリのプレハブには適用できない（ライブラリの中身は変えられないため）。
- **ふつうの Entity に戻す**：プレハブとのつながりを切る。戻したあとは、プレハブに変更を加えても反映されない。入れ子のときは、戻したインスタンスだけがふつうの Entity になり、その中にある別のプレハブのインスタンスは、インスタンスのまま残る。
- プレハブを消したときは、インスタンスを残して、問題として出す（今のリソースの参照が切れたときと同じ）。

### ライブラリ

- 公開されたライブラリのプレハブは、利用者が選んだバージョンを参照する。バージョンを上げるまで、元の変更は反映されない。
- ライブラリのプレハブの中身は変えられないが、そのインスタンスでは、ほかのプレハブと同じく変えられる（フィールドの値・足す・並べ替え・親の付け替え）。

### AI エージェント

- AI エージェントも、人と同じく、プレハブを作る・置く・直す・適用することができる。エージェントの「プレハブに適用する」は、確認なしで行う。

## やらないこと

- プレハブだけをセッションに出すこと。
- インスタンスで、プレハブから来た Entity・KokoState・System を消すこと。
- インスタンスで変えたことに名前を付け、別のリソースとして使い回すこと（ロードマップの「プレハブの一部を上書きしてバリアントを作る」で扱う）。
- プレハブのリストから子を組み立てること（ロードマップの「プレハブのリストから子を組み立てる」で扱う）。

## 完了の条件

- 的の Entity・KokoState・System を、アウトプットの Entity からプレハブにできる。空のプレハブも作れる。
- 的のプレハブのインスタンスを、一つのアウトプットに 3 つ置き、それぞれ場所を変えられる。再生すると、3 つともプレハブの System で動く。
- プレハブを Hierarchy と Inspector で直すと、3 つのインスタンスすべてに反映される。
- インスタンスの一つで、フィールドの値を変え、KokoState・子の Entity・System を足し、プレハブから来た Entity を並べ替えたり親を付け替えたりできる。付け替えた先の親をプレハブ側で消すと、そのさらに親に付け替わる。プレハブに変更を加えても、変えた所は残る。プレハブから来たものは消せない。
- インスタンスの中で、プレハブから来たものと足したものが見分けられ、変えた所に印が付く。印から一つずつプレハブの形に戻せる。
- そのインスタンスで「プレハブに適用する」を押して確認すると、変えたことがプレハブに保存され、ほかの 2 つにも反映される。
- インスタンスの親を複製すると、同じプレハブのインスタンスが一つ増える。インスタンスの中の Entity を複製すると、足した Entity として扱われる。
- 「盤」のプレハブに「駒」のプレハブのインスタンスを置き、「駒」を直すと、盤の中の駒にも反映される。
- 編集する場所を「その場」と「離れた空間」で切り替えられる。初めは「その場」。
- インスタンスの一つをふつうの Entity に戻すと、それ以降はプレハブに変更を加えても反映されない。
- プレハブを消すと、インスタンスは残り、問題として出る。
- プレハブの名前を変えたり動かしたりしても、インスタンスとのつながりは切れない。
- ライブラリのプレハブを、選んだバージョンのまま使える。
- AI エージェントが、プレハブを作り、インスタンスを置いて変え、プレハブに適用できる。

## 決まっていること・決まっていないこと

- 決まっていること：
  - プレハブは部品で、リソースとして作る。セッションには出さない。
  - プレハブは、新しく作るか、アウトプットの Entity から作る。
  - プレハブは Entity・KokoState・System を含められる。System はアウトプットと同じ扱い。
  - プレハブの中に、別のプレハブのインスタンスを置ける。
  - プレハブは、アウトプットと同じように Hierarchy と Inspector で編集する。編集する場所は、プレハブの設定で「その場」と「離れた空間」から選ぶ。初めは「その場」。
  - インスタンスはアウトプットの中に置き、場所・向き・大きさを決められる。
  - インスタンスでは、フィールドの値を変え、Entity・KokoState・System を足し、並べ替えと親の付け替えができる。プレハブから来たものは消せない。
  - 付け替えた先の親が消えたら、さらに親に付け替わる。輪になる付け替えはできない。
  - AI エージェントも、人と同じくプレハブを作る・置く・直す・適用できる。エージェントの適用は確認なし。
  - 元のプレハブの変更は、ワークスペースの中のインスタンスにはすぐ反映し、セッションに出した配置には「適用」で届く。
  - インスタンスの親を複製すると、インスタンスが一つ増える。インスタンスの中の Entity を複製すると、足した Entity になる。
  - 「その場」で編集するとき、インスタンスから開いたら、少しずらして出す。
  - インスタンスで変えたことは、確認してプレハブに適用できる。
  - インスタンスの中で、プレハブから来たものと足したものを見分けられるようにする。変えた所に印を付け、一つずつプレハブの形に戻せる。
  - インスタンスを、ふつうの Entity に戻せる。
  - プレハブを消したら、インスタンスを残して問題として出す。
- 設計者・実装者に任せること：
  - プレハブとインスタンスの保存の形（インスタンスで変えた所の持ち方）。
  - 同じ System を含むプレハブのインスタンスが、一つのアウトプットにいくつもあるときの扱い（System を一つにまとめる）。
  - プレハブの中のプレハブで、変えた所が何段も重なったときの扱い。
- 計画者に聞くこと：なし。
