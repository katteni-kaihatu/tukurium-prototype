## 作り方の方針

### 今の仕組み（調べた結果）

- Entity は、どれか一つのアウトプットに属する（`EntityDef.output`。`packages/repo-model/src/schema.ts`）。値は KokoState ごと・フィールドごとに持つ。
- アウトプットは、動かす System の並び（`OutputDef.systems`）を持つ。
- 再生では、`buildWorld()`（`packages/runtime/src/buildWorld.ts`）が、そのアウトプットの Entity をそのまま World に並べる。
- 共同編集（Yjs）では、Entity の値はフィールドごとの `Y.Map` で、フィールドごとの後勝ち（`packages/repo-model/src/projectDoc.ts`）。
- Git には、1 要素 1 ファイルの JSON で保存する（`packages/repo-model/src/files.ts`）。
- リソースの種類（KokoState・System・マテリアル・素材・フォルダ）は、論理パスで表す（`resourcePath.ts`。ADR 0010）。
- ワールドは、離れた空間で編集する。置き場所は `apps/client/src/workspace/anchor.ts` で決めている。
- 次の所は、どれも「アウトプットの Entity」を直接読んでいる。
  - 依存グラフ・抽出・参照の診断
  - 変化の印と戻す
  - Hierarchy・Inspector
- ライブラリは Entity を持たず、含めるリソース（`OutputDef.resources`）だけを配る。

### 方針

1. **プレハブは新しいリソースの種類にする。**
   - 中身は、プレハブの中の Entity の並び（子と KokoState の値を含む）・System の並び・編集する場所の設定。
   - Git には `prefabs/<ID>.json`（Entity は `prefabs/<ID>/entities/<Entity の ID>.json`）で保存する。
   - 論理パスと ID はほかのリソースと同じ扱い（ADR 0010）。拡張子は `.prefab`。
2. **プレハブの中の Entity の持ち方は、P0 で次の二つから選ぶ。** 手間（`e.output` を読んでいる所の数）と分かりやすさを比べて決める。どちらでも、値はフィールドごとの後勝ち。今のデータは移してよい（プロトタイプ）。
   - (a) `EntityDef.output` を `owner`（`{ kind: "output", id }` か `{ kind: "prefab", id }`）に置き換え、今の `entities` に入れる。
   - (b) `output` はそのままにし、プレハブの Entity を別の `Y.Map` に持つ。
3. **インスタンスは、アウトプットの中の一つの Entity として持つ。**
   - インスタンスは「どのプレハブか」（リソース ID）と、インスタンスで変えた所（上書き）を持つ。
   - 上書きとして持つもの：フィールドの値、並び順、親、足した Entity・KokoState・System。
   - リストの一つの要素だけを変えても、上書きはフィールドまるごと（フィールドごとの後勝ちに合わせる）。
   - 場所・向き・大きさは、インスタンスそのものの Transform に持つ。上書きには数えない。
4. **展開した Entity の ID は、決まった作り方にする。**
   - プレハブの中の Entity には、新しい ID を付ける。
   - 展開した Entity の ID は「インスタンスの ID ＋ プレハブの中の Entity の ID」。入れ子のときはつなげる。開き直しても、別の人の画面でも同じ ID になるので、展開した Entity を指す参照が切れない。
5. **使う所の手前で「展開」する。**
   - 制作データから、インスタンスをプレハブの中身に置き換えた Entity の並びを作る関数（`expandPrefabs()`）を、repo-model に置く。
     - 上書きは、上に重ねる。
     - 入れ子のプレハブも、たどって展開する。自分を含むプレハブ（循環）は、展開せずに問題として出す。
     - 付け替えた先の親（またはインスタンスで足した Entity の親）がプレハブ側で消えていたら、消えた親のさらに親に付ける。その親もなければ、もう一つ上に付ける。
   - 再生（`buildWorld()`）・依存グラフ・抽出・参照の診断・Hierarchy は、展開した並びを読む。今の「アウトプットの Entity」を前にした作りを、そのまま使い続けられる。
   - 展開の結果は取っておき、変わったプレハブを使っている所だけを展開し直す。
6. **反映の範囲**
   - ワークスペースの中のインスタンスには、プレハブの変更がすぐ反映される。
   - セッションに出した配置には、今と同じく「適用」で届く。プレハブの変更も、アウトプットの変更の一つとして扱う。
   - アウトプットを公開したリリースには、使っているプレハブも入れる。リリースは、公開したときのプレハブのまま。
7. **System は、並びと「入・切」だけを足し合わせる。**
   - アウトプットで動かす System は、アウトプットのものと、中のインスタンスのプレハブのもの（インスタンスで足したものを含む）を合わせたもの。
   - 同じ System は一つにまとめる。アウトプットにも同じ System があれば、アウトプット側の「入・切」（`enabled`）を優先する。アウトプットの画面から、プレハブの System も「切」にできる。
   - 権限は、今と同じく System のコードから読み取る（ADR 0012）。
   - 並び順は、アウトプットのものを先にし、プレハブのものはあとに足す。細かな決まりは P0 で決める。
8. **「維持」の印は、アウトプットが持つ。**
   - 指す先は、展開した Entity の ID とフィールドの組。
   - プレハブの中で付けた「維持」は、プレハブが持ち、展開したときにアウトプットの「維持」に足し合わせる。
   - インスタンスを消したときは、その中を指す「維持」の印も一緒に外す。
9. **プレハブの編集は、アウトプットの編集と同じ画面で行う。**
   - Hierarchy でプレハブを開くと、プレハブの中の Entity の並びが出る。Inspector で直す。
   - 編集する場所の設定は、次の 2 つ。
     - 「その場」（初め）：インスタンスを選んでから開いたときは、そのインスタンスと重ならないように、少しずらした所に出す。Resources から開いたときは、今の区画の手前に出す。
     - 「離れた空間」：ワールドと同じ置き場所の決め方（`anchor.ts`）を使う。
   - 今は再生中（Play mode）に編集できないので、プレハブも再生中は編集できない。いずれ再生中に編集できるようにするときの扱いは、実装者に任せる。
10. **印と戻す**
    - インスタンスで変えた所の印と戻すは、今の「変化の印」と「戻す」の仕組みを使い、比べる相手を「プレハブの中身」にする。プレハブから来たものと、インスタンスで足したものも、この比べ方で見分ける。
    - 「最後の保存からの変化」の印は、今のまま。「プレハブからの変化」の印は、形や文字で分ける（今の印は新しいものを緑で出しているので、色だけで分けない）。戻す操作もそれぞれ分ける。
    - プレハブのリソースそのものも、ほかのリソースと同じく、最後の保存と比べて差分に出し、戻せる。
11. **AI エージェントも、人と同じ操作ができる。** プレハブを作る・置く・直す・適用する道具を、MCP に足す。エージェントの「プレハブに適用する」は確認なしで行う。
12. **大きな判断は ADR に残す。**
    - 新しい ADR に、プレハブの保存の形、Entity の持ち方、上書きの持ち方、展開と ID の作り方、System の足し合わせ、編集する場所を書く。
    - 番号は、PR を出す直前に、最新の次の番号を確かめて付ける（ほかの作業と重ならないように）。

## 確かめ方

- 単体テスト
  - 展開：インスタンスがプレハブの中身になること、変えた所が重なること、ID が決まった作り方になること、入れ子と循環
  - System の足し合わせ（同じ System を一つにまとめる、並び順）
  - 再生で、3 つのインスタンスがプレハブの System で動くこと
  - プレハブを直すと、すべてのインスタンスに反映されること
  - Entity からプレハブを作っても、参照が切れないこと
  - プレハブから来たものを消せないこと、変えた所を戻せること
  - 並べ替えと親の付け替えの上書き、付け替えた先の親が消えたときにさらに親へ付くこと、輪になる付け替えを断ること
  - 「維持」の足し合わせと、インスタンスを消したときに外すこと
  - 複製：インスタンスの親を複製するとインスタンスが増えること、中の Entity を複製すると足した Entity になること
  - 「その場」で編集するとき、インスタンスと重ならない所に出ること
  - System の「入・切」の足し合わせ
  - エージェントがプレハブを作り、置き、変え、適用できること
  - プレハブに適用すると、ほかのインスタンスに反映されること
  - ふつうの Entity に戻したあとは反映されないこと
  - プレハブを消したときの問題
  - ライブラリのプレハブのバージョン
  - 名前の変更と移動で、インスタンスとのつながりが切れないこと
- 背骨の E2E：P1 と P8 のあとに流す（再生と保存の流れに触れるため）。
- 画面：Hierarchy・Inspector での見分け方と印、編集する場所の切り替えを、使い捨てのスクリプトのスクリーンショットで確かめる。

## 構想から変えたこと

- 計画者と相談して、構想に次のことを足した：インスタンスで並べ替えと親の付け替えができる（消すことだけはできない）。付け替えた先の親が消えたら、さらに親に付け替わる。AI エージェントもプレハブを作る・置く・直す・適用できる（適用は確認なし）。セッションの配置には「適用」で届くこと、複製の扱い、「その場」で編集するときにずらして出すこと、Entity から作ったときに子への参照も切れないこと、入れ子でふつうの Entity に戻したときの扱い、ライブラリのプレハブのインスタンスでも変えられることを書いた。前に終わっている必要があるものに、フィールドの型の項目を足した。

## 分かったこと・残り

### P0・P1 で決めたこと（ADR 0076）

- プレハブの中の Entity の持ち方は、(b)（`output` はそのままにし、別の `Y.Map` に持つ）。`e.output` を読む所は 90 か所ほどあり、(a) だと、直し忘れた所で、プレハブの中の Entity（ひな形）が実体として扱われる。(b) なら、今のコードはそのまま動く。
- インスタンスの Entity が、プレハブのいちばん上の Entity に当たる。プレハブは、いちばん上の Entity を一つだけ持ち、ほかはその下に入る。P3 で、選んだ親の Entity が ID を引き継いでインスタンスになっても、親を指す参照がそのまま使える。
- 展開した Entity の ID は「インスタンスの ID `/` プレハブの中の Entity の ID」。Entity の ID に `/` は使えなくした。
- System の並び順：アウトプットのものが先。プレハブのものは、Hierarchy で先に出てくるインスタンスのものから。同じ System は一つにまとめ、どれかのプレハブで「入」なら「入」。アウトプットにもあれば、アウトプットが勝つ。
- 上書きの持ち方は、ADR 0076 の 8 に書いた（P4 で実装した）。
- 依存グラフは、展開した並びではなく「インスタンス → プレハブ → プレハブが使うもの」の辺で持つ。展開した Entity を節にすると、インスタンスの数だけ節が増え、問題の相手も利用者が直せない Entity になるため。参照の診断は、指す先があるかだけを、展開した並びで確かめる。
- 計測（`pnpm bench:prefab`。3 段の入れ子、インスタンス 1 個が Entity 69 個）：インスタンス 100 個で、初めの展開は 4 ms、何も変わっていなければ 0.4 ms、インスタンスを一つ動かすと 0.4 ms、いちばん内側のプレハブを変えると 4.5 ms。表示用の World の組み立ては 7 ms で、こちらは制作データが変わるたびに全部を作り直している（プレハブがなくても同じ）。

### P1 で残したこと

- インスタンスの中の Entity を変えることは、P4 で済んだ。プレハブの中身を画面から直すことと、プレハブの中の問題を出すことは、P2 で済んだ。
- ライブラリは P7、抽出とエージェントの道具は P8 で対応した。プレハブを使うアウトプットを抽出すると、中身と依存も持っていく。
- フィールドごとの上書きと印は、P4 で済んだ。いちばん上に足す KokoState は `states`、プレハブから来た KokoState の値は `prefabOverrides` に分けた。

### P2 で決めたこと（ADR 0076 の 9）

- 開いているプレハブは、人ごとの画面の状態（ストアの `editingPrefab`）にした。同期も保存もしない。通信の形は変えていない。
- プレハブを開いているときの表示は、「編集用の並び」（`expandPrefabForEdit()`）を読む。アウトプットを展開したものと同じ形（`output` がプレハブの ID）なので、`buildWorld()`・Hierarchy・Inspector は、アウトプットのときの処理をそのまま使える。
- 選んだものが、いつも Hierarchy に出ているものの中にあるように、ストアの `select()` で、プレハブを開く・閉じる。問題の場所や「置いてある所」からプレハブの中の Entity へ移ると、そのプレハブが開く。
- 「その場」では、アウトプットを出したまま、その横か手前にプレハブの中身を出す。インスタンスから開いたときは、そのインスタンスの +X 側に、すき間 0.5 m をあけて出し、横にほかの物があれば、さらに横へ送る。置き場所は、開いたときに一度決める。
- 「離れた空間」は、ワールドの編集と同じ仕組み（独立した空間・ポータル・出口）を使うが、場所は、ワールドの編集・非公開の作業の空間と重ならない所にした（同じ場所だと、ワールドの中身と重なる）。
- プレハブを開いたまま Play を始めると、アウトプットに戻ってから再生する（「開いている間は Play できない」にはしない。ほかの人が始めた再生も、同じ決まりで受けられる）。
- プレハブの中の問題は、プレハブを相手に出す。問題の場所の道は「`entities` / 中の Entity の ID / KokoState / フィールド」。新しい種類は `prefab-system-missing`・`prefab-system-not-in-dependencies`・`prefab-keep-invalid`。Entity の値の確かめは、アウトプットの Entity と同じ処理で、種類も同じ（`missing-resource` など）。
- Entity の複製は、画面に二つあった処理を `ProjectDoc.duplicateEntity()` にまとめた（アウトプットでも、プレハブの中でも使う）。

### P2 で残したこと

- プレハブの中の Entity の「最後の保存からの変化」は、丸を出すだけ。丸から細かく見る・一つずつ戻すことはできない（戻すのは、プレハブまるごと）。細かく戻すには、差分（`diffView.ts`）と戻す（`revert.ts`）に、プレハブの中の Entity ごとの項目が要る。
- プレハブの中に、画面からインスタンスを置くことは、P6で対応した。Resources のプレハブを Hierarchy に落とすと、子として置ける。
- 開いたプレハブから、開いた元へ順に戻ること（盤 → 駒 → 盤）は、作っていない。戻る先は、いつもアウトプット。
- 「その場」で、プレハブの中身は、開いた人にだけ見える（一緒に編集している人には、直した結果がインスタンスに出る。同じプレハブを開けば、同じ中身を直せる）。ほかの人が、どのプレハブを開いているかは分からない。
- 「その場」の置き場所は、開いたあとは動かない。開いたあとにアウトプットの物を動かして重なっても、よけ直さない（開き直すと、決め直す）。
- マテリアルの詳細の「使っているモノの数」は、プレハブの中の Entity を数えていない。

### P3 で決めたこと（ADR 0076 の 10）

- 「何を移し、何を書き換えるか」の計画を作る関数（`planPrefabFromEntity()`。`packages/repo-model/src/prefabFromEntity.ts`）と、実行（`ProjectDoc.makePrefabFromEntity()`）に分けた。確認の画面と単体テストは、計画を読む。実行は、一つの transaction。
- 選んだ Entity は、Transform だけを持つインスタンスになる。ほかの KokoState は、プレハブのいちばん上の Entity へ移す（Transform は、向きと大きさを写し、場所は原点）。
- 「維持」の印のうち、プレハブに移した Entity を指すものは、プレハブへ移す（あとで置くインスタンスにも効く）。選んだ Entity の Transform の印だけは、アウトプットに残す。
- System は、初めはプレハブに含めない。確認の画面で、アウトプットの System から「プレハブにも入れる」ものを選べる。選んでも、アウトプットの並びからは外さない（アウトプットのものが勝つので、動く順と「入・切」が変わらない）。
- ほかのプレハブの中の Entity が、移す Entity を指していた参照も、展開したあとの ID に書き換える。プレハブに移した Entity から外の Entity を指す参照は、そのまま残し、確認の画面に出す。
- スクリプトの中の ID は、System のコードに ID の文字が含まれるかで調べ、確認の画面に注意として出す。書き換えない。選んだ Entity の ID は変わらないので、調べない。
- 確認は、ボタンの下に重ねて出す窓（変化の丸の窓と同じ作り。3D に置いたパネルでは、そのパネルの上に出る）。`confirm()` は、内容を並べて見せられないので使わない。開いている間に制作データが変わったら計画を作り直し、新しい ID は初めに出したものを使い続ける。
- 「プレハブにする」のボタンは、Inspector の Entity の操作に置いた。Hierarchy の行には置かない（行の操作が三つになると、幅の狭い Hierarchy で名前が隠れる）。
- ひとまとまりで戻す操作は作らない。変換は、Entity の変化とプレハブの追加として差分に出て、一つずつ戻せる。Entity の変化の丸は、プレハブとのつながり（`instanceOf`）が変わったときにも出すようにした。

### P3 で残したこと

- スクリプトの中の ID は、書き換えない（注意を出すだけ）。型の定義のコードは、調べていない。
- セッションに出した配置では、変換のあとの初めの「適用」のとき、中の Entity の「維持」の値は引き継がれない（ID が変わるため。選んだ Entity の値は引き継ぐ）。確認の画面に書いてある。
- プレハブを開いている間に、中の Entity からプレハブを作ることは、P6で対応した。中のインスタンスの下に足した Entity（P4 の形）も、親と参照を保って移す。
- プレハブの名前と置き場所（フォルダ）は、確認の画面では選べない（Entity の名前で、いちばん上に作る。あとから Resources で変えられる）。
- エージェントの道具（MCP）からの作成は P8 で対応した。`ProjectDoc.makePrefabFromEntity()` を画面と同じ制約で呼び、確認画面は出さない。
- 参照の書き換えは、フィールドの型（スキーマ）が分かるフィールドだけに届く。型エラーで読めないフィールドの中の参照は、書き換わらない（展開の付け替えと同じ）。

### 前からあるもの

- フィールドの型の項目のあとに進める。インスタンスで変えた値は、フィールドの値と同じ形で持つので、値の形が広がれば一緒に広がる。
- 非公開の作業は、ワークスペース全体を非公開にするもの（ADR 0008）なので、プレハブのための決まりは要らない。

### P4 で決めたこと（ADR 0076 の 8）

- 上書きは、インスタンスの `prefabOverrides` に、Entity の道・種類・KokoState・フィールドで持つ。共同編集では、初めての別フィールドの編集も競合しない平たい `Y.Map` にした。
- Entity・KokoState・System を足せる。プレハブから来たものは消せず、足したものとインスタンスそのものは消せる。中の Entity を複製すると追加 Entity、いちばん上を複製すると上書きを写したインスタンスになる。
- 親と並び順も上書きにした。プレハブから親が消えたら `deletedParents` をたどって残った祖先へ付ける。親を付ける操作は輪になる場合に断る。
- 保存からの変化は丸、プレハブからの変化は `△` にした。名前・親・並び順・フィールド・追加したものを個別に戻せる。`元` と `追加` で出どころも見分けられる。
- 「維持」は展開した印を合わせて表示する。インスタンスを消すと、中の追加 Entity と、それらを指す印も外す。

### P5 で決めたこと（ADR 0076 の 11）

- 適用・解除は、制作データを変えない計画関数と `ProjectDoc` の実行に分けた。確認中は変更を読み直し、表示した新しい ID を使い続ける。実行は一つの transaction で、変更したフィールドだけを書き込む。
- 適用元の上書きと追加分はプレハブへ移す。いちばん上の名前・親・並び・Transform は残す。追加 Entity の ID、参照、上書きの中の参照、「維持」の印を付け替える。入れ子への変更は、外側のプレハブの中にあるインスタンスが持つ。
- インスタンスの外を親にした変更は、その Entity を示して適用を断る。プレハブは全 Entity がいちばん上の Entity の下にあるため。ライブラリや、元プレハブがない場合も適用できない。
- 解除は一段だけ実体化し、入れ子のインスタンスは残す。本体の System は `unpackedSystems`、元の追加 System は `instanceSystems` に持ち、子の前後で足し合わせる。入れ子の変更への追随を保つため、展開後の System 全体を固定する方式にはしなかった。
- プレハブ本体の「維持」は持ち主へ移し、入れ子自身の印は写さない。プレハブを消したときのインスタンス保持と問題の表示は、既存処理を使う。
- 適用元の KokoState は、フィールドだけを消して空の入れ物を残す。同じ入れ物の別フィールドへの同時編集を保つため。プレハブとアウトプットの定義もフィールド別の `Y.Map` にし、名前と System・「維持」などの同時編集を保つ。通信の版は 15。
- 解除と同時に、変更前のインスタンスへ書かれた編集は、新しい実体へ反映されるとは限らない。構造変更と古い保存先への同時編集を結び直す仕組みは、P5の対象に含めない。

### P6で決めたこと・確認したこと

- Resources から、開いているプレハブへインスタンスを置ける。自分自身と、何段かたどって自分を含む配置は、制作データを変えずに断る。
- プレハブの中の Entity から、新しいプレハブを作れる。選んだ Entity は同じ ID で残り、内側のインスタンスも保つ。元のプレハブの外から展開した中身を指す参照と「維持」の印も、確認画面に出して書き換える。
- 入れ子の更新と保存・共同編集は単体テストで確認した。画面では配置、循環の拒否、確認してからの変換を確認した。
- P4・P5を合わせ、入れ子の上書き・印・戻す・適用・解除を確認した。内側への変更は外側の上書きとして残り、その編集先の「戻す」だけで外せる。
- 変換では上書きの対象・値・親、追加 KokoState、`instanceSystems`・`unpackedSystems`、`deletedParents` も移す。実行はP5のフィールド差分の書き込みを使い、持ち主の名前への同時編集と「維持」の移動を両方保つ。
- 外側の Entity を指す新しいプレハブは、元の持ち主の中では参照を保つ。単体で開いたときの参照先なしの問題は残し、確認画面にも外部参照として示す。
- 入れ子の子の親を変換で移すまとまりの外へ付け替えている場合は、Entity と親の名前を示して変換を断る。フィールドの外部参照は、そのまま残す。

### P7 で決めたこと

- ライブラリに含めるリソースでプレハブを選べる。中の Entity と、使っている KokoState・型の定義・System・マテリアル・素材・入れ子のプレハブも一緒に公開する。
- ライブラリを足すときにバージョンを選ぶ。読み込んだプレハブは Resources の `@別名 · v番号` に並び、アウトプットへインスタンスを置ける。定義の名前・中身は読むだけだが、ローカルのインスタンスは P4 の操作で変えられる。プレハブへの適用禁止は P5 の判定を使う。
- プレハブとリソースの ID は Package とバージョンで区切る。中の Entity には `/` を含まない `pkgent:` の ID を使い、展開した ID の区切りと分ける。参照と上書きの ID も読み込み時に付け替える。素材の ID は取得に使う hash のまま残す。
- 読み込んだ定義を Git や Yjs に複製しない。保存するのは依存のバージョン・content hash と、ローカルのインスタンス。表示と再生では、依存から届いた定義を合わせて展開する。
- 公開した KokoState のフィールドの型情報を manifest に含める。プレハブを含まないライブラリも同じ扱いにする。使う側に同名の型があっても、公開元の型情報に沿って参照を付け替える。制作データに型情報を保存するものではない。

### P8 で確認したこと

- 抽出・フォークでプレハブを持ち運び、同じ内容は再利用する。ID が変わる場合の参照・上書き・「維持」の印、間接ライブラリへの依存もテストした。
- MCP で作成・変換・配置・編集・復帰・複製・適用・リンク解除を行える。実際に公開したライブラリを使い、型に合わない値と読み取り専用の定義への変更を断ることも確認した。
- 背骨の E2E は 4 本を保ち、m6 にプレハブの作成とインスタンスの上書きを加えた。共同保存・公開・セッションへの配置後にも上書きが残ることを確認した。
- FEATURES・用語・エージェントの使い方を更新した。設計の詳細と制約は ADR 0076 に記録した。
