# 用語

Tukurium で使う言葉の意味と呼び方。呼び方は画面で使う言葉に合わせる。新しく文章を書くときは「呼び方」の列を使う。「別の呼び方」は、既存の資料やコードを読むときや、同じものを指していると分かり合うために載せている。正式ではない呼び方や、正しくない呼び方も含む。コード上の名前や、技術一般の言葉まで一律に言い換えるものではない。

## 全体

| 呼び方 | 別の呼び方 | 意味 |
| --- | --- | --- |
| 作品 | — | 作ったもの全般。公開しているかどうかは問わない。公開したものは「リリース」と呼ぶ。 |

## 作る

| 呼び方 | 別の呼び方 | 意味 |
| --- | --- | --- |
| プロジェクト | リポジトリ、Repo | 制作データと履歴をまとめて残す単位。Git での保存を説明するときは「リポジトリ」を使う。 |
| ワークスペース | Workspace | プロジェクトを開き、複数人で編集・再生する作業場所。出ると自分だけ離れ、閉じると一覧からなくなる。プロジェクトは残る。 |
| アウトプット | 出力、Output | プロジェクトの一部を、アイテム・ワールド・ライブラリとして使うまとまり。一つのプロジェクトから複数作れる。 |
| アイテム | — | セッションに置いて使うアウトプット。 |
| ワールド | — | 遊ぶ場所になるアウトプット。 |
| リソース | Resources | プロジェクトの中にある KokoState・System・マテリアル・素材・フォルダなどの一つ一つ。名前や置き場所を変えても、同じものとして扱う。 |
| プレハブ | Prefab | Entity・KokoState・System のまとまりを、部品としてリソースにしたもの。アウトプットの中に置いて使い、それだけをセッションには出さない。 |
| インスタンス | Instance | プレハブをアウトプット（または別のプレハブ）の中に置いたもの。元のプレハブの変更が反映される。インスタンスで変えた所は残る。 |
| プレハブに適用 | — | インスタンスで変えたことを、確認してプレハブに書き戻し、正として保存する操作。ほかのインスタンスにも反映される。 |
| 素材 | アセット、Asset | モデル・画像・音声のファイル。制作データからは参照するだけで、本体は別に持つ。 |
| 制作データ | — | 形・コード・初期値など、作者が編集して残すもの。 |
| 実行状態 | — | 今の位置や残弾など、動かしている間に変わるもの。制作データとは分ける。 |
| 再生 | 試し再生 | ワークスペースで作品を動かして試すこと。セッションでの遊びとは独立している。 |
| 適用 | Apply | ワークスペースの変更を、セッションに置いた配置へ反映すること。編集しただけでは反映しない。 |
| 維持 | 状態維持、keep | 適用したあとも実行中の値を引き継ぐよう、フィールドに付ける印。 |
| リセット | — | 配置を、制作データの初期値からやり直すこと。 |
| 保存 | コミット、Commit | 作業の区切りとして履歴に残すこと。リリースのバージョンの元になる。作業途中の自動の保存とは別。 |
| コードホバー | ホバー、Quick Info | スクリプトのエディタで、コードにマウスを重ねると出る小さな枠。型・説明・型エラーの文が出る。 |
| デバッグモード | — | 再生を、一時停止の条件で一時停止する形にするトグル。デバッグ用のパネルにあり、参加者全員で共有し、再生を始める前に切り替える。 |
| デバッグ実行 | — | デバッグモードを入れて再生すること。一時停止すると参加者全員の再生が一時停止する。 |
| 一時停止の条件 | — | デバッグ実行で再生を一時停止する条件。デバッグ用のパネルに並べ、どれか一つに当てはまったら一時停止する。一つの一時停止の条件は、きっかけ（スクリプトの行・KokoState のフィールドの変化・実行中のエラー）を一つもち、Entity と式で絞れる。ワークスペースの上のもので、参加者全員で共有し、保存の履歴やリリースには含めない。 |
| ブレイクポイント | — | 一時停止の条件のうち、スクリプトの行で一時停止するもの。デバッグモードのとき、エディタの行番号の横に印が出る。 |
| ログポイント | — | 一時停止せずに、文や式の値をログへ書き出すスクリプトの行に付ける印。デバッグモードのときだけ働く。 |
| ステップ実行 | ステップオーバー、ステップイン、ステップアウト | デバッグ実行で一時停止したところから、1 行ずつ進めること。次の行へ・関数の中に入る・関数から出るを選べる。 |

## 遊ぶ

| 呼び方 | 別の呼び方 | 意味 |
| --- | --- | --- |
| セッション | インスタンス、部屋、Session | 人が集まり、作品を作ったり組み合わせて遊んだりする場所。「インスタンス」は個々の実体を指すこともあるので、この意味では「セッション」を使う。 |
| 配置 | Placement | アイテムやワールドをセッションに置いた実体。同じアウトプットから複数作れる。 |
| 所持アイテム | 所持品 | 入手したアイテムとバージョンの記録。セッションに置いた実体とは区別する。所持しても利用の権限は増えない。 |
| ホスト | 実行役、Host | 作品の処理を動かし、参加者へ状態を送る役。 |
| グローバルメニュー | 左のメニュー | 画面の左に置く、アプリ全体の入口。名前つきの形とアイコンの列を切り替える。いまのツクリウムに画面がない項目（タイムライン・イベント・グループ）は、ボタンだけを置く。 |
| ステータス | 状態 | フレンドに見せる、今の過ごし方とひとこと。KokoState や実行状態の「状態」と区別するため、この意味では「ステータス」を使う。 |

## 公開・再利用

| 呼び方 | 別の呼び方 | 意味 |
| --- | --- | --- |
| リリース | 公開作品、Work | プロジェクトの、公開したアウトプット。 |
| バージョン | 版、Release（コード上の名前） | リリースの、ある時点の中身。特定の保存（コミット）に結び付く。 |
| マーケット | Market | リリースを探して入手する入口。 |
| ライブラリ | Library | ほかの制作で使う定義や処理をまとめたアウトプット。セッションに置かず、依存として使う。 |
| 依存 | Dependency | プロジェクトやライブラリが使う別のライブラリ。バージョンと中身を固定して参照する。 |
| Package | パッケージ | 配布する部品の出所とバージョンを扱う単位。 |
| フォーク | Fork | プロジェクトを履歴と由来ごと複製して改造すること。 |
| 抽出 | Extract | 選んだアウトプットやリソースを、必要なものと一緒に別のプロジェクトへ取り込むこと。 |
| 由来 | — | 取り込んだものや複製したものが、どの作品から来たかの記録。 |

## 作品の仕組み

| 呼び方 | 別の呼び方 | 意味 |
| --- | --- | --- |
| EKS | ECS | Entity / KokoState / System で作品を作る方式。ECS の Component を KokoState と呼び替えたもので、別の方式ではない。 |
| Entity | エンティティ | 的や扉など、作品の中の一つの要素。 |
| KokoState | ECS の Component | 位置や体力など、要素が持つ状態。UI 部品などを指す Component とは区別する。 |
| フィールド | 欄、Field | KokoState が持つ値の一つ一つ（例：`Health` の `hp`）。名前とは別の ID で結び付く。 |
| KokoState の参照 | KokoStateRef | Entity と KokoState の組を指す値（例：「的 3 の `Health`」）。名前ではなく ID で結び付く。 |
| フィールドの参照 | FieldRef | Entity・KokoState・フィールドの組を指す値（例：「的 3 の `Health.hp`」）。指せるフィールドの型を、型で決める。 |
| 型の定義 | Types | 名前を付けた型（`Card` など）を、TypeScript の `type` と `interface` で書くリソース。KokoState のフィールドの型から使う。 |
| 型の文 | — | フィールドの型を、TypeScript の型の書き方で書いた文字（例：`number`、`Card[]`、`EntityRef \| undefined`）。 |
| スキーマ | 値の形の決まり | 型の文を読み解いて作る、値の形の決まり（数・文字・選択肢・レコード・リスト・マップ・参照などの入れ子）。値の確かめと、Inspector の入力に使う。保存せず、制作データから作り直す。 |
| 値の形式 | タグ付きの JSON | フィールドの値を、保存・共同編集・通信・スクリプトとの受け渡しで運ぶときの書き方。ふつうの JSON に、JSON で表せない値（`undefined`・日時・`Map`・`Set`・大きな整数・`NaN`・`Infinity`）だけを `"$t"` のキーを持つオブジェクトで足したもの。 |
| 型エラー | 型の誤り | スクリプトや KokoState のフィールドの型が合わないこと。TypeScript の型の確かめで見つかる。再生は止めない。 |
| System | — | どの状態を持つかで対象を選び、動かす処理。 |
| イベント | Event | 押した・当たったなど、一度の出来事。続く状態は KokoState で扱う。グローバルメニューの「イベント」（集まりの予定。まだ画面はない）とは別。 |
| Contract | 公開操作 | 作品が外へ公開する操作の型。受け手が処理を決める。 |
| Capability | — | 作品がホストの機能を使うための許可。 |
| Host API | ホスト API | 物理や音など、基盤の機能をスクリプトから呼ぶための入口。 |
| 実行領域 | realm | スクリプトが動く領域。出所やバージョンごとに分け、別のバージョンのコードが混ざらないようにする。 |

## ロードマップ

| 呼び方 | 別の呼び方 | 意味 |
| --- | --- | --- |
| ロードマップ | — | テーマと原則のために、計画して進める重い変更。小さな追加や修正は含めない。 |
| 構想 | vision | ロードマップの項目で、やりたいこと・範囲・完了の条件を書いた資料。計画者が書く。 |
| 実装計画 | implementation | ロードマップの項目で、作り方の方針と段階を書いた資料。設計者が書く。 |
| 計画者 | 計画する人 | 構想を書き、範囲を決める人。 |
| 設計者 | — | 実装計画を書き、作り方を決める人。実装者と同じ人でもよい。 |
| 実装者 | 実装する人 | 実装計画に沿って作る人。 |
